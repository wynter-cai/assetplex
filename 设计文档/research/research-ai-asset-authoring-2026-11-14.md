## 0. 核心结论

1. **资产的「触发能力」比「内容多少」更决定成败**。技能只预加载 name+description，description 是路由键而非摘要；官方 skill-creator 明确提示模型倾向 undertrigger，描述可以略「pushy」。`[F]`
2. **载体放错是最常见的问题，而不是写错字**。多步流程写进永远加载的根规则、约束写进 memory 当门禁、path-scoped 内容堆在根文件——成本高且不生效。`[F]`
3. **长度有官方硬线**：根 `CLAUDE.md` < 200 行、`SKILL.md` < 500 行、子代理描述合计 ≤ 15k token、Codex 拼接默认 32KiB、Cursor 规则建议 < 500 行。`[F]`
4. **指令数量与准确率强相关**：IFScale 实测 500 条指令时最强模型仅约 68% 准确率；规则不是越多越好。`[F]`
5. **规则冲突不会被自动仲裁**：模型遇到矛盾可能任选一条，所以诊断器必须做跨文件冲突/重复检测，而不是只查单文件格式。`[F]`
6. **「可验证的具体行为」是身份与规则的唯一共同验收标准**。「专业、严谨、高效」不可诊断，必须改写成可观察动作。`[F]`
7. **MCP 诊断要分两层**：静态（明文密钥、未固定版本、工具描述含指令性语言）与组合（私密数据 + 不可信内容 + 外发通道同处一会话，即 lethal trifecta）。后者比逐个 server 打分更有效。`[F]`
8. **诊断分层**：格式与阈值可机器判（零 Key），语义好坏才交给 LLM；AI 只补充「影响与改法」，不负责定罪。`[A]`，与 P1-4 结论一致。

## 1. 跨资产共通原则

| 原则 | 含义 | 可机械判定的信号 |
|---|---|---|
| 单一职责 | 一个资产只解决一类任务；多步流程拆技能，路径约束下沉到 path-scoped rule | 标题/正文出现多个不相关任务；同一文件覆盖 ≥3 类触发场景 |
| 可验证 | 每条指令能对应一个可观察行为或验收条件 | 出现「专业/高效/严谨/尽量」等无动作形容词 |
| 正确载体 | 常驻内容进根规则，流程进技能，硬门禁进 hook，临时事实进 memory | 根文件里出现步骤清单；memory 里出现「必须/禁止」 |
| 长度预算 | 常驻上下文越短越好 | 行数/字数/token 超阈值 |
| 引用一层可达 | 技能引用文件从 SKILL.md 直接链接，不嵌套 | 出现二级引用；引用文件 >100 行且无 TOC |
| 无密钥 | 规则、技能、示例里不得出现真实密钥/PII | 正则命中 token/key/密码/内网地址 |
| 可回归 | 资产变更应能被 diff 与评测覆盖 | 无版本/无变更记录（后续版本化能力承接） |

## 2. 各类资产速览

### 2.1 身份 / 人设（Identity）

- **该有什么**：我是谁、为谁工作、目标、表达方式、不做什么、不确定时怎么办。`[F]`
- **硬要求**：与任务指令分离；跨任务稳定；不写项目细节（项目细节属于 rules）。`[F]`
- **Top 检查项**：
  1. 是否缺「不做什么 / 边界」段落；
  2. 是否用不可验证的形容词描述风格；
  3. 是否混入项目路径、客户名、一次性任务；
  4. 是否与规则文件重复或矛盾；
  5. 是否含密钥/隐私。
- 完整 12 条见分册。

### 2.2 规则（Rules / AGENTS.md / CLAUDE.md / Cursor Rules）

- **分层**：全局 always → 路径/项目 scoped → 任务级 prompt。`[F]`
- **硬线**：根文件 < 200 行（Claude 官方建议），Cursor 建议 < 500 行，Codex 拼接默认 32KiB。`[F]`
- **Top 检查项**：
  1. 是否把「步骤流程」写进常驻规则（应拆技能）；
  2. 是否出现互相冲突的两条规则；
  3. 是否有不可执行表述（「尽量」「注意质量」）；
  4. 是否超长 / 大段复制文档；
  5. 是否含密钥、真实客户信息；
  6. 是否与 memory 重复。
- 完整 12 条见分册。

### 2.3 技能（Skills / SKILL.md）

- **结构**：`SKILL.md`（精确大小写）+ 目录 kebab-case + name 与目录同名；技能目录内不放 README.md。`[F]`
- **description**：写「何时用我」，含正向与负向触发；宁可略 pushy，避免 undertrigger。`[F]`
- **正文**：< 500 行；建议结构「何时使用 → 步骤 → 输出格式 → Gotchas → 失败处理 → 参考文件」。`[F]`
- **渐进披露**：引用文件从 SKILL.md 一层可达；>100 行的参考文件加 TOC。`[F]`
- **反模式**：Windows 反斜杠路径、多选项无默认、时效性信息、术语不一致、嵌套引用、正文过长、描述过泛。`[F]`
- **实证**：238 个真实 SKILL.md 中 99% 以上至少 1 个 skill smell，且很少随迭代消失（arXiv:2607.01456）。`[F]`
- **ponytail 核实**：DietrichGebert/ponytail（MIT），约 60 行单文件「行为约束型」技能 + AGENTS.md 适配层；性能数字为项目自报。`[S]`
- 完整 15 条见分册。

### 2.4 MCP

- **静态检查**：明文密钥、未固定版本（`@latest`）、工具描述含指令性语言、跨服务引用（mcp-scan E001–E003/W001/W008）。`[F]`
- **组合风险**：私密数据 + 不可信内容 + 外发通道同时存在 → lethal trifecta（工程化为 TF001/TF002）。`[F]`
- **最小权限**：只挂需要的 server；写操作工具单独标注；OAuth/凭据不进 Hub 明文。`[F]`
- **差异**：Claude / Codex / TRAE 的 MCP Schema 不同，诊断输出要按工具适配。`[F]`
- 完整 10 条见分册。

### 2.5 命令（Commands）与子代理（Agents）

- **命令**：单职责、有输入契约、有验收与失败处理；正在与技能收敛（Claude Code 已并入 skills，Cursor 提供 `/migrate-to-skills`）。`[F]`
- **子代理**：描述要能路由（何时交给它）、职责边界清晰、工具权限最小；描述总量 ≤ 15k token。`[F]`
- **差异**：Codex 无文件形态子代理，需按工具降级。`[F]`
- 完整 8 + 9 条见分册。

### 2.6 记忆（Memory）

- **该记**：稳定偏好、已确认决策、反复出现的纠正。
- **不该记**：一次性任务、可从代码/文档直接查到的事实、密钥、会过期的状态。
- **风险**：memory 只是上下文，不是硬门禁；把「必须/禁止」写进 memory 会被绕过。`[F]`
- 完整 9 条见分册。

### 2.7 AI-native SDLC（工作流层）

- **可判定标准是工件链**：`intent.md → spec.md → plan.md → diff+tests → PR review → incident`，每环入库并作为下一阶段闸门。`[F]`
- Anthropic 自述 AI 已产出 80% 合并代码、人均产出 8 倍（自报）。`[S]`
- 对 AssetPlex 的含义：未来「资产包/项目模板」应带这套工件链，而不是只给一份提示词。`[A]`

## 3. 诊断规则落地建议

### 3.1 机器判 vs LLM 判

| 类型 | 例子 | 判定方式 | 零 Key |
|---|---|---|---|
| 格式/阈值 | 缺 frontmatter、超长、引用断链、明文密钥 | 规则 | ✅ |
| 结构 | 缺「何时使用」、缺失败处理、多选项无默认 | 规则 + 轻量解析 | ✅ |
| 语义 | 规则冲突、描述过泛、身份不可验证、载体放错 | LLM（需证据片段） | ❌ 可选 |
| 组合风险 | lethal trifecta、跨文件矛盾 | 规则图 + LLM 解释 | 部分 |

### 3.2 严重度映射（初稿）

- **高**：密钥/隐私、跨文件冲突、MCP 工具投毒迹象、规则不可执行且影响 always。
- **中**：超长、缺关键段落、描述过泛、引用断链、技能放错载体。
- **低**：命名不规范、缺 TOC、术语不一致、格式小瑕疵。

### 3.3 与 P1-4 的关系

- P1-4 解决「AI 怎么做诊断」（证据链、误报控制、成本隐私）；本报告解决「诊断什么算好」。
- 每条检查项都应落成 `ruleId + 判定信号 + 建议改法 + 引用来源`，直接进入 P1-4 的 `DiagnosisFinding` 模型。
- 首版建议只做「机器判」20–30 条，够覆盖 80% 常见问题；语义类随 M2 接入。

## 4. 建议的后续动作

1. 把三份分册的检查项合并去重，形成 `diagnosis-rules.yaml`（ruleId / category / severity / 判定 / 建议 / 来源）。

3. 向导「体检」先展示机器判 Top 3；完整清单进独立体检页。
