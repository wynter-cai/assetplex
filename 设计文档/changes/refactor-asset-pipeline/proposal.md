# proposal: refactor-asset-pipeline（单资产流水线：诊断 → 治理 → 分发 收进资产详情）

> 级别：M（跨前后端的体验重构；不改诊断引擎、规则集、修复与分发协议）
> 状态：待维护者审核
> 来源：维护者 2026-11-15 验收反馈（四条痛点）
> 依赖：add-asset-doctor（诊断/草案/apply/undo/备份/分发）、add-diagnosis-rules（findings/证据口径）、
> add-asset-governance（健康分/全局治理）、refactor-home-action-panel（导航五组与 `/governance` 临时容器）

---

## 为什么做（背景）

维护者原话（四条）：

1. **资产库版面平衡差**：身份类别下只有一个文件，仍要点击才展开。
2. **资产医生疑似每次都调模型**：用户不知道缓存是否生效。
3. **点完资产医生直接跳到治理大页面**：丢失当前资产上下文。
4. **期望**：在一个资产详情内跑通「诊断 → 治理 → 分发」流水线，体验丝滑。

现状核实（读码结论，作为本规格的事实基线）：

| 事实 | 位置 | 对本变更的含义 |
|---|---|---|
| 诊断**已有**内容哈希缓存，key = sha256(类别 + 资产正文 + 准则集哈希 + 模型)，存本机 `~/.assetplex/doctor-reports.json`；机械项每次本地重跑零成本 | `src/core/doctor-cache.ts`、`src/core/doctor.ts` | 痛点 2 不是"缓存没做"，而是"缓存不可见、调用成本不可预期" |
| 有按类别的预算估算接口，返回 `cacheHits` / `willCall`，但**没有单资产**的成本预估 | `src/server/routes/doctor.ts` | 单资产需要独立的零成本摘要，不能拿类别估算凑 |
| 医生入口在资产详情只读视图内，仅 rule / identity / memory 提供；mcp / skill 不提供 | `web/src/components/vault/AssetEditor.tsx` | 详情里已有入口，但要点一次；且不覆盖 mcp |
| 报告由 `DiagnosisPanel` 就地渲染，修复走 `FixFlow` + `/api/doctor/fix-draft` / `apply` / `undo` | `web/src/components/doctor/*`、`src/server/routes/doctor-fix.ts` | 流水线所需能力已在，缺的是"常驻呈现"与"串起来" |
| 分发走 `DistributionDialog` + `/api/sync/run`，回滚走 `/api/swap/rollback` | `web/src/components/vault/DistributionDialog.tsx` | 分发无需新建通道，只需就地衔接与结果留存 |
| 进入资产详情是组件内状态（`viewMode`），**URL 不记录**；从治理页/首页过来只能落到类别页 | `web/src/pages/Vault.tsx`、`web/src/lib/use-home-dashboard.ts` | 痛点 3 的根因：没有单资产地址，回退只能靠记忆 |

结论：这是一次**编排与呈现**的改造，不是再造引擎。把已有能力按"一个资产的一生"顺序摆进详情，并把每一步的成本与结果讲清楚。

## Goal

打开任意一个库内资产，用户可以在**同一个详情面板**内完成：

> 看到它上次体检的结论与是否仍然有效 → 重新诊断（或确认这次不花钱）→ 逐条看证据与建议 → 就地修复并自动复检 → 复检通过后就地分发 → 看到逐工具结果与回滚入口。

验收标准：

1. **不点击也能看到内容**：单资产类别进入即展开该资产；空类别给一个明确出口；多资产才是网格。
2. **首屏回答成本问题**：上次诊断时间 / 结论 / 问题数 / 结果是否有效 / 现在点一次会不会调用模型。
3. **不丢上下文**：诊断、修复、复检、分发全程不离开详情；从其它页面进来能直达，返回能回去。
4. **降级不伪装**：没有 AI、没有缓存、诊断失败、分发不可用，都说出具体原因，不拿"健康"冒充"没评估"。
5. **零新增数据出口**：不新增上传面，隐私文案与实际发送范围一致。

## Scope

### 做

1. **版面三套规则**（R1）：空类别 / 单资产 / 多资产，及类别切换时的状态清理。
2. **诊断摘要常驻**（R2）：详情首屏直接给出最近一次结论、时间、问题数、有效性、调用成本；新增一个**零模型**的单资产摘要读取接口。
3. **上下文与深链**（R3）：单资产地址化（`/vault/<类别>?asset=<库内相对路径>`）；从治理页 / 首页待办直达；回退保留来源页面状态。
4. **就地治理**（R4）：问题行展开证据 / 规则依据 / 建议；内嵌现有修复流；写库后自动复检；一键撤销本批修复。
5. **分发衔接**（R5）：复检通过后就地出现分发入口；结果就地展示；失败项可单独重试。
6. **降级与空态**（R6）：无 Key / 无缓存 / 诊断失败 / 分发不可用 / 非库内资产 / 文件已消失。
7. **布局与可达性**（R7）：宽屏双栏、窄屏全屏覆盖、键盘主链路、焦点归还、结果播报。
8. **隐私与文案一致**（R8）：默认本地、BYOK、只发必要内容，且界面措辞不得比实际更窄。

### 不做

- ❌ **不改诊断引擎与规则集**：不改 prompt 组装、闭集解析、机械检查阈值、`diagnosis-rules.yaml`、缓存 key 算法；只新增"上次运行指纹"旁路记录（见 D4）。
- ❌ **不做后台自动诊断 / 定时体检 / 轮询**：详情打开只读摘要，绝不隐式调模型。
- ❌ **不改批量能力**：批量体检、一键整改、健康分算法、去向 `/governance` 的导航结构均不动。
- ❌ **不改造技能 / 智能体专属视图**：`SkillsView`、`AgentsView` 内的详情与医生入口保持现状（不回归即可）；本变更的详情工作台指走 `AssetEditor` 的资产库内部类别。
- ❌ **不给 mcp 增加语义诊断**：mcp 详情不出现诊断区，只保留分发，并说明原因。
- ❌ **不新建分发通道**：仍走 `/api/sync/run` 与 `/api/swap/rollback`；不自建第二条写工具目录的路径。
- ❌ **不新增页面与顶层路由**：只给已有 `/vault/<类别>` 增加查询参数；导航五组不变。
- ❌ 移动端专属重排、命令面板、全局新建按钮、诊断历史趋势。

## 关键决策

- **D1 详情即工作台**：单资产闭环沉到资产详情；全局治理只负责"跨资产总览与批量"。同一件事不在两个入口各做一半——详情负责"这一个怎么改好"，治理负责"先改哪个"。
- **D2 三套布局，不做一套布局硬套**：空类别给单一出口；单资产类别进入即展开详情（列表保留一张卡并高亮，不再要求二次点击）；多资产维持网格 + 详情栏。单资产不拉伸成整行卡片（那会让一个 270px 卡片孤零零占满宽屏）。
- **D3 摘要零成本**：新增 `GET /api/doctor/summary`，只读本机记录与缓存键，**绝不调模型**；是否将调用模型由服务端按当前内容计算缓存键后给出，前端不做推断。详情打开时只发这一个请求。
- **D4 缓存三要素必须可见**：内容 / 准则集 / 模型任一变化即失效。为此新增"每个资产上次运行指纹"记录（本机 JSON，只存摘要与三个哈希/模型名，不存正文），使界面能回答"为什么这次会花钱"。诊断成功是唯一写入点，避免多处写入漂移。
- **D5 复用而不是新造修复链**：草案 → 一屏确认 → 备份 → 写库 → 可选分发，全部沿用现有 `/api/doctor/*`；本变更只把这段流搬进详情的视觉与状态编排。批量整改接口 `/api/governance/remediation/*` 本变更不调用。
- **D6 复检自动，但账要提前算**：apply 成功即意味着正文已变、缓存必然失效，复检会真实产生**1 次**模型调用。故确认屏必须提前写明"保存后将自动复检（将调用 1 次模型）"，复检中可见进度，失败可重试。**撤销不自动复检**——撤销本身不应再产生费用，只把摘要标注为"结果已过期"。
- **D7 分发复用既有真值**：工具清单与类别支持矩阵来自既有接口；执行走 `runSync(tools, false, { backup: true })`；失败项重试只重发失败工具，不重发成功项；状态刷新以分发索引为准，不在前端伪造"已同步"。
- **D8 降级诚实**：不会因为"没有模型"就把语义项当作通过，也不会因为"还没诊断"就显示为健康。所有未知一律说未知。

## 与既有变更的关系

| 变更 | 关系 | 边界 |
|---|---|---|
| **add-asset-doctor** | 复用其诊断 / 草案 / apply / undo / 备份 / 分发全部能力 | 不改其 spec 中的缓存口径（三要素命中即不调模型），只是把该事实**在 UI 上显性化**；不改 apply 的信任红线（落盘唯一入口仍是一次显式确认） |
| **add-diagnosis-rules** | 报告字段与展示口径以它为准（`ruleId` / 证据 / 置信度 / 覆盖度 / 忽略） | 本变更不新增规则、不计算结论；证据不足项继续"无法确定、不可修复、不计分"；忽略条数与恢复入口沿用其口径 |
| **add-asset-governance** | 健康分、下钻、批量整改仍是全局视图，保留 | 本变更**不删** `/governance`，也不改其 URL；只把"单资产修复"从"必须先经治理页"改为"在详情内即可完成"，全局页继续服务"先改哪个" |
| **refactor-home-action-panel** | 导航五组、`/vault` 唯一资产入口、旧 URL 映射全部保留 | 本变更只给 `/vault/<类别>` 增加 `?asset=` 参数（不新增路由）；首页待办与治理下钻的"去资产库修改 / 在资产库中打开"改为深链直达该资产，其余结构不动 |
| **refactor-governance-center（质量中心）** | 本变更负责单资产闭环；质量中心负责跨资产总览、跨类别批量与规则/忽略管理 | 单资产修复不在质量中心重复出现，问题行只提供「在资产库中打开」深链；批量修复归质量中心，本变更只做单条 |

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 新增"上次运行指纹"记录与报告缓存两套数据可能漂移 | 界面说"有效"但实际会调模型（或反之） | 单一写入点（诊断成功路径）+ 同一套 key 算法；摘要只在读时比对，不自行推断；后端用例覆盖"内容变 / 准则变 / 模型变 / 都没变"四态 |
| 单资产类别自动展开打扰用户 | 想先看列表却被面板占满（窄屏尤甚） | 仅在"该类别资产数 = 1"时自动展开一次；用户关闭后本次停留不再重开；窄屏自动展开改为直接进入详情（不叠加列表与覆盖层） |
| 自动复检把"改一次"变成"花两次" | 用户对费用敏感 | 确认屏提前披露 1 次调用；复检失败可重试；撤销不再触发调用 |
| 详情内信息密度过高 | 首屏看不到正文 | 渐进披露：摘要一行、问题默认折叠证据、分发结果折叠历史；正文仍可滚动 |
| 深链与组件内状态并存 | 前进/后退行为不一致、回退丢上下文 | URL 为唯一真源：详情是否打开由 `?asset=` 决定；关闭即移除参数（替换式历史），来源页用 `navigate(-1)` 语义 |
| 视觉改动回归既有资产库用例 | 破坏既有交互（双击卡片收起、Esc 归还焦点） | 三档视口 + 键盘走查；既有 `Vault.test.tsx` / `AssetEditor` 用例保持意图，只更新结构假设 |

## 回滚

按 Phase 分 commit：①版面与深链（纯前端，无接口）②摘要接口与记录（只读旁路，失败可整体忽略）③就地治理（复用写链路）④分发衔接（复用同步通道）。
回滚 ②：详情退化为"手动点诊断"，其余可用；回滚 ③④：修复与分发退回既有面板/对话框入口，数据零损坏。任何一步都不改诊断缓存与备份格式，回滚不丢历史。

## 开放问题（待维护者拍板，附推荐）

1. **自动复检是否默认可关？** 推荐：默认开启，确认屏提前披露"将调用 1 次模型"，并在设置里提供"修复后不自动复检"开关（默认关，即保持自动）。若不加开关，则必须在确认屏给出"暂不复检"选项。
2. **新增本机 `doctor-last.json` 是否可接受？** 推荐：可接受。只存摘要元数据与三个指纹，不存正文、不上传；若维护者要求零新增文件，则退化为"仅本次会话内可见有效性"，重启后摘要显示"上次结论（有效性未知）"。
3. **诊断发送面是否在本变更内收窄到"证据片段"？** 现状诊断 prompt 仍发送资产正文（≤6000 字）。推荐：本变更只保证**不扩大**发送面，并把界面文案写成与事实一致；真正收窄随 add-diagnosis-rules 的发送层约束落地。
