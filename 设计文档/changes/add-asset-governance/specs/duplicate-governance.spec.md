# duplicate-governance.spec.md：重复治理（分组 → 合并草案 → 归档式合并 → 可还原）

> capability: 完全重复/近重复分组、组内保留建议、合并草案、归档式执行与还原
> 变更: add-asset-governance | 决策依据: proposal.md D7
> 入口: HUB 重复治理页（旅程 A）；MCP `assetplex_duplicates_scan`（旅程 C，只读扫描）

## 定义

- **完全重复**：正文归一化（去首尾空白、折叠连续空行）后内容哈希相同；或 name + description 归一化后完全相同。
- **近重复**：同类别且同时满足 ①名称相似度高 ②正文 token 集合相似度 ≥ 阈值（默认 0.85）；阈值可在配置中调整。
- **保留项**：组内建议保留的那一份，理由必须给（如"正文最完整 / 最近修改 / 被最多工具引用"）。
- **归档**：把不保留的成员移动到 `<Hub>/.archive/duplicates/<日期>/<类别>/`，**不删除**，可一键还原。

## Scenario 1：扫描出分组并给出保留建议

- **Given** 库内 12 个技能，其中 5 个是两份两份重复（同一技能在两个工具目录各一份）
- **When** 用户进入重复治理页并扫描
- **Then** 展示 2 个重复组与 1 个近重复组，每组含成员路径、来源工具、正文长度、最后修改时间
- **And** 每组标出建议保留项并给出理由；用户可改选其他成员
- **And** 页头汇总"可合并 3 组，预计减少 4 个重复条目"

## Scenario 2：确定性扫描零模型调用

- **Given** 用户未配置 AI 端点
- **When** 执行扫描
- **Then** 完全重复与满足阈值条件的近重复正常分组，零模型调用
- **And** 需要模型判断的疑难组（相似度落在灰区）标注"需 AI 判定"，并显示将调用的次数；未配置 AI 时不可执行该动作

## Scenario 3：合并草案不写库

- **Given** 用户选中一个近重复组，确认保留项
- **When** 点击「生成合并草案」
- **Then** 展示保留项与待归档项的内容差异，以及合并后的完整正文（可编辑）
- **And** 库内文件零变化，草案可关闭丢弃

## Scenario 4：归档式合并执行

- **Given** 用户确认合并草案
- **When** 执行合并
- **Then** 保留项按草案内容写库（写前备份），其余成员移入归档目录，随后按用户勾选分发到工具
- **And** 结果逐项回报：保留项写入结果、每个归档项结果、每个工具分发结果；任一项失败不中断其余项

## Scenario 5：还原

- **Given** 某组合并已成功，之后用户发现合并不该做
- **When** 点击「还原本组」
- **Then** 归档成员移回原路径，保留项恢复合并前内容，分发状态重新计算并如实展示
- **And** 还原失败时明确列出未还原的路径与原因

## Scenario 6：无重复不打扰

- **Given** 扫描后无任何重复组
- **When** 进入重复治理页
- **Then** 显示"没有发现重复条目"，不生成空的组卡片、不推送建议

## Scenario 7：边界与安全

- **Given** 两个技能名称相似但属于不同用途（如同一工具链的"部署"与"回滚"）
- **When** 出现在灰区分组
- **Then** 默认标记为"待人工判断"，不自动并入可执行合并组；必须用户显式勾选才可生成草案
- **And** 跨类别（技能 vs 规则）永不合并
- **And** 环境（未入库）条目只在组内提示"工具侧存在同名副本"，不参与归档动作

## Scenario 8：规模护栏

- **Given** 全库 200 个技能
- **When** 扫描
- **Then** 扫描在本地完成且展示进度；分组数超过 50 时结果分页，合并执行一次最多 10 组，超出提示分批
