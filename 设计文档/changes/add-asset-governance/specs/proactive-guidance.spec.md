# proactive-guidance.spec.md：主动性建议与首屏第一印象

> capability: 首屏结论式引导、建议清单、建议节流与可执行性
> 变更: add-asset-governance | 决策依据: proposal.md D8/D9
> 入口: HUB 首页（旅程 A）

## 定义

- **建议**：一条"现在最值得做的事"，含结论句、理由、影响面、一个可一键执行的入口。
- **可执行建议**：点击后直接进入某个已存在的流程（整改计划 / 重复治理 / 分发 / 配置 AI），不产生新的确认负担。
- **不可执行信息项**：只能解释、不能一键做的事（如"你有 3 类资产尚未纳入管理"），最多 1 条，且不占前三条建议位。

## Scenario 1：首次进入先收拾烂摊子

- **Given** 用户已完成一次扫描，库内与工具侧存在重复与缺字段资产
- **When** 首次进入首页
- **Then** 首屏不先问"要不要导入"，而是给结论："扫到 N 个技能，其中 M 个是重复/近重复，K 个缺关键信息"
- **And** 主按钮为"帮我收拾"（进入整改 + 去重合并流程），次按钮为"先看看"（关闭引导，仅本次会话）
- **And** 若扫描结果干净，则改为展示"家底干净"与可选的高价值动作（如"接入 MCP"）

## Scenario 2：建议最多三条且排序稳定

- **Given** 全库存在重复、可修复问题、分发待更新、AI 未配置四类可做之事
- **When** 打开首页
- **Then** 最多展示 3 条建议，按「影响面 × 可执行性」排序，第一条为影响面最大者；同类建议合并为一条（不逐资产刷屏）

## Scenario 3：无可做之事不硬凑

- **Given** 资产全部合格、全部分发、无重复、AI 已配置且诊断无问题
- **When** 打开首页
- **Then** 建议区显示"状态良好，暂无需要处理的事项"，不生成任何低价值建议

## Scenario 4：每条建议必须一键可执行

- **Given** 建议"12 个资产缺少触发描述"
- **When** 点击该建议
- **Then** 直接进入整改计划页并预选该批问题，不需要用户再自己找入口
- **And** 建议卡片上标注预计动作规模（"涉及 9 个资产 / 预计调用 5 次模型"）

## Scenario 5：建议不打断

- **Given** 用户正在 HUB 其他页面操作
- **When** 有新建议产生
- **Then** 不弹模态框、不出现红点计数、不改变用户当前页面；建议只在首页建议区呈现

## Scenario 6：忽略与恢复

- **Given** 用户点击某条建议的"本次忽略"
- **When** 本次会话内再次进入首页
- **Then** 该建议不出现；关闭浏览器重开或问题发生变化（新增/减少）后重新出现
- **And** 被忽略的建议不影响健康分展示

## Scenario 7：AI 未配置时的建议口径

- **Given** AI 端点未配置
- **When** 生成建议
- **Then** 建议只基于确定性数据（机械项、分发状态、重复分组），并明确说明"更多语义建议需配置 AI"
- **And** 不把"可能有语义问题"写成确定结论

## 边界

- 建议生成必须本地完成，除用户主动发起诊断外不调用任何模型
- 建议不包含任何需要用户额外输入才能执行的项（如需用户填表的一律不列为建议）
