# proposal: add-asset-governance（懂你的资产管家：真实健康度 → 一键整改 → MCP 双入口 → 去重治理）

> 级别：S（定位升级 + 新聚合能力 + 新入口形态 MCP + 跨类别治理链路）
> 状态：待维护者审核
> 依赖：add-asset-doctor（诊断/草案/apply/分发基建）、add-llm-conflict-arbitration（准则/LlmClient/缓存）、distribution-status（分发真实状态）、enable-tool-hot-swap（分发执行通道）

## 为什么做（背景）

1. **维护者验收反馈（2026-11-08）**：现在是"资产保险箱 + 同步工具"——只回答"资产在不在、到哪了"，不回答"我的资产好不好、缺什么、该怎么改"。期望是**管家**：主动维护个人 AI 资产（身份/技能/规则/记忆/子代理），把最佳实践嵌进维护动作，再供给/分发到各 Agent 工具。
2. **定位升级一句话**：管家是角色，懂你是价值。产品人格从「仓库管理员」变成「你的个人超级工程助理」。
3. **现状四个硬缺口**：
   - 假健康分：首页分数由资产条数线性推导（条目越多分越高，与质量无关），且无构成、无下钻、无整改。
   - 无治理动作：82 类重复条目只能人肉比对，软件不主动指出"这几份是一回事"。
   - 零主动性：首页不告诉你"今天最该改什么"，全靠用户自己翻页面。
   - 无 MCP 入口：Agent 工具里用不上你的资产库，只能靠文件同步"物理投喂"，与 MCP-first 时代脱节。
4. **地基已充足**：诊断（机械 + 语义）、修复草案、apply/备份/分发、准则包、分发真实状态判定都已落地。本变更不是重写，而是**把已有能力编排成管家视角 + 补一个 MCP 端口**。

## 用户旅程（本变更的验收主线）

| 旅程 | 场景 | 走哪条路 |
|------|------|----------|
| A 专项整理 | 周末坐在电脑前，想系统收拾一遍资产 | HUB 首页健康分 → 维度和清单 → 一键整改 |
| B 顺手维护 | 在 TRAE 里写代码时想起"这条偏好该记下来" | MCP `propose` → 宿主内确认 → `commit` 写入库 |
| C 自动取用 | 新开一个会话，Agent 自动知道我是谁、守什么规矩 | MCP 只读工具 + 分发时注入的"开工前先取身份"引导语 |

三条旅程共用同一套 core 与同一个 `~/.assetplex` 数据源；HUB 是主界面，MCP 是第二入口，**不是替代关系**。

## 目标

| # | 目标 | 用户可见结果 |
|---|------|-------------|
| G1 | 真实健康分 | 分数由「完整性 / 规范性 / 分发一致性 / 唯一性」四维计算，与资产条数无关；每分可解释 |
| G2 | 构成下钻 | 点任一维度 → 问题清单（按严重度排序）→ 点条目直达资产详情与体检报告 |
| G3 | 一键整改 | 批量可修复项生成计划 → 一屏确认 → 逐项执行 → 汇总成败 → 整批可撤销 |
| G4 | MCP 第二入口 | `assetplex mcp` stdio 服务：只读取用 + 两段式写入（propose/commit），TRAE、Claude Code 等一行配置接入 |
| G5 | 去重治理 + 主动性建议 | 主动指出完全重复/近重复分组，给合并草案与归档式合并；首页最多 3 条"今天最该做的事"，每条一键可执行 |

## 非目标

- ❌ **不做内建对话助手**：不在 Web 里再造一个 Chat 面板；对话入口交给用户已有的 Agent 工具（MCP）
- ❌ **不做云端账号/多端漫游**：仍是本地优先的资产箱
- ❌ **不做无确认自动修复**：管家给建议、给草案、给一键，但改库必须用户点头（沿用 D2 信任红线）
- ❌ **不做删除**：重复治理只归档（可还原），永不物理删除资产
- ❌ 生成式入职（"问几个问题自动生成身份/规则初稿"）——第四步，未立项，不在本变更
- ❌ MCP 远程传输（HTTP/SSE、鉴权、多用户）——一期只做 stdio 本机
- ❌ 分数历史趋势、团队看板、评分排行
- ❌ mcp 服务器的语义诊断（沿用医生既有非目标）

## 关键决策

- **D1 分数必须可解释、可下钻、可整改**：任何展示给用户的分数，都必须能回答"为什么是这个分 / 改哪里能涨分"。做不到就不展示分数（宁缺勿假）。
- **D2 四维加权 + 缺失维度权重重归一化**：完整性 30 / 规范性 30 / 分发一致性 25 / 唯一性 15。某维度无适用资产（如一个工具都没装）时标"不适用"并把权重按剩余维度归一化，**不因未接工具而扣分**。
- **D3 降级要明说**：AI 未配置时规范性维度只计机械项，界面标注"语义质量未评估"，不把未评估当满分也不当零分。
- **D4 一键整改 = 批量医生，永不跳过确认**：计划页展示条目、预计模型调用数、不可修复项与原因；单批上限 20 个资产（超出提示分批）；逐项独立成败；成功项可整批撤销（库内恢复 + 分发侧回滚入口）。
- **D5 MCP 是端口不是产品**：复用 core 全部能力，零独立数据库、零独立配置；HUB 与 MCP 数据永远同一份。HUB 仍是主界面。
- **D6 MCP 写操作两段式**：`propose` 只产草案与预览（零写库），返回 `pendingChangeId`（TTL 10 分钟）；`commit` 需带上该 id 且要求宿主侧用户确认语义。写前备份、越界拒写、环境条目拒写。
- **D7 去重先确定性、后模型**：内容哈希（归一化空白）+ 名称/描述归一化 + 正文 token 集合相似度，零调用即可分组；LLM 只用于"疑难组该不该合并"与合并草案生成，且发起前估算调用数。
- **D8 主动性有节制度**：首页建议最多 3 条，按「影响面 × 可执行性」排序；每条必须一键可执行；无可做之事就明说"状态良好"，绝不硬凑；不做模态弹窗、不做红点计数。
- **D9 首屏先收拾烂摊子**：首次进入若扫描到问题，首屏直接给结论与主 CTA（"扫到 N 个技能，其中 M 个重复，K 个缺关键信息，要我先收拾吗"），而不是"要不要导入"。
- **D10 同步降级为兼容路径**：MCP 之后，同步的职责收敛为「安装插座 + 分发一行引导语」；文件搬运只服务不支持 MCP 的工具。

## 影响面

- `src/mcp/` + `src/cli/`：新增 `assetplex mcp` 子命令（stdio 传输）；`sync` 增加引导语注入
- `web/`：首页健康分卡（构成 + 下钻）、整改计划与执行页、重复治理页、建议条
- 依赖：新增 `@modelcontextprotocol/sdk`（仅运行时依赖，不引入任何前端框架）
- 文档：taxonomy 补"管家层"；README 补 MCP 接入；PRIVACY.md 补 MCP 数据边界
- 不动：扫描器、适配器、swap 执行内部逻辑（仅被复用）

## 风险与预留

- **分数争议**：用户可能不认同权重。缓解：权重可在 hub.toml 覆盖（一期先固定并披露，二期开放）；维度可分开展示，避免"一个总分定生死"。
- **重复合并误判**：近重复阈值可能把"同主题不同用途"的技能判成重复。缓解：默认只归档不删除 + 合并前逐组人工确认 + 归档可还原。
- **MCP 写入越权**：模型可能误用 commit。缓解：两段式 + TTL + 宿主确认 + 备份，四道闸。
- **批量整改烧 token**：计划页先给估算，超过阈值二次确认；缓存生效项不计费。
- **示例数据隐私**：所有 spec/测试夹具一律中性示例名（`demo`、`testuser`、`example-skill`），禁止照搬本机真实目录与资产名。

## 回滚

按 Phase 分 commit：①健康分（只读聚合）②整改（写链路）③MCP（新入口）④去重（写链路）。任一 Phase revert 后其余功能仍可用；revert ③④后退回"纯 HUB 管家"，数据零损坏（归档目录只是普通文件夹）。
