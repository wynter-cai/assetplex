# proposal: refine-skill-cards-wizard（P2-B）

> 级别：M（specs + tasks + TDD）
> 来源：`assetplex-ui-ux-roadmap.md` P2-B；问题编号 P1-7 残余、P2-3、P1 遗留「行内修改无反馈」
> 前置：P2-A `enhance-a11y-responsive` 已完成（令牌基线、焦点环、断点基线已落）

## Goal

把技能卡与收藏向导的「噪声」降到一眼能扫的程度，并让行内改分类变成可撤销的确定动作。三件事：

1. **九职能色彩编码 + 图例**：职能徽章此刻全灰，九个分类在卡面上完全等价，用户无法建立「颜色 = 职能」的肌肉记忆；补上色彩编码，并给一个随时可查的图例。
2. **技能卡完整减负 + 行内改分类确认式化**：P1 只做了「徽章 ≤2 枚」，卡面仍常驻一整行「职能分类」下拉（高度约 28px/卡），且改分类即刻落盘、无确认无撤销（审计 P0-4 已记「行内 select 即时生效，无 loading/无成功反馈/无撤销」）。
3. **收藏向导降噪**：扫描把隐藏配置（如 `.arkcli-managed-skills.json`）当技能列出来；二进制文件（如技能目录里的 `_icon.png`）在冲突页被要求「智能合并：追加新内容」——图片没有「追加」语义；228 个发现文件平铺，没有按状态折叠。

## 方案

### A. 九职能色彩编码（code 侧）

- 九个职能各一个颜色令牌 `--fn-coding` … `--fn-other`（HSL 三分量，落 `index.css` `:root`）。
- **徽章形态**：中性底 + 左侧 6px 色点 + 文字（而不是整枚彩色底），颜色只做编码不做重点，避免和语义色（success/warning/info/destructive）抢注意力。
- 色彩选择避开既有语义色色相：`warning` 26、`success` 142、`info` 224、`destructive` 0 四个区间不占。
- 图例：技能页工具条放「图例」按钮，弹出九类色点 + 名称 + 当前计数。
- 对比度：色点属图形元素，对白底 ≥3:1（`contrast.ts` 断言）；徽章文字用既有 `--muted-foreground`（P2-A 已校准 ≥4.5:1），不新增文字色。

### B. 卡面减负 + 行内改分类确认式化（web 侧）

- 卡面移除常驻「职能分类」下拉行，改为卡面右上角图标按钮「调整分类」；点开后在卡内展开确认区（下拉 + 「应用」「取消」）。
- 应用成功后 toast「已改为 ××」并带「撤销」动作（30s 内可撤，撤销即写回原分类）；失败 toast 报错并把下拉回滚到原值。
- `toast-store` 增加可选动作：`action?: { label: string; onClick: () => void }`，视图渲染为 toast 内文字按钮（不改三态与去重规则）。
- 详情面板补同一职能选择器（卡面收起后保持可发现性）。

### C. 收藏向导降噪（core + web）

- **隐藏条目过滤**：`AdapterBase.scanDirectory` 跳过「以 `.` 开头的文件与目录」，只作用于目录递归；适配器显式映射的点文件（WorkBuddy/Claude Code 的 `.mcp.json`）走 `makeDiscoveredItem`，不受影响（已核 `workbuddy.ts:312`、`claude-code.ts` 显式路径）。
- **二进制识别**：`DiscoveredItem` 增加 `binary: boolean`，扫描期按扩展名判定（廉价、可单测）；导入期再加一道 NUL 字节嗅探兜底。
- **二进制处理**：扫到的二进制照常列出但**默认不勾选**、标注「二进制文件，收藏时跳过」；冲突页对二进制只给「覆盖 / 跳过」两种策略，不给「智能合并」、不给差异视图与 AI 仲裁，文案改成「二进制文件无法逐行合并」。
- **导入期兜底**：`executeImport` 遇到二进制改为 `status='skipped'` + 说明原因，不再写乱码。
- **按状态折叠**：Step 3 拆成「内容冲突（N）」「库内已存在（N）」「新增文件（N）」三组，冲突组默认展开，另两组默认折叠（可展开预览条目）。

## 非目标

- 不动职能九分类的 MECE 重构（P2-9 独立议题）：仍是 9 个分类，只上色。
- 不改扫描口径、不改冲突判定规则（`none/exists/differs` 语义不动）。
- 不做暗色模式：颜色令牌只补 `:root`，`.dark` 留空不新增。
- 不改收藏/导入的落盘语义（除二进制跳过这一条）。
- 不做卡面拖拽排序、不做批量改分类的交互翻新。

### 收口说明：二进制按原样复制

方案 C 原写「导入期遇到二进制改为 skipped」，实装改为**原始字节复制**（`writeHubFileBytes`）：
二进制条目默认不勾选但可手动勾选，`created` / `overwritten` 逐字节复制；只有「策略为 merge」的二进制才 `skipped`。
理由：技能目录里的图标必须能跟技能一起进库，一律跳过等于永远收不全带图标的技能。详见 `specs/import-wizard-noise.spec.md`。

## 风险与对策

1. **隐藏过滤误伤**：`scanDirectory` 是共享基类，四个适配器都走它 → 先写失败测试覆盖「点文件/点目录被跳过 + 显式映射的 `.mcp.json` 仍能扫到」，再改实现。
2. **二进制误判**：扩展名白名单会漏（未知后缀）→ 扫描期扩展名 + 导入期 NUL 嗅探双保险；单测覆盖「UTF-8 中文 md 判文本」「含 0x00 判二进制」「.png 判二进制」。
3. **色彩与语义色混淆**：9 色相避开语义色四区间；图例常驻可查；色点仅 6px 不做大面积填充。
4. **撤销与并发**：撤销写回原分类可能覆盖用户随后的手动改动 → 撤销只在 toast 存活期内有效，且写回前比对当前值是否仍等于「改动后的值」，不等则提示「分类已被修改，撤销已失效」。
5. **卡面减负导致可发现性下降**：图标按钮带 `aria-label="调整 {name} 的分类"` + 详情页保留同款控件；e2e 断言按钮可达。
