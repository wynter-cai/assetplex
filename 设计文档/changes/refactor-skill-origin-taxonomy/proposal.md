# refactor-skill-origin-taxonomy：技能来源分类 MECE 重构 +「保险箱」改名「我的库」

## Goal

当前技能来源六分类（保险箱/个人自建/项目技能/插件自带/市场安装/官方内置）违反 MECE：把「管理状态」和「来源出处」两个维度压进了一行——

1. **保险箱是状态不是出处**：它表达"入没入库"，与"从哪来"（市场/插件/官方）不在同一维度；
2. **个人自建恒为 0**：自建技能实际住在保险箱（31）和项目（68）里，"个人自建"切的是文件位置（用户级目录）而非出处，分类与用户心智错位；
3. **项目技能混合作用域与出处**：项目里的 68 个技能基本都是自建的，"项目"表达作用域（已有「项目 · 工作区名」徽章表达），在来源轴重复占位；
4. **术语违反陌生用户开箱即用**（宪法第 8 条）：「保险箱」「沉淀」是圈内隐喻，开源陌生用户费解。

本次变更：①来源轴重构为纯出处四类（自建/市场安装/插件自带/官方内置），MECE；②入库状态独立表达（三档状态开关，不占分类轴）；③术语全面替换：保险箱→我的库、沉淀→收藏、沉淀自→来自。

## Scope

### 做

- **后端**：inventory 推导 `provenance`（4 值出处）与 `inLibrary`（是否已入库），替换 origin 六值枚举的 API 对外语义；列表过滤参数改 `provenance` + `status`；计数结构改 `countByProvenance` + `countByStatus`；写管理/沉淀契约等价迁移（内部判定 vault → inLibrary，行为不变）
- **前端**：来源 chips 单行四类；状态用三档分段控件（全部/我的库/未入库）与出处 chips 正交组合；全量 UI 文案替换（详情面板、对话框、批量条、删除确认、Home 等所有出现「保险箱/沉淀」处）
- **agent-labels**：「保险箱」标签同步改名「我的库」（术语一致性），智能体分类结构不动

### 不做

- 职能九类（编码开发/浏览器自动化/工作流自动化…）的 MECE 重构——同样混维度（渠道/模式混进领域轴），下一步单独 spec
- vault 物理目录改名与数据迁移（磁盘路径、source frontmatter 格式、内部标识均不动）
- 旧 API 参数兼容（本地应用无外部消费者，前后端同仓同发布，直接破坏式更换）

## Risks

| 风险 | 缓解 |
|------|------|
| origin 字段被 scanners/merger/curation/write/routes/frontend 多处引用，重构面广 | tasks 按层拆分，每层完成即跑全量测试 |
| 写管理契约（仅 vault 可写）必须等价映射为 inLibrary=true | 回归测试逐条对照原契约场景 |
| 计数语义变化（chips 计数随状态筛选联动） | spec Scenario 明确计数口径，组件测试锁定 |
| AI 分类缓存失效 | 不受影响——缓存 key=SKILL.md 内容 hash，与 origin 无关，442 个技能无需重新分类 |

## 关键设计决策（用户已拍板 2026-10-06）

1. **命名**：保险箱 → **我的库**（ Steam/相册库心智，零学习成本）；按钮「收藏到我的库」
2. **结构**：**单行纯出处**四类，库状态不占分类轴，用状态开关表达
3. **补强**：三档状态开关（全部/我的库/未入库）× 出处 chips 正交组合——保住「未入库 × 市场安装 = 待收藏候选」杀手级查询（当前基线 292 个待收藏市场技能）
