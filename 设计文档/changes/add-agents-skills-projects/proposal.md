# Change: add-agents-skills-projects

> Change ID: `add-agents-skills-projects`
> 类型: S 级（新增资产来源 + 新增顶级模块 + 技能视图重构）
> 状态: 待审核
> 日期: 2026-10-05
> 作者: 用户反馈

## 背景与问题（Problem）

实际使用中发现三处"看不到全貌 / 管不起来"：

1. **子智能体散落各处，没有统一视图**。TRAE、CodeBuddy、Codex、Claude Code 都有子智能体（用户自建 agent、CodeBuddy Expert、TRAE 内置 persona、插件包内智能体），但 AssetPlex 目前只盘点了 4 类核心资产，智能体完全不可见。
2. **技能数量过百，平铺无法浏览**。仅本机 `~/.trae-cn/skills` 就有 29 个，叠加各工具与插件后总数 100+。当前技能只有平铺列表，无法看到全貌、无法按类型筛选。
3. **AI-Coding 跑过哪些项目，无可视化入口**。用户在 `~/.trae-cn/worktrees/` 下已有 15 个项目，但没有任何地方能集中看到"我用 AI 做过哪些项目、每个项目用了什么 AI 工具、有哪些资产"。

## 预期结果（Proposed outcome）

做完后，用户可以：

1. 在**资产库**新增"智能体"类别，一处看到来自各工具的全部子智能体（只读盘点：来源、类型、名称、描述、文件位置）。
2. 在**技能**模块看到分类全貌：可按「职能」分类浏览，也可切换按「来源」分类；自动归类 + 支持手动调整。
3. 在侧边栏新增顶级菜单**「项目」**，可视化查看 AI-Coding 项目清单，每张项目卡含基础信息、AI 工具标记、项目资产统计，并提供"在文件管理器 / 终端 / IDE 打开"快捷操作。

## 范围（Scope）

### 做什么

**A. 智能体（只读盘点）**
- 扫描四类来源：
  - 用户自建子代理：Claude Code `~/.claude/agents/*.md`、Codex `config.toml` 内嵌 agents
  - CodeBuddy Expert：`~/.codebuddy/expert-history.json` 等
  - TRAE 内置 persona：`~/.trae-cn/builtin/code|work/*`（hebe、iris、thetis 等）
  - 插件包内智能体：`~/.trae-cn/plugins/*` 与 CodeBuddy 插件市场中携带的 agent/技能
- 资产库左侧导航新增"智能体"，支持按来源/类型筛选，点击查看详情与源文件位置
- 第一版**只读**：不做导入 Hub、不做跨工具分发、不做编辑

**B. 技能分类（两个维度）**
- 「职能」维度自动归类：编码开发、文档写作、浏览器自动化、数据处理、DevOps/部署、AI 集成、设计创意、工作流自动化、其他
- 「来源」维度：官方内置、插件自带、个人自建、市场安装
- 基于 SKILL.md 的 name/description 做规则/关键词自动归类，允许用户手动覆盖
- 提供全貌视图：分类计数 + 分组展示 + 分类筛选

**C. AI-Coding 项目（新顶级模块，TRAE 优先）**
- 数据源：`~/.trae-cn/worktrees/` + `~/.trae-cn/work/`
- 项目卡信息：项目名、路径、最近修改时间、目录是否仍存在
- AI 工具标记：识别项目内 `.trae/`、`.claude/`、`AGENTS.md` 等标记
- 项目资产统计：项目内规则/技能/文档数、git 分支与状态
- 快捷操作：在文件管理器 / 终端 / IDE 打开
- 侧边栏新增顶级菜单「项目」

### 不做什么（Non-Goals）

- ❌ 智能体不做跨工具分发/导入/编辑（格式差异大，后续迭代）
- ❌ 项目模块第一版只接 TRAE 数据源，不做多工具项目聚合、不做全盘磁盘扫描
- ❌ 不新增 command / memory 类别（沿用分类法既定节奏）
- ❌ 不引入新框架/状态库（继续 Hono + React + shadcn/ui + TanStack Query）
- ❌ 不做项目内编辑，项目模块只做可视化与快捷打开

## 受影响系统

- 后端：`src/core/`（新增 agent 扫描器、技能分类器、项目扫描器）、`src/server/routes/`（新增对应 API）
- 适配器：`src/core/adapters/`（各工具补 agent 发现能力）
- 前端：侧边栏、资产库（智能体类别）、技能页（分类视图）、新增项目页与路由
- 数据：仅读取本机配置/项目目录，不涉及上传；路径信息属本机敏感数据，继续仅本地服务

## 约束（Constraints）

- 遵循架构单向依赖：扫描/分类纯逻辑放 `core/`，不反向依赖 server/web
- 禁止 `any` / `@ts-ignore`；公共函数显式返回类型
- 后端覆盖率门槛：行 80% / 函数 80% / 分支 75%
- 类别必须配置化、可扩展，不在前端导航/后端类型写死

## 风险（Risks）

| 风险 | 影响 | 缓解 |
|------|------|------|
| 各工具智能体格式碎片化 | 统一模型困难 | 第一版只读盘点，抽象最小公共字段（名称/描述/来源/路径），差异字段保留 |
| 自动分类不准 | 用户对归类结果不信任 | 规则透明可解释 + 手动覆盖 + "其他"兜底 |
| TRAE 内置/插件目录随版本变动 | 扫描路径失效 | 路径缺失时优雅降级，扫描器单测覆盖缺失场景 |
| work 目录为哈希名、worktrees 为项目名 | 项目信息需关联 | 以 worktrees 为主，work 仅作活动补充，关联失败不阻塞 |

## 实施阶段

- **Phase 1**：智能体只读盘点（后端扫描 + API + 资产库类别）
- **Phase 2**：技能分类（分类器 + 两个维度视图）
- **Phase 3**：项目模块（项目扫描器 + API + 顶级页面）
