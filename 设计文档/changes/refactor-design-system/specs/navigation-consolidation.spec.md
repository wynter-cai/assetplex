# Spec: 导航去重与窄屏详情可用

> Capability: navigation-consolidation
> Change: refactor-design-system（P1-4 / P1-5 P1 份内部分）
> 背景实测：全局侧栏 240px 内含「资产库 → 5 类别」子菜单，资产库内部又一道 192px
> 左栏，内容完全重复；718px 视口下打开技能详情，主从两栏硬挤，卡片被压到 95px。
> 已拍板：撤 Vault 内类别栏，类别导航只保留全局侧栏一处。
> 侧栏折叠/汉堡菜单属 P2-A，不在本变更。

## MODIFIED Requirements

### Requirement: 类别导航单轨

#### Scenario: 在资产库切换类别

- **Given** 用户处于资产库任一类别页
- **When** 想切换到另一类别
- **Then** 唯一途径是全局侧栏的类别导航，点击即切换
- **And** 资产库页内不再出现第二道重复的类别栏

#### Scenario: 当前类别的上下文感知

- **Given** 用户已进入资产库某类别页（类别栏已撤）
- **When** 查看页面
- **Then** 通过页头 H1（类别名）明确当前类别（见 page-headers.spec.md）
- **And** 侧栏当前类别项呈选中态

### Requirement: 窄屏下技能详情可用

#### Scenario: 窄视口打开技能详情

- **Given** 视口宽度 <1024px，用户在技能列表
- **When** 点击任一技能卡打开详情
- **Then** 详情以全屏/抽屉式 overlay 呈现，可关闭返回列表
- **And** 列表卡片宽度不再被挤压（窄屏列表不与详情同屏硬挤）

#### Scenario: 宽视口主从布局

- **Given** 视口宽度 ≥1024px，用户打开某技能详情
- **When** 查看列表区
- **Then** 列表卡片宽度不因详情打开而低于 200px（不足则详情改 overlay 而非继续挤压）

#### Scenario: 长列表滚动中打开详情

- **Given** 视口宽度 ≥1024px，技能/智能体列表已滚动到中后段
- **When** 点击位于视口内的卡片打开详情
- **Then** 右侧详情面板贴住滚动视口顶部保持可见，不会跑到视口上方
- **And** 详情内容超出面板高度时由面板内部独立滚动，不带动左侧列表

#### Scenario: 切换详情对象

- **Given** 详情面板已打开且内容区已滚动
- **When** 点击列表中的另一个同类资产
- **Then** 详情切换到新对象，内容区回到顶部，不残留上一个对象的滚动位置

#### Scenario: 详情开关往返

- **Given** 任一视口宽度
- **When** 打开详情后关闭
- **Then** 返回先前的列表状态（滚动位置/筛选不丢失）

### Requirement: 连接页布局出血清理

#### Scenario: 打开连接页

- **Given** 用户打开连接页
- **When** 查看页面布局
- **Then** 内容与全局容器对齐，不存在负 margin 出血
- **And** 信息面板宽度自适应容器，不写死固定像素宽
