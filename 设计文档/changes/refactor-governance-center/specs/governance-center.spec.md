# governance-center.spec.md：质量中心（全局体检报告 + 跨类别批量 + 规则与忽略）

> capability: 命名与入口、全局体检报告与问题聚类、跨类别批量诊断、跨类别批量修复、规则与忽略管理、裁决准则、与单资产详情的边界、降级与空态
> 变更: refactor-governance-center | 决策依据: proposal.md D1-D8
> 前置口径：健康分与整改沿用 `add-asset-governance/specs/*`；规则、证据、置信度、忽略沿用 `add-diagnosis-rules/specs/diagnosis-rules.spec.md`；
> 单资产诊断 / 修复 / 复检 / 分发归 `refactor-asset-pipeline/specs/asset-pipeline.spec.md`；技能模块内分类与批量归 `refactor-skill-catalog/specs/skill-catalog.spec.md`；
> 导航结构沿用 `refactor-home-action-panel/specs/navigation.spec.md`（本规格只改该组名称、子项与 `/governance` 的去向）

## 定义

| 名词 | 含义 |
|---|---|
| **质量中心** | 面向全库的体检与批量处置入口，只回答「整体怎么样、先改哪一类」 |
| **问题聚类** | 把同一规则（或同一规则标题）在多资产上的命中合并成一条「问题类型」：含命中资产数、命中次数、严重度分布、可修复资产数、预计调用数 |
| **影响面分** | 受影响资产数 × 严重度权重（high 3 / medium 2 / low 1），跨类别求和；用于排序，不做「及格线」判断 |
| **预估** | 发起批量前披露的成本与影响：总资产数、缓存命中数、需调用次数、不可诊断项及原因、被跳过的规则条数 |
| **批量诊断** | 对选定类别或问题类型的多资产发起诊断；静态规则零调用，语义规则按 AI 配置与用户开关执行 |
| **批量修复** | 对可修复命中项生成修复计划，一次显式确认后逐项写库（含备份），整批可撤销 |
| **忽略** | 用户主动屏蔽某条命中；影响展示与计分，不改变资产内容 |
| **深链** | `/vault/<类别>?asset=<库内相对路径>`，直接打开该资产详情 |
| **内置规则 / 用户规则** | 内置随产品版本发布、只读；用户规则存于本机用户规则目录，可覆盖同编号或追加新编号 |
| **按需加载** | 只加载目标资产类别 + 跨资产通用规则，不把其他类别的规则喂给模型或计入覆盖度 |

统计口径（与 add-diagnosis-rules 一致）：跨资产通用规则在任一适用类别下可见，但全库只计一次；`mcp` 类别有规则但一期无诊断执行通道，必须在报告与预估中如实披露。

## ADDED Requirements

### Requirement 1：命名与入口收口为「质量中心」

**用户可见行为**：侧栏和页面只说「质量中心」；旧地址不 404，也不出现第二套入口。

#### Scenario 1.1 侧栏与页面改名

- **Given** 用户以任意视口打开任意页面
- **When** 侧栏渲染
- **Then** 第三组名称为「质量中心」，组内顺序为：体检报告、跨类别批量、规则与忽略、重复项、裁决准则
- **And** 全站不再出现把该功能称作「治理」的导航文案
- **And** 窄屏顶部摘要与页面主标题同步显示「质量中心」

#### Scenario 1.2 旧地址替换式重定向

- **Given** 用户收藏了旧地址 `/governance`
- **When** 直接在地址栏访问
- **Then** 落到 `/quality`，页面正常渲染、不 404
- **And** 使用替换式跳转，按浏览器返回不会立刻被弹回旧地址
- **And** 旧地址不再保留任何独立页面或第二套入口；`/quality/*` 各子页也不保留 `/governance/*` 同前缀副本

#### Scenario 1.3 徽标与首页同源

- **Given** 首页状态条显示「待治理 12」
- **When** 侧栏与质量中心渲染
- **Then** 组徽标为 12，质量中心概览的待处理数也是 12，三者取自同一次数据快照
- **And** 待处理为 0 或数据不可用时，徽标不显示，也不显示「0」占位

#### Scenario 1.4 直接输入新地址

- **Given** 用户直接访问 `/quality/batch`
- **When** 页面加载
- **Then** 「质量中心」组自动展开，「跨类别批量」高亮
- **And** 页面标题与浏览器标签都表明这是质量中心下的跨类别批量

### Requirement 2：全局体检报告（四维分数 + 问题聚类 + 可解释排序）

**用户可见行为**：一眼看出整体分数怎么来的、哪一类问题最多、为什么它排在最前面。

> 口径边界：健康分算法、维度权重与「不适用/数据缺失」降级均由 `add-asset-governance` 定义；未评估的展示口径由 `add-diagnosis-rules` 定义。本页只做**全库汇总与聚类排序**，不重新定义评分或降级规则。

#### Scenario 2.1 四维分数与构成

- **Given** 库内资产已体检过，四维均有评估对象
- **When** 用户打开「体检报告」
- **Then** 显示总分与四个维度（完整性 / 规范性 / 分发一致性 / 唯一性）的分值、权重、受影响资产数与问题数
- **And** 点任一维度可看到该维度的问题条目，条目只提供「在资产库中打开」深链
- **And** 任一维度无评估对象时显示「不适用」并把权重按剩余维度归一化，不显示为 0 分

#### Scenario 2.2 问题按类型聚类

- **Given** 全库 18 个技能中有 9 个缺 description，另有若干其他类别的问题
- **When** 用户查看体检报告的问题类型列表
- **Then** 出现一条聚类「技能缺 description」，显示「9/18 个资产 · 命中 N 次 · 高 0 / 中 9 / 低 0」
- **And** 展开该条可看到受影响的 9 个资产（资产名、严重度、是否可修复、深链），默认只列前若干条并可「查看全部」
- **And** 每一类都标明聚合依据是「规则编号」还是「规则标题」

#### Scenario 2.3 排序可解释

- **Given** 「技能缺 description」（9 个资产，全静态）与「人设边界模糊」（3 个资产，需模型）同时存在
- **When** 问题类型列表渲染
- **Then** 前者排在前面（影响面分更高）
- **And** 影响面相同时，预计调用更少的排在前面；仍相同时按类别声明顺序
- **And** 页面提供「排序依据」说明：影响面 = 受影响资产数 × 严重度权重，同分按成本升序

#### Scenario 2.4 诚实空态

- **Given** 库内没有任何资产
- **When** 用户打开质量中心
- **Then** 不展示健康分，展示「先把资产收进库再体检」与去资产库 / 去新手引导两个出口
- **Given** 库内资产全部达标、无命中
- **When** 用户打开体检报告
- **Then** 显示「未发现违反规则集的问题」+ 规则集版本 + 最近一次体检时间
- **And** 若存在被忽略的条目，同时显示「另有 N 条已忽略」与恢复入口，不把忽略算成健康

#### Scenario 2.5 语义未评估如实披露

- **Given** 用户未配置 AI 端点
- **When** 查看聚类列表
- **Then** 只展示静态规则命中，规范性维度标注「语义质量未评估」
- **And** 明确显示「另有 N 条语义规则本轮未评估」与配置入口，不把未评估显示为通过

#### Scenario 2.6 数据缺失不伪造

- **Given** 某类别的目录不可读
- **When** 计算体检报告
- **Then** 该类别标注「数据缺失，暂不可用」，不参与计分也不计入待处理数
- **And** 其余类别照常展示，不整页失败

### Requirement 3：跨类别批量诊断

**用户可见行为**：可以按类别或按问题类型圈定一批资产体检；点之前就知道要花多少次模型调用。

#### Scenario 3.1 两种圈选方式

- **Given** 库内有身份、规则、技能、智能体、记忆五类可诊断资产
- **When** 用户进入「跨类别批量」
- **Then** 可按类别多选（默认全选可诊断类别），也可从体检报告的问题类型多选带入
- **And** 两种方式同时使用时，显示交集的实际资产数量，不重复计数
- **And** 不可诊断的类别（如 MCP）在列表中标注原因并禁止勾选，不静默忽略

#### Scenario 3.2 发起前必须预估

- **Given** 用户已圈定 24 个资产
- **When** 用户查看发起区
- **Then** 显示：共 24 个资产、缓存命中 10 个、需调用 14 次、不可诊断 2 个及原因、本轮将跳过 8 条语义规则（原因：AI 未配置或语义开关关闭）
- **And** 只有「缓存命中」与「需调用」分开给出才算有效预估；缺任一项时发起按钮禁用并显示「无法估算成本，暂不能发起」

#### Scenario 3.3 上限与分批

- **Given** 用户圈定了 150 个资产，或预估需调用 260 次
- **When** 查看发起区
- **Then** 提示「单次最多 100 个资产」「单次实际调用上限 200 次」，并说明如何分批
- **And** 已选集合保留，用户可自行删减；不得截断后静默执行
- **And** 预计调用超过 50 次时，发起前需再确认一次

#### Scenario 3.4 执行与聚合

- **Given** 用户在预估页确认发起
- **When** 批量执行
- **Then** 逐资产显示进度与结果（完成 / 失败 / 跳过），单项失败不中断其余项
- **And** 结束后结果按「问题类型 → 资产」两层聚合，可按严重度筛选，并显示本轮覆盖度（评估规则数 / 跳过规则数及原因 / 规则集版本）
- **And** 每条结果只提供「在资产库中打开」深链，不提供就地修复

#### Scenario 3.5 诊断只读

- **Given** 批量诊断完成
- **When** 用户对比诊断前后的资产
- **Then** 资产正文、分发状态、备份记录均无变化
- **And** 失败项可单独重试，重试只针对失败项，不重跑成功项

#### Scenario 3.6 无 AI 也能跑

- **Given** 用户未配置 AI 端点
- **When** 用户发起批量诊断
- **Then** 仍可发起，本轮只跑静态规则并零模型调用
- **And** 明确说明「本次不评估语义质量」，不把语义项显示为通过或 0 分

### Requirement 4：跨类别批量修复

**用户可见行为**：批量改动前先看到会动哪些文件、花多少次调用；改完能一键退回。

#### Scenario 4.1 只有可修复项能进批量

- **Given** 某聚类下有 12 个资产命中，其中 8 个可修复、4 个仅建议
- **When** 用户点击「批量修复」
- **Then** 只有 8 个可修复资产进入计划，4 个仅建议项列出并注明「需人工判断，不参与批量」
- **And** 证据不足、无法确定的命中项一律不进入批量（沿用诊断口径）

#### Scenario 4.2 影响清单

- **Given** 用户已生成批量修复计划
- **When** 用户查看计划
- **Then** 显示：将修改的资产数、类别分布、每条资产的库内相对路径与命中规则、预计模型调用次数（缓存命中项标注「不消耗」）
- **And** 显示「写库前自动备份，可在本批完成后整批撤销」与「默认只改库，不分发」
- **And** 计划超过单批上限时，只勾选前 20 个并提示分批，其余不静默丢弃

#### Scenario 4.3 一次确认才写库

- **Given** 用户在影响清单页
- **When** 用户点击执行
- **Then** 弹出一次明确确认，说明将写入的资产数量与是否分发
- **And** 未确认前不产生任何文件写入
- **And** 同一批次执行中再次点击发起被禁用并说明「上一批仍在执行」

#### Scenario 4.4 逐项结果与汇总

- **Given** 批次执行完成
- **When** 用户查看结果
- **Then** 逐项显示成功 / 失败 / 跳过及原因，并汇总结论与批次号
- **And** 单项失败不影响其余项，失败项可查看原因

#### Scenario 4.5 整批撤销

- **Given** 本批有 7 项写库成功、3 项失败
- **When** 用户点击「撤销本批」
- **Then** 7 项库内内容恢复为执行前版本，3 项失败项不在撤销范围
- **And** 撤销本身失败时如实报告哪几项未恢复，不显示「全部已撤销」
- **And** 若本批选择了分发，撤销只恢复库内内容，分发侧提供逐项回滚入口，不自动回滚

#### Scenario 4.6 写库后数字刷新

- **Given** 批量修复完成
- **When** 用户返回体检报告
- **Then** 健康分、聚类计数与待处理数按最新内容重新计算
- **And** 侧栏徽标与首页状态条同步更新，不出现「质量中心说 5、首页说 12」的自相矛盾

### Requirement 5：规则与忽略管理

**用户可见行为**：看得见产品在用什么规则查我、查了哪些没查哪些；不认同可以忽略，也能随时恢复。

> 口径边界：规则的结构、静态/AI 分层、证据与「忽略按内容哈希失效」均由 `add-diagnosis-rules` 定义；单资产报告里的忽略展示归资产详情。本页只提供**全库规则浏览、按需加载披露、用户规则与忽略清单的集中入口**，不新增规则语义。

#### Scenario 5.1 内置规则可浏览、不可改

- **Given** 规则集已加载
- **When** 用户打开「规则与忽略」
- **Then** 列表显示每条规则的编号、类别、严重度、模式（静态 / AI）、一句话标题、来源依据
- **And** 可按类别筛选、按编号搜索；内置规则只读，不提供编辑或删除
- **And** 页面显示规则集版本与总数（含静态 / AI 条数）

#### Scenario 5.2 按需加载可披露

- **Given** 用户筛选到「技能」
- **When** 查看覆盖度
- **Then** 显示「本类别将评估 N 条（内置 X + 自定义 Y，含跨资产通用 K 条），跳过 Z 条及原因」
- **And** 跨资产通用规则只计一次，明细中标注「通用规则，在多个类别共用」

#### Scenario 5.3 用户自定义规则

- **Given** 用户在本机用户规则目录新增一条规则
- **When** 用户保存
- **Then** 保存前校验结构（编号、类别、严重度、模式、判定信号、建议、来源）；缺字段或编号非法时拒绝保存并指出具体字段
- **And** 与内置规则同编号时视为覆盖，列表标注「覆盖内置」；不同编号视为追加
- **And** 保存成功后规则列表与覆盖度立即反映新规则，无需重启

#### Scenario 5.4 坏规则跳过不拖垮体检

- **Given** 用户规则文件中有一条结构非法
- **When** 规则集加载
- **Then** 该条被跳过，其余规则（含内置与其他用户规则）照常工作
- **And** 规则页显示告警条「跳过 N 条规则」，可展开查看文件、编号与原因
- **And** 诊断不因单条坏规则整份失败；只有规则集版本缺失或全部规则非法才整体报错（见 R8）

#### Scenario 5.5 忽略清单与恢复

- **Given** 用户忽略了某资产上的某条命中
- **When** 用户打开忽略清单
- **Then** 列出资产、规则编号、忽略时间、是否已失效
- **And** 点「恢复」后下次体检重新提示该条；内容已变更导致忽略失效的条目标注「已失效」，并在下次体检自动重新提示
- **And** 忽略数据只存本机，不上传

#### Scenario 5.6 忽略透明计入披露

- **Given** 某类问题有 3 条被忽略
- **When** 用户查看体检报告
- **Then** 显示「已忽略 3 条」，忽略不计入扣分但条目仍可查看与恢复
- **And** 不出现「忽略后显示全部健康」的结论

#### Scenario 5.7 规则集升级提示

- **Given** 规则集版本从 v1.0.0 变为 v1.1.0
- **When** 用户打开质量中心
- **Then** 提示「规则集已更新，部分结论可能变化，建议重新体检」
- **And** 不自动发起任何诊断或模型调用，由用户显式点击

### Requirement 6：裁决准则迁入质量中心

**用户可见行为**：裁决准则与质量问题在同一处；资产库不再单列这一类。

> 口径边界：准则的字段、编辑、准则包与「只作偏好层」的限权由 `add-llm-conflict-arbitration` 的 criteria 规格与 `add-diagnosis-rules` D6 定义。本变更只负责**入口位置、旧地址重定向与资产库类别收敛**，不改准则数据面。

#### Scenario 6.1 入口位置

- **Given** 用户展开侧栏「质量中心」
- **When** 查看子项
- **Then** 存在「裁决准则」，点击进入 `/quality/criteria`
- **And** 资产库的类别子项中不再出现「裁决准则」

#### Scenario 6.2 旧地址兼容

- **Given** 用户收藏了 `/vault/criteria`
- **When** 直接访问
- **Then** 替换式重定向到 `/quality/criteria`，页面正常渲染
- **And** 准则列表、准则包导入、单条新增 / 编辑 / 删除的行为与迁移前一致

#### Scenario 6.3 职责与限权

- **Given** 用户在裁决准则页
- **When** 阅读页面说明与新建准则
- **Then** 页面明确说明：准则用于冲突仲裁与诊断建议的偏好叠加，不新增诊断规则编号
- **And** 新建准则不影响健康分、不改变规则集条数、不进入批量诊断的规则候选

#### Scenario 6.4 与忽略/规则的边界

- **Given** 用户关闭或删除某条准则
- **When** 重新体检
- **Then** 健康分与问题计数不因子项变化而升降（准则不计入健康分）
- **And** 规则与忽略页的规则集版本与条数不变

---

### Requirement 7：与单资产详情的边界（只给深链，不重复修复）

**用户可见行为**：质量中心负责「先改哪一类」，具体怎么改一定在资产详情完成，不会两处都有改按钮。

#### Scenario 7.1 深链直达详情

- **Given** 用户在聚类展开列表中点击某资产
- **When** 跳转完成
- **Then** 进入该资产所属类别并直接打开该资产详情，诊断摘要可见
- **And** 地址栏可反映是哪一个资产；详情内的关闭与返回行为沿用资产详情规格

#### Scenario 7.2 质量中心不提供就地修复

- **Given** 用户在质量中心的任一问题行或聚类
- **When** 查看可执行操作
- **Then** 只有「在资产库中打开」，没有「应用修复」「重新诊断」「分发」按钮
- **And** 不内嵌单资产体检面板，不因展开一行而触发诊断或模型调用

#### Scenario 7.3 详情回跳质量中心

- **Given** 用户在资产详情内
- **When** 点击「查看质量中心」
- **Then** 跳到质量中心，此前质量中心的筛选与展开状态保留
- **And** 返回时回到原资产详情，不丢失当前资产

#### Scenario 7.4 同一能力唯一归属

- **Given** 任一批量或单条能力
- **When** 用户在三个入口中寻找
- **Then** 单条诊断 / 修复 / 复检 / 分发只出现在资产详情
- **And** 跨类别批量诊断与批量修复只出现在质量中心
- **And** 技能模块内的分类、诊断选中与分发选中只出现在技能页，且其数字与质量中心同源

---

### Requirement 8：降级与空态

**用户可见行为**：没有模型、规则坏了、批量太大、只成功一半，都会说清楚，不会得到一份「看起来健康」的假报告。

#### Scenario 8.1 无 AI Key

- **Given** 用户未配置 AI 端点
- **When** 打开质量中心与批量页
- **Then** 静态规则结果完整可用，批量诊断可发起（零调用）
- **And** 涉及语义项的批量修复禁用并说明「需配置 AI 才能生成语义修复草案」
- **And** 页面不把未评估项计为通过或 0 分

#### Scenario 8.2 规则集校验失败

- **Given** 规则集版本缺失或全部规则非法
- **When** 用户打开体检报告或发起批量
- **Then** 显示「规则集加载失败（原因）」+ 重试入口，不展示 0 分、不展示「全部健康」
- **And** 已缓存的旧报告如需展示，必须标注「基于旧规则集 vX」，并提示重新体检

#### Scenario 8.3 批量超限

- **Given** 用户圈选资产数或预估调用次数超过上限
- **When** 用户尝试发起
- **Then** 按钮禁用并显示具体上限与当前数量，给出分批建议
- **And** 不得在成本未知或超限时发起任何模型调用或写库

#### Scenario 8.4 部分失败

- **Given** 批量诊断或批量修复中部分项失败
- **When** 本轮结束
- **Then** 汇总显示成功 / 失败 / 跳过数量，逐项给出原因
- **And** 诊断失败项可单独重试；修复成功项可整批撤销；两种操作互不混淆

#### Scenario 8.5 预估接口失败

- **Given** 预估接口超时或返回字段缺失
- **When** 用户查看发起区
- **Then** 显示「暂无法估算，请稍后重试」并提供重试
- **And** 发起按钮保持禁用，不提供「先跑起来再说」的旁路

#### Scenario 8.6 规则/忽略接口未就绪

- **Given** 本机版本尚未提供规则或忽略接口
- **When** 用户打开「规则与忽略」
- **Then** 显示「规则管理暂不可用」并只展示内置规则集版本与条数
- **And** 不展示可编辑控件，不伪造空白列表为「没有规则」

## 非功能约束

- **同源**：待处理数、健康分、聚类计数必须来自同一份服务端聚合，不允许前端二次估算；三个入口（首页、侧栏徽标、质量中心）数字不一致视为缺陷。
- **零隐式调用**：打开质量中心、展开聚类、浏览规则都不触发模型调用；只有用户显式发起诊断/修复才可能产生调用。
- **可解释**：任何排序、分数、批量范围都要能回答「为什么」；不提供无法复算的神秘分值。
- **隐私**：只展示库内相对路径与资产名，不出现绝对路径与用户名；聚合与预估不上传；规则、忽略、用户规则全部本机存储。
- **示例中性**：spec、夹具、测试数据一律使用 `demo-skill`、`example-rule`、`testuser` 这类中性名。
