# specs/onboarding.spec.md：首次使用向导（add-zero-config-onboarding）

> 适用屏幕：原型 s0–s6（开场 / 盘点 / 结果 / 收纳 / 静态体检 / 分发 / 完成）。
> 本规格只描述用户可见行为与数据口径，不规定实现细节；接口复用与扩展见 `api-contract.ts`。
> 全局约束：全程本地、不上传；静态环节零模型调用；任何写操作必须可取消且取消后零改动。

## 定义

- **首次环境**：未写入 onboarded 标记，且（`<Hub>/hub.toml` 不存在 或 资产库资产数为 0）。
- **盘点**：复用现有扫描能力，只读各工具配置目录，得到可导入条目（身份/技能/规则/MCP/智能体/记忆）。
- **收纳**：复用现有导入能力，把条目写入 Hub。
- **静态体检**：规则可判定的检查，零模型调用。
- **覆盖 / 冲突**：见 Requirement 6 的口径；二者都必须先备份再写入。

## 屏幕对照（原型 s0–s6）

| 屏 | 进入条件 | 必须出现的元素（文案以原型为准） | 主要出口 |
|---|---|---|---|
| s0 开场 | 首次环境访问 `/` | 「首次使用 · 约 60 秒」「你的 AI 资产，正在每个工具里各存一份」「全程本地 · 不上传」「开始盘点」 | 开始盘点 → s1；跳过 → 资产库 |
| s1 盘点 | 点击开始盘点 | 「正在盘点本机工具」「只读取配置目录，不改动任何文件」；工具清单与真实总数 | 扫描完成 → s2；单工具失败不阻断 |
| s2 结果 | 扫描完成 | 「盘点完成，你有 N 个资产」；类别分布；重复维护 / 内容不一致 / 只在部分工具存在 | 全部收进资产库 → s3；跳过 → 资产库 |
| s3 收纳 | 点击全部收进 | 「收进资产库」；写入中的真实状态；完成后「已入库 N 个资产」 | 下一步：体检 → s4；跳过 → 资产库 |
| s4 体检 | 收纳完成 | 「收纳完成，先做一次体检」；静态检查（已完成、零 API 调用）；「可选增强」AI 深度诊断 | 下一步：分发 → s5；跳过 → 资产库 |
| s5 分发 | 点击下一步分发 | 「分发到工具」「影响预览」：新增/覆盖/冲突/无变化 + 文件清单 | 二次确认 → 执行 → s6；取消留在本屏；跳过 → 资产库 |
| s6 完成 | 分发完成或中途跳过 | 真实结果数字（入库数、分发结果、静态问题数）；「进入资产库」 | 进入资产库 |

约束：视觉按原型，交互只实现本变更范围（s8/s9/s10 不实现）；屏幕上的所有数字必须来自真实接口。

## ADDED Requirements

### Requirement 1：首次进入自动进入向导

#### Scenario 1.1 首次打开 Web UI
- **Given** `ASSETPLEX_DIR` 指向一个空目录，服务已启动
- **When** 用户访问 `/`
- **Then** 直接呈现向导开场屏，不显示侧栏与首页内容
- **And** 开场屏包含「全程本地 · 不上传」「开始盘点」「跳过，直接进入资产库」
- **And** 不得出现尚未扫描就编造的资产数量

#### Scenario 1.2 CLI 无子命令首跑
- **Given** 本机处于首次环境
- **When** 用户执行 `npx assetplex`（不带子命令）
- **Then** 终端说明正在创建 Hub 骨架并打开引导
- **And** 自动启动 Web UI 并在浏览器落到向导，而不是只打印帮助
- **And** 创建骨架不得写入身份/规则空模板

#### Scenario 1.3 非首次环境保持原行为
- **Given** 用户已完成过引导，或资产库已有资产
- **When** 用户执行 `npx assetplex`（无子命令）
- **Then** 仍显示命令帮助，不启动服务、不写任何文件

#### Scenario 1.4 已初始化但无资产的用户
- **Given** 用户曾运行 `assetplex init`，`hub.toml` 存在但资产库为 0，且没有 onboarded 标记
- **When** 用户打开 `/`
- **Then** 自动进入向导
- **And** 已有 `hub.toml` 与目录不得被覆盖或重建

#### Scenario 1.5 服务不可达时不白屏
- **Given** 前端已加载，但后端服务停止或接口报错
- **When** 读取首次状态失败
- **Then** 显示可读错误与「重试」，不白屏、不跳空白首页、不写标记
- **And** 重试成功后按正常首次判定进入

#### Scenario 1.6 深链不被劫持
- **Given** 用户处于首次环境
- **When** 用户直接访问 `/vault`、`/settings` 等非根路径
- **Then** 按目标页面正常渲染，不强制重定向到向导
- **And** 只有访问 `/` 时才执行首次自动进入判定

### Requirement 2：盘点显示真实工具与资产数量

#### Scenario 2.1 工具行与安装状态
- **Given** 本机安装了部分受支持工具，另有工具未安装
- **When** 用户点击「开始盘点」
- **Then** 盘点屏逐工具显示：工具名、配置目录、已发现数量或「未安装」
- **And** 未安装工具必须标为未安装，不得显示 0 个资产冒充已检测
- **And** 页面说明「只读取配置目录，不改动任何文件」

#### Scenario 2.2 数量与实际扫描一致
- **Given** 隔离环境中的工具配置目录实际包含 N 个可导入条目
- **When** 盘点完成
- **Then** 该工具行数量与扫描返回条目数一致
- **And** 结果页总数等于各已安装工具条目数之和（同一资产在不同工具各存一份时分别计数）
- **And** 类别分布由同一批扫描数据聚合，不得前端另算一套口径

#### Scenario 2.3 扫描期间不伪造进度
- **Given** 盘点请求尚未返回
- **When** 盘点屏渲染
- **Then** 展示真实工具检测列表与「正在读取」状态，不显示未经返回的资产数字
- **And** 不得加入与真实请求无关的固定延时、假百分比或逐条动画

#### Scenario 2.4 单个工具读取失败
- **Given** 某工具目录存在但不可读
- **When** 盘点执行
- **Then** 该工具标记为读取失败并可继续其他工具
- **And** 整体流程不阻断，结果页注明该工具未纳入统计

#### Scenario 2.5 盘点到 0 个资产
- **Given** 本机没有任何可导入资产
- **When** 盘点完成
- **Then** 结果页显示「没有检测到可导入的资产」及可执行建议
- **And** 仍提供「跳过，直接进入资产库」，不得卡死或报错

#### Scenario 2.6 60 秒时间目标
- **Given** 常见环境：已安装工具不超过 6 个、可导入条目不超过 500 个、磁盘正常
- **When** 用户点击「开始盘点」
- **Then** 从点击到结果页首个真实数字可见不超过 60 秒（不计人工阅读）
- **And** 超时场景显示仍在读取的工具，而不是假装完成

### Requirement 3：结果页指出重复维护与版本不一致（真实数据）

#### Scenario 3.1 重复维护
- **Given** 同一类别、同一目标路径的资产同时出现在 ≥2 个工具中
- **When** 结果页渲染
- **Then** 该资产被列为「重复维护」，并写明出现在哪些工具
- **And** 副本数即涉及工具数，不得写死组数或副本数

#### Scenario 3.2 版本不一致
- **Given** 同一资产多个工具副本内容不完全相同
- **When** 结果页渲染
- **Then** 该项额外标记「内容不一致」，并给出不同版本的份数
- **And** 是否相同必须来自实际文件内容比对（哈希或字节比较），不得按文件大小猜

#### Scenario 3.3 覆盖不全
- **Given** 某资产只在一个或部分已安装工具中存在
- **When** 结果页渲染
- **Then** 以「只在 N 个工具中存在」陈述事实，并列出有/无该资产的工具
- **And** 不得使用「应该有」「缺失」等价值判断措辞

#### Scenario 3.4 没有重复时如实说没有
- **Given** 盘点结果中不存在跨工具重复
- **When** 结果页渲染
- **Then** 显示「未发现重复维护」，不展示空警示列表，不编造时间成本估算

### Requirement 4：收纳后资产出现在资产库

#### Scenario 4.1 骨架初始化不含空模板
- **Given** 用户处于首次环境并进入向导
- **When** 用户开始盘点或收纳
- **Then** Hub 被创建为骨架：目录、`hub.toml`、`README.md`
- **And** 不写入 `identity/profile.md` 等空模板，也不写 `mcp/mcp.sources.json`（该文件位于资产目录内会被计为资产，导致首跑判定失效；由 `assetplex init` 完整初始化或用户首次添加 MCP 时创建）
- **And** 重复进入向导时骨架初始化幂等，不覆盖已有文件

#### Scenario 4.2 全部收纳
- **Given** 盘点发现若干可导入条目
- **When** 用户点击「全部收进资产库」
- **Then** 条目写入 Hub，完成后显示「已入库 N 个资产」，N 取自资产库真实计数
- **And** 用户在资产库页面能检索到这些资产
- **And** 收纳不修改工具侧原文件

#### Scenario 4.3 同名冲突不静默覆盖
- **Given** 两个工具包含映射到同一 Hub 目标路径但内容不同的资产
- **When** 收纳执行
- **Then** 先处理的工具条目入库，后续同名条目记为「跳过」
- **And** 结果明确显示跳过数量与原因，后续可在导入向导逐条处理
- **And** 被跳过的工具侧原文件不得被删除或改动

#### Scenario 4.4 部分条目写入失败
- **Given** 个别条目因权限或文件损坏无法入库
- **When** 收纳执行
- **Then** 其余条目正常入库，结果如实显示失败数量
- **And** 用户可重试，已入库条目不重复计入

#### Scenario 4.5 收纳过程不伪造进度
- **Given** 收纳请求在途
- **When** 收纳屏渲染
- **Then** 显示「正在写入资产库」等真实 pending 状态
- **And** 不得用与请求无关的定时器制造百分比
- **And** 完成后展示真实的 created / skipped / errors 与资产库计数

#### Scenario 4.6 重复点击与刷新幂等
- **Given** 用户慢网重复点击「全部收进资产库」，或收纳中刷新页面
- **When** 请求完成或页面重新进入
- **Then** 同一 `hubTargetPath` 不出现重复条目
- **And** 已完成收纳的资产保持可用，未完成步骤可重新执行
- **And** 重复执行不得覆盖已入库内容（同名按 Scenario 4.3 跳过）

### Requirement 5：静态体检零 API Key 可完成，AI 诊断可选

#### Scenario 5.1 静态检查无需任何配置
- **Given** 用户从未配置过模型或 API Key
- **When** 用户进入体检屏
- **Then** 静态检查结果正常展示（健康分与待处理问题数）
- **And** 全程不发起模型请求，不需要网络
- **And** 用户可继续下一步或跳过

#### Scenario 5.2 静态问题来自真实数据
- **Given** Hub 中存在缺 description 的技能、重复规则等可判定问题
- **When** 体检屏渲染
- **Then** 问题数与摘要来自治理接口真实返回
- **And** 不得写死示例问题或数量；无问题时显示「未发现可判定的问题」

#### Scenario 5.3 AI 深度诊断可选
- **Given** 用户未配置模型
- **When** 体检屏渲染
- **Then** AI 区域标为「可选增强」，说明需要接入自己的模型，并提供「配置模型」入口
- **And** 不配置也能进入分发或跳过

#### Scenario 5.4 AI 诊断不阻塞主流程
- **Given** 用户已配置模型并发起 AI 诊断
- **When** 诊断进行中或失败
- **Then** 用户仍可随时停止、进入下一步或跳过
- **And** 诊断失败只提示原因，不阻断向导
- **And** API Key 只保存在本机 `~/.assetplex/ai-config.json`，请求直发用户填写的端点

#### Scenario 5.5 模型配置弹窗与预设
- **Given** 用户点击「配置模型并诊断」
- **When** 弹窗打开
- **Then** 提供接口地址、模型、API Key 三个字段，以及 DeepSeek / 豆包 / OpenAI / 本地 Ollama 预设
- **And** 预设只填充地址与模型名，不预置 Key；本地 Ollama 允许 Key 为空
- **And** 说明 Key 仅存本机、请求不经过 AssetPlex 服务器
- **And** 提供「跳过，直接分发」「进入资产库」「开始诊断」三个出口

### Requirement 6：分发前展示影响，取消零写入

#### Scenario 6.1 预览分类口径
- **Given** 用户已收纳资产并进入分发屏
- **When** 预览生成
- **Then** 每个已安装工具显示可接收条目数与勾选状态
- **And** 影响预览按以下口径显示数量与文件清单：
  - **新增**：目标文件不存在，将新建
  - **覆盖**：目标文件存在，且计划对非链接目标给出覆盖预警
  - **冲突**：覆盖项中，分发索引判定该资产在工具侧为 conflict（曾同步后偏离）
  - **无变化**：计划为 skip（已一致或源缺失），不计入前三类
- **And** 文件清单必须列出具体目标路径，不得只给汇总数字

#### Scenario 6.2 二次确认
- **Given** 影响预览已生成
- **When** 用户点击「分发到 N 个工具」
- **Then** 弹出确认弹窗，标题写明将覆盖的文件数，正文列出覆盖/冲突文件，并说明备份位置
- **And** 提供「取消」「确认分发」「先不分发，进资产库」三个出口
- **And** 未勾选工具或没有可分发内容时主按钮禁用并说明原因

#### Scenario 6.3 取消不产生任何写入
- **Given** 确认弹窗已打开
- **When** 用户点击「取消」、关闭弹窗或按 Esc
- **Then** 目标工具目录、Hub 资产文件、备份目录均无新增或修改
- **And** 不发起分发请求
- **And** 用户停留在分发屏，可重新调整目标

#### Scenario 6.4 确认后先备份再写入
- **Given** 用户确认分发，且存在覆盖/冲突文件
- **When** 写入执行
- **Then** 被覆盖的原文件先复制到 `<Hub>/.backups/onboarding/<批次>/`，并留可追溯清单
- **And** 完成后显示成功/失败工具数与条目数
- **And** 单个工具失败不影响其他工具完成，失败原因可见

#### Scenario 6.5 分发不改变资产库内容
- **Given** 分发执行完成
- **When** 用户进入资产库
- **Then** Hub 内资产文件内容与分发前一致
- **And** 只有工具侧目标文件被创建或更新

#### Scenario 6.6 没有可分发内容
- **Given** 所有已选目标都已一致，或本机没有已安装工具
- **When** 分发屏渲染
- **Then** 明确显示「没有需要分发的文件」或「未检测到已安装工具」
- **And** 主按钮禁用并说明原因，不弹确认、不发起写入
- **And** 仍可跳过进入资产库

### Requirement 7：任意步骤可跳过，完成/跳过都落标记

#### Scenario 7.1 跳过路径
- **Given** 用户处于开场、结果、收纳、体检或分发任一步
- **When** 用户点击「跳过，直接进入资产库」
- **Then** 直接进入资产库，不报错、不白屏
- **And** 已完成步骤产生的真实数据保留
- **And** 未执行的分发不产生任何写入

#### Scenario 7.2 跳过也写标记
- **Given** 用户从任一步骤跳过
- **When** 跳转完成
- **Then** 本机写入 onboarded 标记，记录结果为「跳过」及所在步骤
- **And** 下次打开 `/` 不再自动进入向导

#### Scenario 7.3 完成页
- **Given** 用户走完流程或中途跳过
- **When** 进入完成页
- **Then** 数字全部来自真实接口：入库资产数、分发结果、静态问题数
- **And** 未执行分发时不得显示「所有工具已同步」

#### Scenario 7.4 标记写入失败不阻断
- **Given** 标记文件因权限等原因写入失败
- **When** 用户完成或跳过
- **Then** 仍正常进入资产库，并提示「本次未记录完成状态」
- **And** 不得因标记失败回滚已完成的收纳或分发

#### Scenario 7.5 中途刷新可恢复
- **Given** 用户在收纳或体检步骤刷新页面
- **When** 页面重新加载
- **Then** 可从开场重新进入，并看到已入库的真实资产数
- **And** 不出现半渲染旧进度、不重复创建骨架、不自动分发
- **And** 直接跳过时，资产库包含此前已完成的收纳结果

#### Scenario 7.6 资产库空态可续接
- **Given** 用户从开场或 0 资产结果页跳过
- **When** 进入资产库
- **Then** 空态说明「还没有资产」，并提供「重新运行首次引导」与「手动导入」入口
- **And** 页面不报错、不显示加载失败

### Requirement 8：已完成过向导的用户不再自动进入

#### Scenario 8.1 标记生效
- **Given** `onboarding.json` 已记录 onboarded
- **When** 用户访问 `/`
- **Then** 正常显示首页，不跳转向导
- **And** 直接访问 `/onboarding` 仍可查看

#### Scenario 8.2 老用户不被打扰
- **Given** 资产库已有资产、但没有 onboarded 标记（历史版本升级）
- **When** 用户访问 `/`
- **Then** 正常显示首页，不自动进入向导
- **And** 不为了消除提示而擅自写入标记

#### Scenario 8.3 手动重新运行
- **Given** 用户已完成过向导
- **When** 用户在设置页点击「重新运行首次引导」
- **Then** 允许进入向导重看流程
- **And** 收纳与分发仍遵循「取消零写入、覆盖先备份」规则

#### Scenario 8.4 标记损坏按未完成处理但不打扰
- **Given** `onboarding.json` 内容损坏或版本未知
- **When** 服务读取状态
- **Then** 不抛错、不崩溃，按「未记录完成」处理
- **And** 若资产库已有资产，仍不自动进入向导
- **And** 用户可在设置页手动重新运行并覆盖写入合法标记

### Requirement 9：隔离环境与数据安全

#### Scenario 9.1 ASSETPLEX_DIR 生效
- **Given** 用户将 `ASSETPLEX_DIR` 指向临时目录
- **When** 执行盘点、收纳、体检、分发
- **Then** 所有 Hub 读写只发生在该目录内
- **And** 不读写真实 `~/.assetplex` 下的任何文件

#### Scenario 9.2 零上传
- **Given** 用户未配置模型
- **When** 用户走完整个向导
- **Then** 全程不产生外部网络请求（扫描、收纳、静态体检、分发均为本地文件操作）
- **And** 只有用户主动配置并运行 AI 诊断时，资产内容才发往用户填写的端点

#### Scenario 9.3 CLI 盘点式初始化
- **Given** 本机已有工具配置，用户执行 `assetplex init --import-existing`
- **When** 命令执行
- **Then** 真实扫描并导入可收纳条目，输出新建/跳过/失败的真实计数
- **And** 同名冲突按 Scenario 4.3 跳过，不覆盖已有内容
- **And** 不写 onboarded 标记（用户已通过 CLI 完成，Web 不再自动弹出）
