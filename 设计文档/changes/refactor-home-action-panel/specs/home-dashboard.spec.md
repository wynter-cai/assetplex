# specs/home-dashboard.spec.md：老用户日常首页（总览）

> 适用屏幕：`/`（总览）一期形态。
> 本规格只描述用户可见行为与数据口径，不规定实现细节；接口复用与新增见 `api-contract.ts`。
> 全局约束：全程本地只读；主页不因打开而触发模型调用；任何数字必须可回溯到真值来源。

## 定义

- **行动面板**：首页主区是「需要我动手的事」，不是资产清单或宣传区。指标只放「需要行动的数字」。
- **状态条**：顶部一行的四个数字（健康分 / 待治理 / 未同步 / 上次备份），是状态不是卡片，不加营销文案。
- **待治理**：跨四个健康维度收集到的全部问题，**按「资产 + 检查项」去重后**的条目数。完整性维度的问题同时出现在规范性维度里时只算一条。
- **未同步**：分发一致性问题数，按「资产 × 工具」计（与健康分「分发一致性」维度的问题数同口径），文案写作「N 处未同步」。
- **今日待办**：按严重度排序后的待治理条目，首屏展示前 5 条。
- **最近同步**：活动日志中该工具最近一次同步记录的时间；没有记录就是「尚无同步记录」，不用健康分时间或备份时间冒充。
- **上次备份**：三个本地备份根目录中最新的那次备份时间。
- **数据不可用**：对应数据源读取失败或该维度不适用。界面必须显示「暂不可用」，不得显示 0、不得显示「全部健康」。

## 屏幕与模块对照

| 模块 | 出现条件 | 必须出现的元素 | 主要出口 |
|---|---|---|---|
| 状态条 | 库已初始化 | 健康分（含等级）/ 待治理 / 未同步 / 上次备份 | 健康分、待治理 → `/governance`；未同步 → `/sync`；上次备份不可点 |
| 今日待办 | 库已初始化（含 0 条） | 每行：严重度 + 问题标题 + 资产名 + 「查看」；可修复项额外「去资产库修改」；底部「查看全部 N 项」 | 单条 → 就地体检报告；「查看全部」→ `/governance` |
| 工具与同步 | 检测到至少一个受支持工具 | 每行：工具名 + 状态 + 最近同步时间；底部「添加工具」 | 行 → `/connections?tool=<toolId>`；「添加工具」→ `/connections` |
| 最近变化 | 库已初始化 | 最近 5 条活动（时间 + 类型 + 摘要）+「查看全部」 | `/activities` |
| 库为空态 | 库内 0 个可评估资产 | 「从已安装工具收藏第一批资产」「运行首次引导」两个出口，不显示待办队列与 0 分 | `/import`、`/onboarding` |
| 全部健康态 | 待治理为 0 且数据可用且非空库 | 「全部健康」+ 最近一次体检时间 + 「重新体检」，不制造虚假待办 | `/governance` |
| 数据不可用态 | 单块数据源失败 | 该块显示「暂不可用」+ 重试；其他块正常渲染 | 块内重试 |

## ADDED Requirements

### Requirement 1：顶部状态条呈现四个可下钻的数字

#### Scenario 1.1 常态四个数字
- **Given** 库内已有资产，健康分已算出，待办与分发数据均可读，本机有备份记录
- **When** 用户打开 `/`
- **Then** 顶部一行显示四个数字：健康分（含等级文案）、待治理条数、未同步处数、上次备份时间
- **And** 数字为一行状态条，不是四张卡片，也不出现资产总数
- **And** 不显示营销文案、欢迎语或资产类别九宫格

#### Scenario 1.2 下钻
- **Given** 状态条显示「健康分 78 / 待治理 12 / 未同步 3」
- **When** 用户点击「健康分」或「待治理」
- **Then** 跳转到 `/governance`
- **When** 用户点击「未同步」
- **Then** 跳转到 `/sync`
- **And** 「上次备份」为只读文本，不可点击，也不渲染成链接样式

#### Scenario 1.3 库为空
- **Given** 库内没有任何可评估资产
- **When** 用户打开 `/`
- **Then** 健康分位置显示「待盘点」，不显示 0 分
- **And** 待治理与未同步不显示 0，主区切换为库为空态（见 Requirement 3）

#### Scenario 1.4 单个数字不可用
- **Given** 分发索引读取失败，健康分与待办正常
- **When** 用户打开 `/`
- **Then** 「未同步」显示「暂不可用」，不是 0，也不是「已全部同步」
- **And** 其余三个数字正常显示
- **And** 顶部不出现整页错误

### Requirement 2：今日待办队列按严重度排序，可逐条查看

#### Scenario 2.1 排序
- **Given** 待治理条目包含高/中/低三种严重度
- **When** 待办队列渲染
- **Then** 高危在最上，其次中危，最后低危；同严重度按资产名排序
- **And** 首屏展示前 5 条，底部显示「查看全部 N 项」，N 为去重后的待治理总数
- **And** N 与状态条「待治理」数字一致

#### Scenario 2.2 每一行的信息
- **Given** 某条目是关于人设缺少边界的高危问题
- **When** 该行渲染
- **Then** 显示：严重度标签、问题标题、资产名、「查看」
- **And** 该条目可生成修复草案时，额外显示「去资产库修改」
- **And** 不显示「忽略」「稍后」「一键修复」——这些属于治理中心（B12）

#### Scenario 2.3 就地查看
- **Given** 用户点击某条待办的「查看」
- **When** 详情展开
- **Then** 就地展开该资产的体检报告（问题清单 + 建议），不离开首页
- **And** 报告只读，展开动作本身不修改任何资产库文件
- **And** 未配置模型时，报告只含机械检查项并提示「语义检查需配置模型」

#### Scenario 2.4 去修复
- **Given** 某条目可生成修复草案
- **When** 用户点击「去资产库修改」
- **Then** 跳转到该资产所属类别页（如 `/vault/rule`）
- **And** 类别无法映射时跳转 `/vault`，不报错

#### Scenario 2.5 去重口径
- **Given** 某资产同时命中「完整性」与「规范性」维度中的同一条检查项
- **When** 待办与「待治理」计数渲染
- **Then** 该检查项只出现一次、只计一条
- **And** 界面不把四个维度的 issueCount 相加作为待治理数

#### Scenario 2.6 键盘操作
- **Given** 焦点已进入待办队列
- **When** 用户按上下方向键（或 J/K）
- **Then** 焦点在条目间移动，当前条目有可见焦点环
- **When** 用户按 Enter
- **Then** 打开该条目的体检报告
- **When** 用户按 Esc
- **Then** 关闭报告并把焦点还给触发它的条目

### Requirement 3：空态诚实——全部健康、库为空、数据不可用互不混淆

#### Scenario 3.1 全部健康
- **Given** 库内有资产，待办 0 条且数据可用
- **When** 首页渲染
- **Then** 待办区显示「全部健康」，并显示最近一次体检时间
- **And** 提供「重新体检」（显式触发重算），不在打开页面时自动重算
- **And** 状态条健康分区呈正向状态，不放红色告警

#### Scenario 3.2 库为空
- **Given** 库内 0 个可评估资产
- **When** 首页渲染
- **Then** 主区显示「从已安装工具收藏第一批资产」与「运行首次引导」两个出口
- **And** 不显示「全部健康」，也不显示待办为 0 的成功态
- **And** 工具与同步矩阵若已有工具检测结果，仍正常显示（工具状态与库是否为空无关）

#### Scenario 3.3 待办不可用
- **Given** 资产快照读取失败（待办无法计算）
- **When** 首页渲染
- **Then** 待办区显示「暂不可用」与原因提示、重试按钮
- **And** 不得显示「全部健康」
- **And** 「待治理」状态数字同样显示「暂不可用」

#### Scenario 3.4 混合状态
- **Given** 健康分可用、待办不可用、工具矩阵可用
- **When** 首页渲染
- **Then** 三块各自呈现自己的状态，页面不整体失败、不回退成全屏错误页

---

### Requirement 4：工具与同步矩阵显示真实状态与最近同步时间

#### Scenario 4.1 状态取值
- **Given** 本机检测到多个受支持工具，状态各不相同
- **When** 工具与同步矩阵渲染
- **Then** 每个工具显示其一：已同步（正向标记）、有漂移（并显示「N 处」）、未连接、未安装
- **And** 未安装工具置灰，标注「未安装」，不显示「0 处漂移」冒充已检测
- **And** 状态来自真实检测与分发索引，不按「已安装即已同步」推定

#### Scenario 4.2 最近同步时间
- **Given** 某工具在活动日志中有同步记录
- **When** 矩阵渲染
- **Then** 该行显示最近一次同步到该工具的时间
- **Given** 某工具从未同步过
- **Then** 该行显示「尚无同步记录」，不显示健康分时间、备份时间或「刚刚」

#### Scenario 4.3 下钻
- **Given** 某工具状态为「有漂移」
- **When** 用户点击该行
- **Then** 跳转到该工具的连接详情（`/connections?tool=<toolId>`），可看到待同步内容
- **And** 未安装工具不可点击，也不渲染成链接

#### Scenario 4.4 添加工具
- **Given** 用户需要接入新工具
- **When** 点击矩阵底部「添加工具」
- **Then** 跳转到 `/connections`
- **And** 一期不提供新建工具的弹窗或向导

#### Scenario 4.5 部分工具读取失败
- **Given** 分发索引中至少一个工具判定失败
- **When** 矩阵渲染
- **Then** 失败工具显示「状态暂不可用」，其余工具正常显示
- **And** 页面顶部不出现「部分工具状态暂不可用」之外的误导性总结

#### Scenario 4.6 一个工具都没检测到
- **Given** 本机没有受支持工具
- **When** 矩阵渲染
- **Then** 显示「未检测到已安装工具」与「去连接工具」出口
- **And** 状态条「未同步」显示「暂不可用」，不显示 0

---

### Requirement 5：最近变化只显示 5 条

#### Scenario 5.1 有记录
- **Given** 活动日志存在多条记录
- **When** 首页最近变化区渲染
- **Then** 只显示最近 5 条，时间倒序，每条含时间、类型与摘要
- **And** 提供「查看全部」，跳转 `/activities`

#### Scenario 5.2 超过 5 条不吞主区
- **Given** 活动日志有 100 条记录
- **When** 首页渲染
- **Then** 最近变化区仍是 5 条，不出现滚动嵌套或「加载更多」
- **And** 主区高度不被活动流挤占

#### Scenario 5.3 无记录
- **Given** 活动日志为空
- **When** 首页最近变化区渲染
- **Then** 显示「还没有操作记录」，并保留「查看全部」入口（不产生死链）

---

### Requirement 6：诚实数据口径（不可伪造）

#### Scenario 6.1 不伪造 0
- **Given** 任一数据源读取失败
- **When** 首页渲染
- **Then** 对应数字/区块显示「暂不可用」，不显示 0 或「暂无问题」

#### Scenario 6.2 不伪造健康
- **Given** 健康分从未算过（库内无资产或从未触发体检）
- **When** 首页渲染
- **Then** 不显示任何默认分（如 60、100），显示「待盘点」或「暂不可用」

#### Scenario 6.3 不伪造同步
- **Given** 某工具未同步过
- **When** 矩阵渲染
- **Then** 不显示「已同步」，显示「尚无同步记录」或真实检测状态

#### Scenario 6.4 打开首页零模型调用
- **Given** 用户已配置模型且资产存在语义类问题
- **When** 用户打开 `/`
- **Then** 首页只读取缓存中的语义结论，不发起新的模型请求
- **And** 只有用户显式点击「查看」「重新体检」时才可能触发新的诊断/重算

---

### Requirement 7：加载、失败与刷新

#### Scenario 7.1 首次加载
- **Given** 用户刚打开首页，聚合数据返回中
- **When** 页面渲染
- **Then** 状态条、待办、矩阵、最近变化各自显示骨架占位
- **And** 不显示未经返回的 0、假分数或示例待办

#### Scenario 7.2 接口整体失败
- **Given** 后端服务不可达
- **When** 首页加载失败
- **Then** 显示「无法连接到 AssetPlex 服务」与「重试」
- **And** 不白屏、不跳转空页面

#### Scenario 7.3 重试幂等
- **Given** 首次加载失败
- **When** 用户点击「重试」并成功
- **Then** 页面按真实数据完整渲染
- **And** 重试不产生任何写操作

#### Scenario 7.4 刷新健康分
- **Given** 用户点击「重新体检」
- **When** 重算完成
- **Then** 健康分、待治理数、待办队列、未同步数一起更新为同一次快照的结果
- **And** 刷新失败时保留旧数据可见，并提示刷新失败，不清空为 0

---

### Requirement 8：响应式与可访问

#### Scenario 8.1 宽屏布局
- **Given** 视口 ≥1024px
- **When** 首页渲染
- **Then** 待办队列为主区（较宽），工具与同步矩阵在右侧栏位，最近变化在下方整行
- **And** 状态条四个数字同一行

#### Scenario 8.2 窄屏布局
- **Given** 视口 <1024px
- **When** 首页渲染
- **Then** 单列依次为：状态条 → 今日待办 → 工具与同步 → 最近变化
- **And** 状态条数字折行后仍可读，不出现横向滚动

#### Scenario 8.3 语义与焦点
- **Given** 屏幕阅读器用户浏览首页
- **When** 焦点依次移动
- **Then** 四个区块各有可读的区块名（状态条、今日待办、工具与同步、最近变化）
- **And** 状态条数字的下钻是链接语义，工具行可点击项是链接语义，不出现 `div` 假按钮

## MODIFIED Requirements

### Requirement 9：首页不再是「资产快照 + 快捷动作」型页面（取代 add-vault-connections-ui R1/R3）

`add-vault-connections-ui/specs/home-page.spec.md` 中「资产快照」「快速动作」两项不再适用于老用户日常首页：

- 资产类别与总数只在资产库展示；首页不出现类别卡片墙。
- 快捷动作九宫格取消；导入入口由库为空态与资产库页头承接。

#### Scenario 9.1 老用户首页不出现资产快照
- **Given** 库内有身份/技能/规则等多类资产
- **When** 用户打开 `/`
- **Then** 首页不显示各类资产数量卡片，也不显示「我的库 N 项」汇总
- **And** 用户仍可在资产库看到这些数字

#### Scenario 9.2 导入入口仍可达
- **Given** 用户想把工具里的资产收进库
- **When** 用户打开 `/vault` 或首页库为空态
- **Then** 都能找到「收藏/导入资产」入口并跳转 `/import`

### Requirement 10：最近活动区改为「最近变化」并常驻「查看全部」（取代 add-vault-connections-ui R4）

#### Scenario 10.1 旧断言失效
- **Given** 旧形态要求首页活动区不提供「查看全部」（活动页当时未实现）
- **When** 首页最近变化区渲染
- **Then** 必须提供「查看全部」并跳转 `/activities`
- **And** 行数固定 5 条（见 Requirement 5）
