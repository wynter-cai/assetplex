# specs/navigation.spec.md：导航信息架构（refactor-home-action-panel）

> 适用区域：桌面常驻侧栏、窄屏抽屉、窄屏顶部当前页摘要。
> 本规格取代 `changes/simplify-navigation-ia/specs/navigation-ia.spec.md`（其「5 项主导航 + 更多折叠」方案不再执行）。
> 原则：只重组入口，不删路由、不改页面内部；旧 URL 一律可达。

## 定义

- **导航组**：一个一级入口 + 其下若干子项。组内只有 1 个目标时，该组渲染为直接链接；组内有 ≥2 个目标时，渲染为「组按钮 + 子项列表」。
- **命中**：当前地址以组内某个目标路径开头（`/` 只精确匹配 `/`），或当前地址属于该组的旧 URL 映射范围。
- **自动展开**：当组被命中时，其子项列表自动可见，无需用户先点开。
- **徽标**：组按钮上的数字提示，只用于「需要行动的数量」。

## 区域对照

| 区域 | 出现条件 | 必须出现的元素 | 主要出口 |
|---|---|---|---|
| 桌面侧栏（≥1024px） | 任意页面 | 五个导航组 + 底部（新手引导 / 设置 / 版本号） | 各组目标页 |
| 窄屏抽屉（<1024px） | 点击汉堡 | 与桌面完全相同的五个组、子项与徽标 | 选择后跳转并关闭抽屉 |
| 窄屏顶部摘要 | <1024px | 当前所属组或页面名称 | 无（只读摘要） |
| 组子项列表 | 组被命中或用户展开 | 该组全部子项，当前目标高亮 | 子项对应页面 |

## 新信息架构

```
总览              /
资产库            /vault（+ 动态类别子项）
  └ 发现外部技能   /discover
治理              /governance（体检与待办）
  └ 重复项        /duplicates
连接与同步        /connections（工具连接）
  └ 分发与漂移    /sync
  └ 切换工具      /swap
  └ 项目工作区    /projects
活动              /activities
设置              /settings（固定在侧栏底部，与新手引导、版本号同区）
```

归类依据：
- 「一个任务只出现在一个主入口」，跨入口用深链，不复制功能。
- 治理相关（体检、待办、重复项）归一组；连接、分发、切换、项目归一组，因为它们共同服务于「把资产送到工具里」。
- 活动保留一级：用户常看「我改的东西同步出去了吗」。
- 「更多」折叠层取消：分组本身即渐进披露单位。

## ADDED Requirements

### Requirement 1：侧栏只呈现五个导航组 + 设置

#### Scenario 1.1 桌面侧栏结构
- **Given** 用户以 ≥1024px 视口打开任意页面
- **When** 侧栏渲染
- **Then** 从上到下依次呈现：总览、资产库、治理、连接与同步、活动
- **And** 底部固定区呈现：新手引导入口、设置、版本号
- **And** 不存在「更多」折叠分组，也不存在第十个平铺入口

#### Scenario 1.2 单链接组与多链接组
- **Given** 侧栏已渲染
- **When** 用户查看「总览」与「活动」
- **Then** 它们是直接链接（点击即跳转，无展开箭头）
- **And** 「资产库」「治理」「连接与同步」是组按钮，带展开箭头与 `aria-expanded`

#### Scenario 1.3 子项内容
- **Given** 后端资产类别声明存在
- **When** 展开任一组
- **Then** 「资产库」子项为该类别清单（动态来自类别接口，不写死四个）+「发现外部技能」
- **And** 「治理」子项为「体检与待办」「重复项」
- **And** 「连接与同步」子项为「工具连接」「分发与漂移」「切换工具」「项目工作区」

#### Scenario 1.4 类别动态扩展
- **Given** 后端新增一个资产类别
- **When** 侧栏渲染
- **Then** 新类别自动出现在「资产库」子项中，顺序与接口声明一致
- **And** 前端不回退到写死的类别清单

### Requirement 2：当前路由高亮，并自动展开命中的组

#### Scenario 2.1 深链直达
- **Given** 用户直接在地址栏输入 `/swap`
- **When** 页面加载完成
- **Then** 「连接与同步」组自动展开
- **And** 「切换工具」以选中态高亮
- **And** 用户无需手动展开即可知道自己在哪

#### Scenario 2.2 资产类别的嵌套高亮
- **Given** 用户访问 `/vault/rule`
- **When** 侧栏渲染
- **Then** 「资产库」组展开且组按钮呈命中态
- **And** 「规则」子项高亮
- **And** 「总览」不被误高亮（`/` 只精确匹配）

#### Scenario 2.3 手动折叠不丢位置
- **Given** 当前页为 `/duplicates`，治理组已自动展开
- **When** 用户手动点击组按钮收起治理组
- **Then** 子项隐藏，但组按钮保留命中态提示（如左侧标记或加粗）
- **And** 用户当前所在页面不跳转、不卸载
- **When** 用户随后访问 `/sync`
- **Then** 治理组保持用户手动收起的状态，「连接与同步」组因命中而自动展开

#### Scenario 2.4 路由变化时重新展开
- **Given** 用户手动收起了「连接与同步」组
- **When** 用户通过任意入口再次进入 `/sync`
- **Then** 该组重新自动展开，并高亮「分发与漂移」

### Requirement 3：治理组显示待治理徽标

#### Scenario 3.1 有数字
- **Given** 待治理数为 12，且首页数据已加载
- **When** 侧栏渲染
- **Then** 「治理」组按钮右侧显示徽标「12」
- **And** 该数字与首页状态条「待治理」完全一致（同一份数据）

#### Scenario 3.2 零或不可用
- **Given** 待治理为 0，或该数据尚未加载、读取失败
- **When** 侧栏渲染
- **Then** 不显示徽标
- **And** 不显示「0」，也不为了显示徽标而单独阻塞页面加载或额外轮询

#### Scenario 3.3 其他页面不额外请求
- **Given** 用户停留在 `/settings` 且从未打开过首页
- **When** 侧栏渲染
- **Then** 徽标可以不显示，页面其他功能不受影响
- **And** 侧栏不得为徽标引入独立轮询或高频请求

### Requirement 4：旧 URL 全部兼容，重复入口重定向

#### Scenario 4.1 保留原路径
- **Given** 用户收藏了下列任一地址：`/`、`/vault`、`/vault/<类别>`、`/connections`、`/sync`、`/swap`、`/projects`、`/duplicates`、`/activities`、`/discover`、`/import`、`/settings`、`/onboarding`、`/governance`
- **When** 直接访问
- **Then** 页面正常渲染，不 404、不白屏
- **And** 页面内容与改造前一致（除首页与新增的 `/governance`）

#### Scenario 4.2 重复入口重定向
- **Given** 下列旧地址来自早期版本，功能已被资产库或连接页取代
- **When** 用户访问该地址
- **Then** 按映射跳转，页面正常渲染：

| 旧地址 | 跳转到 |
|---|---|
| `/identity` | `/vault/identity` |
| `/rules` | `/vault/rule` |
| `/skills` | `/vault/skill` |
| `/mcp` | `/vault/mcp` |
| `/tools` | `/connections` |
| `/legacy/dashboard` | `/` |

- **And** 使用替换式跳转，不新增历史记录（用户按返回不会立刻被弹回旧地址）

#### Scenario 4.3 未知地址
- **Given** 用户访问不存在的路径
- **When** 页面加载
- **Then** 仍按现状落到 `/`，不出现空白页

#### Scenario 4.4 降级入口不死
- **Given** 「发现外部技能」「重复项」「项目工作区」都不再是平铺一级入口
- **When** 用户寻找这些功能
- **Then** 都能在对应组内找到入口
- **And** 首页最近变化、状态条提供到 `/activities`、`/governance`、`/sync` 的直达路径

### Requirement 5：窄屏抽屉与桌面侧栏结构一致

#### Scenario 5.1 抽屉内同一结构
- **Given** 视口宽度 800px
- **When** 用户点开汉堡抽屉
- **Then** 抽屉内呈现与桌面完全相同的五个组、子项与徽标
- **And** 不出现额外的层级或移动端专属折叠规则

#### Scenario 5.2 选择后关闭并归还焦点
- **Given** 抽屉已打开
- **When** 用户点击「项目工作区」
- **Then** 跳转 `/projects`，抽屉关闭
- **And** 焦点归还给汉堡按钮
- **And** 命中组在下一次打开抽屉时仍自动展开

#### Scenario 5.3 顶部当前页摘要
- **Given** 用户处于 `/sync`
- **When** 窄屏顶部条渲染
- **Then** 摘要文案为所属组或该页名称（如「连接与同步」），不显示为「总览」
- **And** 处于 `/` 时摘要为「总览」

---

### Requirement 6：键盘与语义正确

#### Scenario 6.1 组按钮可键盘操作
- **Given** 用户用 Tab 在侧栏内移动
- **When** 焦点落在组按钮上
- **Then** Enter / Space 可展开或收起该组
- **And** 组按钮带 `aria-expanded`，并指向其子项列表（`aria-controls`）
- **And** 不存在 `<a>` 内嵌 `<button>` 的非法结构

#### Scenario 6.2 地标可读
- **Given** 屏幕阅读器用户浏览侧栏
- **When** 焦点进入各区域
- **Then** 侧边栏、主导航、资产类别（或当前组子列表）均有可读名称
- **And** 徽标数字带有可读说明（如「12 项待治理」），不只有视觉数字

---

### Requirement 7：「治理」一期落地页边界

#### Scenario 7.1 一期内容
- **Given** 用户点击侧栏「治理 → 体检与待办」
- **When** `/governance` 渲染
- **Then** 显示健康分（含四维）与四维问题清单，点条目可展开该资产的体检报告
- **And** 页面明确标注「治理中心建设中」，说明当前为体检与待办视图
- **And** 不提供筛选、排序切换、批量应用、忽略、稍后、一键修复

#### Scenario 7.2 与治理中心的边界
- **Given** 后续治理中心（B12）落地
- **When** 用户访问 `/governance`
- **Then** URL 不变，仅页面内容被替换
- **And** 一期的只读视图不再保留为第二套治理入口

#### Scenario 7.3 与首页一致
- **Given** 首页状态条显示「待治理 12」
- **When** 用户进入 `/governance`
- **Then** 页面呈现的问题集合与首页待办同源（同一次快照口径）
- **And** 不出现「首页说 12、治理页说 15」的自相矛盾
