# Proposal：老用户日常首页重设计（refactor-home-action-panel）

> 级别：S（新页面形态 + 导航信息架构重组）· 日期：2026-11-15 · 状态：待审核
> 来源：`设计文档/assetplex-home-and-governance-proposal.md`（P2-3 首页大改）第 1、3、4、6.2、7、8、10 节
> 合并对象：`设计文档/changes/simplify-navigation-ia/`（导航收敛提案，本变更取代其导航方案）
> 一期边界：只做 Phase 0 —— 主页**只读**展示现有 health / issues / activity / connections 数据；**治理中心是另一件事（B12）**，另立变更

## Goal

老用户每天打开 AssetPlex，3 秒内回答三个问题：

1. 哪里不一致、有风险？
2. 我今天该改哪一条？
3. 改完有没有同步到各工具？

因此首页从「信息展示页」改为「行动面板」：顶部一条状态条（四个可行动数字）+ 今日待办队列（按严重度排序）+ 工具与同步矩阵 + 最近变化 5 条。导航同时从「按功能平铺 10 项」收敛为「按任务分组 5 组 + 设置」。

**验收标准**

- 打开 `/` 后，首屏可见「今天要处理什么」：待办队列与状态条同屏，不需要滚动穿过欢迎区或卡片墙。
- 任意一个数字都能回到它的真值来源；数据缺失时显示「暂不可用」，不出现伪造的 0 分或虚假「全部健康」。
- 改造后所有既有 URL 仍可直达（不 404、不白屏），老用户书签不失效。

## Scope

### 做（Phase 0）

- **主页布局重写**：状态条 → 今日待办 → 工具与同步矩阵 → 最近变化（默认 5 条）。
- **状态条四个数字**：健康分、待治理、未同步、上次备份；每个数字可下钻到对应视图（上次备份除外，见「风险与开放问题」）。
- **今日待办队列**：跨维度合并去重、按严重度排序；单条可查看体检报告；可修复项给「去资产库修改」出口。
- **工具与同步矩阵**：工具名 + 状态 + 最近同步时间；漂移工具可点进连接详情。
- **最近变化**：固定 5 条，带「查看全部」到 `/activities`。
- **诚实空态**：库为空、全部健康、单块数据不可用三种状态分别定义。
- **导航五组**：总览 / 资产库 / 治理 / 连接与同步 / 活动 + 设置；当前路由高亮与自动展开；旧 URL 兼容与重定向。
- **治理入口临时形态**：新增 `/governance` 作为「治理」的落地页，一期只复用现有体检能力（健康分 + 四维问题清单 + 单资产体检报告），**不做**筛选、批量、应用修复。

### 不做（明确排除）

- ❌ 治理中心（B12）：三种视图、按资产类型 tab、证据与建议 diff、应用/撤销/忽略/稍后、AI 判定标注 —— 全部不在本变更。
- ❌ 任何写操作：本变更新增接口全部只读；不新增「应用修复」按钮，不新增忽略/稍后状态持久化。
- ❌ 空态之外的引导流程改动：首跑向导（add-zero-config-onboarding）不动。
- ❌ 命令面板 ⌘K、全局「+」新建按钮（后续独立变更）。
- ❌ 首页「资产总数」大数字与快捷操作九宫格：数字留在资产库，首页只放需要行动的数字。
- ❌ Sync / Connections / Swap 页面合并、页面内部布局与文案改动。
- ❌ 移动端只剩「待办/资产/同步」三件事的精简形态（backlog P2-4）。
- ❌ 删除任何路由；不删功能，只重组入口。

## 与 simplify-navigation-ia 的关系

`simplify-navigation-ia` 已有一版导航提案（5 项主导航 + 默认收起的「更多」分组）。本变更**取代其导航方案**，理由与保留项如下：

| 维度 | simplify-navigation-ia | 本变更（取代） |
|---|---|---|
| 分组依据 | 按使用频率，把低频项塞进「更多」 | 按任务分组：治理与连接同步各自成组，活动回到一级 |
| 治理入口 | 无（体检能力仍埋在首页卡里） | 独立「治理」组，一期落 `/governance`，B12 落地后替换内容不改 URL |
| 活动 | 降级进「更多」 | 保留一级组（日常要回看「我改的东西同步出去了吗」） |
| 「更多」折叠 | 保留 | 取消：分组本身就是渐进披露单位，再套一层「更多」等于两级折叠 |
| 共同约束 | 不删路由、URL 兼容、抽屉共用同一 Sidebar、降级项必须有二级入口 | **全部继承** |

落地方式：`simplify-navigation-ia` 目录保留作为历史输入，其 `specs/navigation-ia.spec.md` 与 `tasks.md` 标记为 **superseded**，不再执行；导航以本变更 `specs/navigation.spec.md` 为唯一规格来源。若其 tasks 中已完成的单项（如首页「查看全部」补链）与本变更不冲突，可保留。

## 数据真值（复用 vs 新增）

一期只读展示，绝大部分数据已经存在：

| 主页元素 | 真值来源 | 状态 |
|---|---|---|
| 健康分 / 体检时间 | `GET /api/governance/health`（四维规则打分，30s 缓存） | ✅ 直接复用 |
| 待治理（去重总数）+ 今日待办条目 | 同一次治理快照的跨维度问题集合 | ⚠️ 需新增聚合（维度接口按维度返回，跨维度会重复计数：规范性维度已包含完整性维度的机械项） |
| 未同步 | 分发维度问题数（资产×工具，来自分发索引） | ⚠️ 需在新聚合接口中一并返回，禁止前端就地统计 |
| 工具状态（已同步/漂移/未连接/未安装） | 适配器 detect + `hub.toml` 启用状态 + `GET /api/distributions`（30s 缓存） | ⚠️ 需后端聚合 |
| 最近同步时间 | 活动日志中 `type=sync` 且 `targets` 含该工具的最近记录 | ⚠️ 需后端取最近一条；无记录时返回 null，不猜 |
| 上次备份 | 三个本地备份根目录（`.doctor-backup/`、`.swap-backup/`、`.backups/onboarding/`）中最新的备份时间 | ⚠️ 需新增只读探测 |
| 最近变化 5 条 | `GET /api/activity?limit=5`（活动日志） | ✅ 直接复用 |
| 单条待办「查看」 | `GET /api/doctor/diagnose`（只读、可选 AI） | ✅ 直接复用 |
| 工具行下钻 | `/connections?tool=<toolId>`（已支持 tool 参数） | ✅ 直接复用 |

结论：新增**一个**只读聚合接口 `GET /api/home/dashboard`，避免首页为拼一个数字而发 5 个请求、也避免前端各算一套口径；其余能力全部复用。契约见 `api-contract.ts`。

## Risks

| 风险 | 影响 | 对策 |
|---|---|---|
| 治理快照要遍历全部资产，侧栏徽标 + 首页同时拉取会变慢 | 首页 3 秒目标落空 | 复用同一个 30s 缓存与同一 query key（`home-dashboard`）；不做轮询；侧栏徽标只读缓存，未加载就不显示徽标 |
| 「待治理」与四维 issueCount 口径不一致（规范性 ⊃ 完整性） | 用户看到「完整性 3 + 规范性 5」却显示待治理 6，怀疑数字造假 | 去重规则写进 spec 与 api-contract；界面不把维度数相加；标注「待治理按问题去重计数」 |
| 「未同步」按资产×工具计，用户以为是资产数 | 数字偏大 | 文案写清「N 处未同步」而非「N 个资产」；工具矩阵给每工具明细 |
| 主页删除资产快照 / 快捷动作，老用户少入口 | 抱怨功能消失 | 资产库页头保留「导入」「发现外部技能」；状态条与矩阵承接同步相关入口；release notes 说明 |
| 导航重组让老用户迷路 | 找不到原来的页面 | 旧 URL 全部保留或重定向（见 navigation spec 对照表）；只重组入口，不删页面 |
| `/governance` 临时容器与 B12 治理中心边界模糊 | 二期返工或范围蔓延 | URL 与组件边界在本变更写死：一期只复用现有体检能力，不新增任何诊断/修复逻辑；B12 只替换容器内容 |
| 备份根目录条目过多 | 首页首屏慢 | 只读目录名与单个元数据文件，不递归、不读正文；只取最大值 |

## 已拍板（2026-11-15 维护者确认）

| 问题 | 决定 | 说明 |
|---|---|---|
| 「治理」一期落地形态 | **先用现有体检能力，落地后替换** | 当前产品没有独立体检页，体检能力嵌在首页（`HealthHero` + `HealthIssuesPanel`）。本变更把这份现有视图抽到 `/governance` 路由作为临时容器，**不新增任何诊断/筛选/修复逻辑**；B12 治理中心落地时只替换该页内容，不改 URL、不加第二套入口。 |
| 「未同步」口径 | **未同步条目数（资产×工具）** | 与分发维度问题数同口径，与待办队列同源；文案写「N 处未同步」，不写成「N 个资产」。 |
| 「上次备份」出口 | **本期只读、不可点** | 不补备份页；后续备份变更再给出口。数字只读探测三个备份根目录，取最新时间。 |
