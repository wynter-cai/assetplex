# activity-feed.spec.md：操作事件日志与活动时间线

> capability: 操作留痕、首页最近活动、活动页时间线、保留期
> 变更: add-activity-log | 决策依据: proposal.md D1-D6
> 入口: 首页「最近活动」卡片、侧栏「活动」

## 定义

- **活动条目**：一次已完成写操作留下的记录，含 `id / at / type / actor / summary / targets? / counts? / paths?`。
- **类型闭集**：`import`（收藏/导入）、`sync`（分发同步）、`edit`（编辑/治理批次）、`create`（新建）。
- **写入点**：同步完成、导入完成（正向/反向）、Hub 写库（新建/编辑/删除）、治理批次（整改、重复合并的 apply/undo）。

## Scenario 1：同步完成后留痕

- **Given** 用户对已启用工具执行一次真实同步（非 dryRun）
- **When** 同步返回成功
- **Then** 事件日志新增一条 `type=sync` 的条目，摘要含目标工具与成功/跳过数量
- **And** dryRun 不写日志

## Scenario 2：导入完成后留痕

- **Given** 用户通过导入向导提交 N 个文件，或执行反向导入
- **When** 导入返回
- **Then** 事件日志新增一条 `type=import` 条目，摘要含新建/合并/覆盖/跳过计数
- **And** 部分失败时仍记录一条（计数里体现失败数），不因个别失败丢弃整批记录

## Scenario 3：写库留痕

- **Given** 用户新建、编辑或删除 Hub 内文件
- **When** 写操作成功
- **Then** 事件日志分别新增 `create` / `edit` / `edit` 条目，`paths` 只含 Hub 相对路径
- **And** 写操作失败不写日志

## Scenario 4：治理批次留痕

- **Given** 用户执行一键整改或重复合并的 apply/undo
- **When** 批次返回
- **Then** 事件日志新增一条 `type=edit` 条目，摘要含成功/失败/跳过计数
- **And** 撤销同样留痕（摘要以「撤销」开头），便于回溯「改了什么又被撤回」

## Scenario 5：首页最近活动

- **Given** 事件日志中存在活动
- **When** 打开首页
- **Then** 「最近活动」展示最新 5 条，按时间倒序，`occurredAt` 为条目时间
- **And** 日志为空或不存在时展示既有空态文案，不伪造数据

## Scenario 6：活动页时间线

- **Given** 用户点击侧栏「活动」
- **When** 页面加载
- **Then** 展示全部活动的时间线（默认 20 条），每条含类型图标、摘要、相对时间
- **And** 支持按类型筛选（全部 / 同步 / 导入 / 编辑 / 新建）
- **And** 还有更早记录时提供「加载更多」，使用游标翻页，不重复、不跳条

## Scenario 7：保留期

- **Given** 事件日志存在超过 6 个月的分片
- **When** 读取活动或写入新活动
- **Then** 读取忽略超期分片；写入时删除超期分片（失败不影响写入结果）

## Scenario 8：坏数据不扩散

- **Given** 某个分片文件包含无法解析的行，或分片文件读取失败
- **When** 读取活动
- **Then** 跳过坏行/坏文件，其余条目正常返回，不抛错

## Scenario 9：隐私边界

- **Given** 任意一次写操作
- **When** 生成活动条目
- **Then** 条目只含路径、类别、计数、工具名，不含资产正文内容
- **And** 摘要中不出现用户主目录绝对路径

## 边界

- 日志追加失败（磁盘满、权限不足）时，同步/导入/写库照常成功返回。
- `limit` 超出 1-100 或 `type` 不在闭集内时，接口返回 400，不静默降级。
- 游标只对「更早」有效，格式非法时按无游标处理（返回第一页）。
