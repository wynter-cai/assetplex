# refactor-skill-asset-first-view：技能页只显资产，环境技能不公示

## Goal

技能页当前默认展示**全机器盘点**（约 600 项），其中 85% 以上是工具环境噪声——CodeBuddy 市场安装缓存（374）、TRAE 内置 persona 包（193）、插件自带（35）等，并非用户沉淀的资产。这与「资产保险箱 + 分发中心」的产品定位冲突：用户打开自己的库，大半屏是别人家的货架。

前序变更 refactor-skill-origin-taxonomy 已建立出处四分类（self/marketplace/plugin/builtin）× 库状态（in/out）正交筛选，但**默认口径仍是"全部"**，本次只改默认口径与视图分层，不动分类法。

本次变更（按用户准则「只管理高频使用与自己沉淀的技能；市场内容随时可重新安装，不值得代为管理」）：①技能页口径改为**资产优先**——列表、计数、职能分面默认只含**资产（已入库 ∪ 自建未入库）**，市场安装缓存/内置/插件内容**不公示**；②只留一条**主动调取**通道：页面底部折叠入口「本机技能环境（N）」，展开后保留出处筛选与「收藏到我的库」操作（真要取用时兜底），用完可收起；③引擎层**照旧全量扫描**——同名校验、同步冲突预览、AI 分类缓存都依赖环境清单：**引擎扫、UI 不公示**。

## Scope

### 做

- **后端**：`GET /api/skills` 新增 `scope=asset|environment|all` 参数（纯函数过滤，落在 skill-listing.ts），响应新增 `countByScope`；缺省（不带 scope 参数的旧调用）行为不变，保证既有调用方零破坏
- **盘点源补齐（资产侧要宽，用户批准并入本次）**：`SkillSources` 新增 Qoder 用户级目录（`~/.qoder-cn/skills` 优先、回退 `~/.qoder/skills`，与适配器同一判定顺序；origin=personal、tool=qoder）；工作区项目级扫描从只认 `.trae/skills` 扩展为兼认 `.qoder/skills`（origin=project，携工作区信息）；目录不存在时零贡献不报错（与现有容错一致）
- **前端**：技能页列表固定为资产视图（**不设平级分段**）；底部常驻折叠入口「本机技能环境」并显示计数，展开为环境列表（出处 chips + 收藏操作保留，可收起）；搜索默认限定资产口径，空态引导展开环境入口
- 统计口径：技能页总计数、职能分面（及 Home 概览中引用技能计数处）一律按**资产口径**计算，环境条目不参与；scope 与 function/search 正交组合（供展开的环境列表使用）

### 不做

- 市场技能"沉淀价值评分/整理建议"——依赖 LLM 仲裁基建（后续 S 级变更），本次不预埋
- 出处分类法与 deriveProvenance 语义——上一变更已定，不动
- 其他资产类别（rules/mcp/identity）的同口径改造——本次只在技能页验证信息架构，跑通后推广
- 盘点源改为**适配器注册表驱动**（消灭第二份真相）——架构性变更另立 spec，本次先补 Qoder 止血

## Risks

| 风险 | 缓解 |
|------|------|
| 环境不公示导致"我装过的技能找不到了" | 折叠入口常驻且明示计数，搜索空态指向入口；引擎仍全量扫描，收藏取用路径未删 |
| scope 与既有 status/provenance 参数组合语义复杂 | scope 定位为"视图预设"，与显式 status/provenance 同时出现时 scope 先行、细分参数在其内二次过滤；spec 场景逐一钉死 |
| 前端测试 mock 全按旧参数构造，改动后假绿 | 组件测试断言 `api.listSkills` 实际调用参数（沿用上次教训：mock 契约必须与真实响应同构） |

## 关键设计决策（用户已拍板 2026-10-18）

1. **资产定义**：`asset ⇔ inLibrary || provenance==='self'`（入库即资产，个人/项目目录自建也是资产）；反面即 environment
2. **环境不公示（用户对初稿的修订）**：初稿曾设计「我的技能/本机环境」平级分段，用户拍板改为**降级为折叠入口**——市场缓存不作为平级视图管理。这构成对 refactor-skill-origin-taxonomy「未入库×市场=待收藏候选池」决策的**规格修订**：能力保留（API scope 参数 + 收藏操作），UI 入口降级
3. **默认视图**：资产视图（当前基线约 130 项），非仅「已入库 31」
4. **「高频」口径**：暂无使用频率数据，本次以「自己沉淀」划界；使用统计/高频推荐留作分类法 hook，后续变更再议
5. **API 兼容**：保留不带 scope 的旧语义（=all），前端显式传参，后端零破坏
6. **官方内置包在环境入口内保留一格（用户批准）**：默认折叠、分组排序市场安装 → 插件自带 → 官方内置（最后）——收藏内置技能分发到其他工具是资产 hub 的真实场景，市场缓存则无此价值
7. **盘点源补齐并入本次（用户批准）**：新口径下资产漏扫比环境噪声严重得多，Qoder 用户级/项目级自建技能必须进入盘点；适配器注册表驱动统一改造后续另立变更
