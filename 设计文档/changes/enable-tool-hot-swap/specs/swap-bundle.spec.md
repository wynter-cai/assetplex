# Spec: 切换包(Swap Bundle)资产覆盖面

> Capability: swap-bundle
> Change: enable-tool-hot-swap
> 背景实测(recon-notes §3):workbuddy/codebuddy 适配器 `resolveHubItems` 只映射 rules/skills/mcp,
> 用户的 `IDENTITY.md`、`SOUL.md/USER.md`、`memory/`、`expert-history`(子代理)不在分发面内,
> 导致"换过去接不上活"。本 spec 定义切换包应携带哪些资产、以及工具不支持时的表现。
> 决策(维护者 2026-10-11):切换包默认含六类;工具不支持的类别标注"已跳过"。

## ADDED Requirements

### Requirement: 切换包六类资产

切换包 = 当前 Hub(我的库)中以下六类的全部资产的集合快照:身份(identity)、规则(rule)、技能(skill)、MCP(mcp)、记忆(memory)、子代理(agent)。一次切换以"工具"为单位整体投放,不要求用户逐类手动操作。

#### Scenario: 打开切换选择目标工具

- **Given** 我的库中六类各有若干资产,用户进入「切换」页并选定一个目标工具
- **When** 查看切换包概览
- **Then** 概览按六类分组列出将被投放的资产数量与清单
- **And** 每一类显示该目标工具"支持 / 不支持"

#### Scenario: 身份与记忆被纳入投放

- **Given** 我的库存在身份资产与记忆资产,目标工具支持该类别
- **When** 用户执行切换到该工具
- **Then** 身份与记忆按目标工具的目录约定写入对应位置
- **And** 不再出现"只带了规则/技能/MCP、身份记忆缺失"的情况

### Requirement: 工具不支持类别的显式降级

当目标工具本身不支持某类资产(如某工具无用户级身份概念),该类在切换中应被明确跳过并说明原因,不得静默丢弃,也不得写入工具不认识的路径。

#### Scenario: 切换到不支持身份的工具

- **Given** 目标工具不支持身份类别,我的库有身份资产
- **When** 用户查看切换包概览
- **Then** 身份分组标注「此工具不支持,已跳过」,并给出原因简述
- **And** 执行切换时身份被跳过,其余支持类别正常投放
- **And** 结果面板把"跳过"与"成功/失败"分列,不混淆

#### Scenario: 不支持类别不影响其余投放

- **Given** 目标工具仅支持六类中的部分
- **When** 执行切换
- **Then** 仅支持类别被投放并验证,不支持类别被跳过
- **And** 整个切换不因某类别不支持而整体失败

### Requirement: 记忆类型进入资产体系

记忆(memory)作为可管理、可分发的资产类别纳入 Hub 类型,资产库导航与后端类型支持动态扩展到含 memory 的类别集合,不写死既有类别数。

#### Scenario: 记忆资产出现在切换包与库导航

- **Given** 用户已从 workbuddy 目录收藏了记忆资产到我的库
- **When** 打开资产库导航或切换包概览
- **Then** 「记忆」作为一个类别出现,可被计入并分发
- **And** 新增类别不要求改动写死的类别数量逻辑

## 验收锚点

- 六类齐全度以"目标工具支持矩阵"为准:支持的必带、不支持的必标注跳过。
- 关键回归:切换一个支持全部六类的工具时,切换包六类计数之和 == 我的库六类资产总数(不含偏好类)。
