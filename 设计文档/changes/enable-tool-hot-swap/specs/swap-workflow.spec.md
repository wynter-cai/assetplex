# Spec: 一键切换工作流(预览 → 确认 → 执行)

> Capability: swap-workflow
> Change: enable-tool-hot-swap
> 现状:仅有按 hub.toml 已启用工具做的逐类 sync(`/sync/plan`→`/sync/run`),缺"选一个工具、把我全部能力一次投放"的编排。
> 宪法①(智能默认):对用户不利的默认要关——本 spec 中"会覆盖目标工具里已存在且内容不同的资产"这一动作,默认不覆盖,需显式确认。

## ADDED Requirements

### Requirement: 切换入口与目标选择

「切换」提供以工具为单位的整体投放入口:选一个目标工具即针对该工具发起一次切换,不要求用户先逐类勾选资产。

#### Scenario: 选择在线的目标工具

- **Given** 至少一个已安装工具
- **When** 用户在切换页选择目标工具
- **Then** 系统据切换包(见 swap-bundle.spec)生成该工具的投放预览
- **And** 未安装/未检测到的工具不可作为目标,选择器中置灰并说明原因

### Requirement: 冲突预览先行

执行前必须先展示预览:将写入哪些路径、其中哪些是"目标已存在且内容不同(会覆盖)"、哪些是"新增"、哪些"无变化"。用户看到预览后才进入执行。

#### Scenario: 存在会被覆盖的资产

- **Given** 目标工具目录中某规则已存在且与我的库内容不同
- **When** 查看切换预览
- **Then** 该项被标为「冲突·将覆盖」并突出显示,默认勾选为**不覆盖(跳过)**
- **And** 用户可对单个冲突项显式选择"覆盖"后才会计入覆盖

#### Scenario: 无冲突项直通

- **Given** 切换包中某类资产在目标处不存在
- **When** 查看预览
- **Then** 该项标为「新增」,默认包含在执行中,无需逐个确认

#### Scenario: 未确认覆盖就不动已存在内容

- **Given** 预览存在「冲突·将覆盖」项,用户未对其选择覆盖
- **When** 用户执行切换
- **Then** 这些冲突项保持目标原样不被改动
- **And** 结果面板把未覆盖项列为「已跳过(冲突)」

### Requirement: 执行与结果反馈

确认后执行切换,过程与结果对用户可见:逐类别的进行态、总成功/失败/跳过计数、可下钻到单资产结果。执行动作有明确反馈(toast + 结果面板),不存在"点了没反应"。

#### Scenario: 执行成功

- **Given** 用户确认预览
- **When** 执行切换且全部投放项写盘并校验通过
- **Then** 结果面板显示成功计数,并进入验证视图(见 swap-verify-rollback.spec)
- **And** 出现成功 toast,提供"撤销本次切换"入口

#### Scenario: 部分项失败

- **Given** 执行中某项写盘或校验失败
- **When** 切换结束
- **Then** 结果面板分项列出成功/失败/跳过,失败项给出人类可读原因与受影响路径
- **And** 不因单项失败而谎称整体成功

## 验收锚点

- 预览与执行分离:任何覆盖必先在预览中被标出且默认不覆盖。
- 每次切换产出一条切换历史记录(供活动流与回滚使用)。
