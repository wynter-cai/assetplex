# Spec: 验证生效与回滚(显示成功 = 真的成功)

> Capability: swap-verify-rollback
> Change: enable-tool-hot-swap
> 缺口(recon G4/G5):现状 `run` 写完不回读,换工具最怕"以为同步了其实没生效";装错/覆盖错无法撤回。
> 诚实边界:验证只保证"文件到位 + 格式合法 + 与源一致",**不谎称"工具已加载生效"**(工具加载逻辑是黑盒)。

## ADDED Requirements

### Requirement: 落盘后回读验证

切换执行完成后,系统对每个已投放项做回读验证:目标路径文件存在、按其类型可解析(md/json/toml)、内容与我的库源一致。验证结果逐项呈现。

#### Scenario: 验证全部通过

- **Given** 一次切换的所有投放项均已写盘
- **When** 系统回读验证
- **Then** 每项标记「已写入并校验」,列出校验维度(存在/可解析/一致)
- **And** 文案表述为"已写入并校验",不出现"工具已生效/已加载"等无法证实的措辞

#### Scenario: 回读发现不一致

- **Given** 某项写盘后回读内容与源不一致或不可解析
- **When** 验证
- **Then** 该项标红为「校验未通过」并说明是哪一维度失败、受影响路径
- **And** 整体结果计为部分失败,不笼统报成功

#### Scenario: MCP 等结构化文件按格式校验

- **Given** 投放项为 MCP(JSON)或 Codex(TOML)等结构化文件
- **When** 验证
- **Then** 以对应解析器校验其语法合法,而非仅比对字节

### Requirement: 切换前备份与一键回滚

执行切换前,对"将被覆盖的目标已存在文件"先行备份(仅备份 differs/覆盖项)。提供"撤销本次切换",将该次切换覆盖的文件从备份恢复。备份存放于 Hub 内,受保留策略约束。

#### Scenario: 覆盖前自动备份

- **Given** 预览中用户对某冲突项选择了覆盖,目标处已有文件
- **When** 执行该项覆盖
- **Then** 旧文件在覆盖前被备份(带本次切换标识与时间戳)
- **And** 新增类文件(目标原本无)不产生备份(回滚即删除)

#### Scenario: 撤销本次切换

- **Given** 刚完成一次切换,存在对应备份记录
- **When** 用户点击"撤销本次切换"
- **Then** 被覆盖文件从备份恢复原内容;本次新增的文件被移除
- **And** 撤销后目标目录回到切换前状态,并在历史中记录一次回滚

#### Scenario: 备份保留策略

- **Given** 已发生多次切换
- **When** 查看/触发清理
- **Then** 仅保留最近 3 次切换的备份(默认,可配置),更早的自动清理
- **And** 清理只针对备份目录,不触碰工具现有资产

### Requirement: 切换历史

每次切换(含预览结论、执行结果、验证结果、是否已回滚)记录为一条切换历史,作为活动流的数据源之一,只存本机。

#### Scenario: 切换后历史新增一条

- **Given** 用户完成一次切换
- **When** 打开切换历史
- **Then** 顶部出现该次记录:目标工具、时间、成功/失败/跳过计数、是否可回滚
- **And** 数据仅本机存储,无外发

## 验收锚点

- 任一投放项若无验证结论,不得展示为"成功"。
- 回滚的原子性:撤销要么完整恢复要么明确报失败,不得留下半恢复状态。
