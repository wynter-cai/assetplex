# Change: add-vault-connections-ui

> Change ID: `add-vault-connections-ui`
> 类型: S 级（UI 架构重构）
> 状态: 待审核

## Goal (目标)

将 AgentHub Web UI 从当前 9 个平铺 tab 的"功能菜单"结构，重构为 4 个核心区域 + 1 个引导层的"任务地图"结构，让用户在 3 秒内知道自己有什么、该做什么。

核心价值：
- 让"入库→管理→分发"的用户旅程一条线走通
- 让每个资产清晰可见"在哪、从哪来、到哪去"
- 为未来扩展资产类别（command/agent/memory）做好准备

## Scope (范围)

### 做什么
1. 重构导航：9 个 tab → 4 个核心区域（首页/资产库/连接/活动）+ 设置
2. 重写首页：从仪表盘 → 指挥中心（资产快照 + 连接状态 + 快速动作 + 最近活动）
3. 重构资产库：从 4 个独立页面 → 1 个统一资产库（左侧类别导航 + 右侧卡片列表）
4. 重写连接页：从工具列表 → 工具详情面板（资产分发状态 + 未入库文件）
5. 新增活动页：时间线展示入库/分发/编辑历史
6. 资产类别支持动态扩展（不写死 4 类）
7. 整合入库向导入口（首页/连接页/资产库都可发起）
8. 整合分发同步入口（每个工具详情面板内完成）

### 不做什么（Non-Goals）
- ❌ 不新增 command/agent/memory 资产类别（留给 Phase B）
- ❌ 不改后端核心业务逻辑（scanner/merger/sync-engine 保持不变）
- ❌ 不做首次使用 Onboarding 向导（留给 Phase C）
- ❌ 不做全局搜索（留给 Phase C）
- ❌ 不引入新UI框架（继续用 shadcn/ui + TailwindCSS）

## Risks (风险)

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 后端 API 不够用 | 首页/连接页需要聚合数据，现有 API 太碎 | 新增 `/api/hub/overview` 和 `/api/connections/:tool/assets` 聚合接口 |
| 重构期间功能不可用 | 用户当前依赖的功能暂时用不了 | 分阶段重构，每个阶段保证核心功能可用 |
| 资产类别动态扩展影响类型 | 写死 `AssetCategory = 'identity' \| ...` 会导致扩展困难 | 改为 `string` + 配置化定义 |
| DiffView 等组件复用问题 | 新页面布局可能和现有组件不兼容 | 先重构布局，再适配组件 |
