# p0.spec.md：发布配套 SEO 的 P0 三件套

> capability: 社交卡片元数据、README 首屏素材、站点地图与抓取指引、构建产物可见性、零统计硬约束
> 变更: add-launch-seo（M 级）| 关联: `../proposal.md`
> 沿用决策: 公开面划分（D1）、og:image 只复用不新设计（D2）、大图卡片（D3）、
> README 首屏允许降级（D4）、sitemap 由构建产出（D5）、robots 只放开与指向（D6）、
> 禁 GA 硬约束（D7）、不引入 SSR/预渲染（D8）、本机界面只做零维护元数据（D9）

> **D9 口径（2026-11-17 维护者拍板）**：本机界面（`127.0.0.1`）的 SEO 价值边界与公开站点不同——爬虫到不了本机，
> 链接贴到聊天工具里对方也打不开。因此本机界面**只做零维护元数据**：页面标题、描述、社交卡片标签，
> 图片指向随构建复制的静态资源；**不产出** `sitemap.xml`、`robots.txt`、`canonical`、`og:url`、结构化数据。
> 「让用户知道界面长什么样」不靠 SEO 标签，靠 README 首屏素材与文档站的界面截图 + 启动指引（R9）。

## 定义

- **公开站点**：对外可访问、可被搜索引擎抓取的静态站点（当前为文档站）。下文「站点 URL」一律以
  `https://assetplex.example.com/` 作占位，真实主机与子路径由维护者在配置中确定，本 spec 不固化。
- **构建产物**：公开站点执行生产构建后输出的目录；本机界面执行 Vite 生产构建后输出的目录。
- **社交卡片**：链接在即时通讯或社交平台中展开时显示的预览卡，包含图片、标题、描述。
- **首屏素材**：README 中紧随标题与徽章组之后、第一段正文之前出现的第一张展示图。
- **公开页**：不需要登录、不属于错误页、可被外部直接访问的页面。
- **统计脚本**：任何会把访客标识、访问路径或行为事件发送到本站以外域名的第三方脚本（含内联、CDN、图片像素、上报接口）。
- **三件套**：`og:image` + `twitter:card`、README 首屏素材、`sitemap.xml` + `robots.txt`。

## Requirement 1：社交卡片图（R1）

### Scenario 1.1 分享站点首页时显示大图卡

- **Given** 站点已按本期构建并部署
- **When** 把站点首页链接粘贴到支持富卡片的即时通讯工具或社交平台
- **Then** 链接展开为大图卡：显示卡片图、页面标题与页面描述；图片能正常加载（不是灰块、不是 404）

### Scenario 1.2 卡片图规格与声明一致

- **Given** 卡片图已放入站点静态资源
- **When** 检查该文件与页面声明
- **Then** 图片尺寸恰为 **1280×640**（宽高比 2:1）；页面声明了图片地址、宽度 1280、高度 640 与替代文本；
  替代文本是一句中性描述，不含个人称谓、本机路径或客户信息

### Scenario 1.3 图片缺失时阻断发布，而不是发布坏链

- **Given** 页面已声明卡片图地址，但图片文件未进入构建产物
- **When** 执行发布前检查
- **Then** 检查结果明确报「卡片图缺失」，该次发布视为不通过；不得带着指向 404 的卡片图上线

### Scenario 1.4 页面缺少自身描述时的兜底

- **Given** 某公开页没有页面级描述
- **When** 该页被分享或抓取
- **Then** 卡片描述回落到站点级描述，标题回落到页面标题；不出现空标题或空描述

## Requirement 2：卡片类型与跨平台一致（R2）

### Scenario 2.1 卡片类型为大图

- **Given** 站点任一公开页已构建
- **When** 检查页面输出
- **Then** 卡片类型声明为 `summary_large_image`；卡片图与通用社交卡片图使用同一张图、同一绝对地址

### Scenario 2.2 平台只认通用标签时仍有卡片

- **Given** 某平台不读取专用卡片标签，只读取通用社交标签
- **When** 该平台抓取页面
- **Then** 至少仍能取到通用三项（标题、描述、图片），不出现「只有标题没有图」的降级

## Requirement 3：README 首屏素材（R3）

### Scenario 3.1 有 GIF 时首屏展示 GIF

- **Given** 维护者已提供首屏动图
- **When** 打开英文或中文 README
- **Then** 首屏（标题与徽章之后、正文之前）展示该动图，带中性替代文本；图片随容器宽度自适应，不横向溢出；
  文件存放在仓库内，不外链第三方图床

### Scenario 3.2 GIF 未就绪时用真实界面静态图占位

- **Given** 首屏动图尚未录制
- **When** 打开 README
- **Then** 首屏展示一张**真实界面**的静态截图作为占位，带中性替代文本；
  不留空位、不使用坏链、不使用设计稿或合成图冒充真实界面、不引用本机绝对路径

### Scenario 3.3 首屏素材不拖垮阅读

- **Given** 首屏素材已就位
- **When** 在常见网络下打开 README
- **Then** 素材文件体积不超过 5 MB；超过 5 MB 必须压缩或退回静态图；正文在素材加载完成前即可阅读

### Scenario 3.4 中英文 README 素材一致

- **Given** 仓库同时提供英文与中文 README
- **When** 对比两份首屏
- **Then** 两份展示同一素材、同一说明口径；不出现一份有图一份无图

## Requirement 4：站点地图（R4）

### Scenario 4.1 构建产物包含站点地图且覆盖全部公开页

- **Given** 公开站点执行生产构建
- **When** 查看构建产物根目录
- **Then** 根目录存在 `sitemap.xml`；至少包含以下 5 个公开页：站点首页、入门指南、支持的工具、数据与隐私、常见问题；
  每条地址为绝对 URL，并包含站点的子路径

### Scenario 4.2 站点地图不含不该出现的地址

- **Given** 站点地图已生成
- **When** 逐条检查
- **Then** 不含错误页、不含带查询参数或锚点的地址、不含 `localhost` / `127.0.0.1` / 内网 IP、不含仅本机可访问的界面路由

### Scenario 4.3 新增公开页后自动纳入

- **Given** 维护者新增一个公开页并重新构建
- **When** 查看新的站点地图
- **Then** 该页已自动出现在地图中；维护者不需要手工编辑第二份页面清单

### Scenario 4.4 地图里的地址都能打开

- **Given** 站点地图已部署
- **When** 逐条访问地图中的地址
- **Then** 每条都返回对应页面内容，不出现 404、不跳转到其他页

### Scenario 4.5 生成失败要报错，不静默缺件

- **Given** 站点地图生成环节失败
- **When** 执行构建
- **Then** 构建明确失败并指出缺失的文件；不得产出「没有站点地图」的构建产物并继续发布

## Requirement 5：抓取指引（R5）

### Scenario 5.1 抓取指引包含站点地图指令

- **Given** 公开站点执行生产构建
- **When** 查看构建产物根目录的 `robots.txt`
- **Then** 文件存在；包含对所有抓取方放开站点的规则；包含一行指向站点地图的指令，其值为站点地图的绝对地址，且与实际位置一致

### Scenario 5.2 不误伤静态资源

- **Given** 抓取指引已生效
- **When** 抓取方访问任意公开页
- **Then** 页面的样式、脚本与图片资源均未被屏蔽；不出现「整站禁止抓取」的规则

### Scenario 5.3 修好「整站被禁止」的情况

- **Given** 站点此前存在全站禁止抓取的规则
- **When** 本期构建发布后抓取方重新抓取
- **Then** 首页与公开页可被抓取，且能从抓取指引找到站点地图

## Requirement 6：构建产物可见性（R6）

### Scenario 6.1 公开站点产物可见三件套

- **Given** 执行公开站点生产构建
- **When** 检查产物根目录与首页 HTML
- **Then** 根目录可见 `sitemap.xml` 与 `robots.txt`；首页 HTML 的头部静态可见卡片图地址、卡片类型、标题与描述；
  这些标签不依赖运行时脚本注入

### Scenario 6.2 本机界面只做零维护元数据

- **Given** 执行本机界面的 Vite 生产构建
- **When** 检查产物
- **Then** 入口 HTML 静态可见页面标题、描述、卡片图地址与卡片类型标签；放在静态资源目录的图片被原样复制到产物根目录；
  产物中**不存在** `sitemap.xml`、`robots.txt`、`canonical`、`og:url` 与结构化数据；
  不引入服务端渲染或预渲染；本期不承诺界面正文被搜索引擎索引

### Scenario 6.3 不依赖服务端

- **Given** 产物目录被任意静态托管
- **When** 直接访问入口 HTML 与三件套文件
- **Then** 全部可直接取得，无需任何服务端逻辑参与

## Requirement 7：零第三方统计（硬约束，R7）

### Scenario 7.1 页面与产物中 0 个统计脚本

- **Given** 本期三件套已落地
- **When** 检查所有页面、构建产物与前端依赖
- **Then** 不存在任何第三方访客统计或行为分析脚本（含 Google Analytics / Google Tag Manager 类、自建 SaaS 统计类、
  百度统计类、热图与录屏类），也不存在其上报地址、内联片段或图片像素

### Scenario 7.2 有人提议接入统计时的处理

- **Given** 有人提出「加个统计看看流量」
- **When** 该提议进入评审
- **Then** 必须先有独立 spec 与评审结论，且方案满足「自托管、无 cookie、数据聚合在自有域名」；
  评审通过前一律不改动；理由必须在评审记录中写明：第三方统计会把访客数据发往站外，与项目「零数据上传」的宪法承诺冲突

### Scenario 7.3 发布前的零统计检查

- **Given** 准备发布
- **When** 执行发布前检查
- **Then** 对仓库与构建产物做一次统计脚本扫描，命中数为 0 才允许发布；命中即回退对应改动

## Requirement 8：降级与边界（R8）

### Scenario 8.1 图片体积或格式不合规

- **Given** 卡片图被替换为尺寸不符或超过体积上限的文件
- **When** 执行发布前检查
- **Then** 检查报出具体不符项（尺寸 / 格式 / 体积），该次发布不通过；不得自动拉伸或压缩后继续

### Scenario 8.2 站点主机或子路径变更

- **Given** 站点迁移到新的主机或子路径
- **When** 重新构建
- **Then** 卡片图地址、站点地图内的地址、抓取指引中的地图指令都随构建更新，不需要逐处手改

## Requirement 9：界面可发现性（R9）

### Scenario 9.1 文档站能先看到界面长什么样

- **Given** 访客打开公开文档站的「快速开始」页
- **When** 阅读安装步骤
- **Then** 页面内有一张真实界面截图，能看出这是一个「AI 资产全貌」视图（分类、数量、状态一屏可见）；
  截图下方有一句明确的启动指引：启动后在本机浏览器打开对应地址查看自己的资产
- **And** 截图与 README 首屏素材口径一致，不用设计稿或合成图冒充真实界面

### Scenario 9.2 README 能让访客在安装前判断价值

- **Given** 访客只打开仓库 README
- **When** 浏览首屏
- **Then** 首屏素材直接呈现资产全貌界面，而不是只有文字描述或架构图；
  访客不需要先安装就能判断这个工具是否解决自己的问题

## 非目标（Non-goals）

- 不做服务端渲染、预渲染或首屏静态化
- 不做关键词投放、外链建设，不承诺搜索排名
- 不做多语言 `hreflang`、不做页面级结构化数据（P1）
- 不新增 `/alternatives` 对比页（P2）
- 不接入任何访客统计，包括自托管方案（P2，且需独立评审）
- 不新设计卡片图美术资产（复用同源图）
- 不改任何业务代码、后端路由或前端组件
