# proposal: add-launch-seo（发布配套 SEO 的 P0 三件套）

> 级别：M（站点 head 元数据 + 静态资源 + 构建门禁，不改业务逻辑）
> 状态：草案，待评审
> change-id：`add-launch-seo`
> 关联：HANDOFF 待办池 B5；队列 B5-01（spec）/ B5-02（实现）

---

## 为什么现在做

发布在即，三处「第一眼」是空的：

- 链接贴进 IM / 社交平台，没有预览大图，只有一行裸链接；
- README 首屏（标题与徽章之后）直接就是大段英文，没有一张能三秒说清「这是什么」的画面；
- 搜索引擎与 AI 抓取端只能看到首页，看不到站点有几页、哪几页值得抓。

这三件事都不涉及产品逻辑，却直接决定「点进来的人有多少、进来的人几秒内懂不懂」。发布窗口内做，成本最低、收益最直接。

## 现状核对（写 spec 前逐文件读码结论）

| 诉求 | 现状 | 证据 |
|------|------|------|
| 社交卡片图 | ❌ 无 `og:image`，也无 `twitter:card` | `docs/.vitepress/config.mts` 的 `head` 只有 `keywords`、`og:title`、`og:description`；`web/index.html` 只有 `charset` / `favicon` / `viewport` / `title` |
| 站点地图 | ❌ 无 `sitemap.xml` | `docs/.vitepress/dist/` 根目录只有 `index.html`、`404.html`、三个页面 HTML 与 `assets/` |
| 抓取指引 | ❌ 无 `robots.txt` | 同上；也没有 `docs/public/` 目录 |
| README 首屏素材 | ❌ 无截图、无 GIF | `README.md` / `README.zh-CN.md` 第 11–19 行是徽章，第 25 行直接进 `Why AssetPlex?` 段落 |
| 公开站点形态 | ✅ 纯静态 | 文档站由 VitePress 构建（`docs/` → `docs/.vitepress/dist/`），由 Pages 工作流整目录上传；`base` 为子路径 |
| 本机界面形态 | ✅ Vite SPA | `web/index.html` 为入口，静态资源放 `web/public/`，构建产物 `web/dist/` 由本机后端托管；无 SSR、无预渲染 |
| 统计脚本 | ✅ 目前为 0 | 上述两个入口均无任何第三方脚本 |

结论：**P0 是从零补三块静态件**，不涉及任何后端路由、数据库或前端业务组件。

## 范围

### P0（本期，必须）

1. **社交卡片**：`og:image`（1280×640）+ `twitter:card`
2. **README 首屏素材**：GIF 优先，缺素材时用静态图占位
3. **可抓取性**：`sitemap.xml` + `robots.txt`

### P1（不在本期）

- 5 个文档页各自的 `description` frontmatter
- `canonical` / `og:url` / `og:type` / `og:site_name` 补全
- JSON-LD 结构化数据
- `llms.txt`

### P2（不在本期）

- `/alternatives` 对比页
- 自托管访客统计（**即使自托管也必须单独 spec 评审**，见 D7）

## 关键决策

- **D1 公开面划分**：对外可索引的站点 = 文档站（纯静态构建产物）；`web/` 是 `assetplex ui` 的本机界面，默认不对外。
  SEO 的主战场是文档站，但本机界面的入口 HTML 也要带同样的卡片标签——将来若独立托管或截图分享，不至于裸链。
- **D2 og:image 只复用、不新设计**：规格 1280×640（2:1），与 GitHub 仓库的 Social preview 同源，实现时从既有同源图导出，不另画。
  本期只锁定「规格 + 路径 + 校验方法」，不产生新美术资产。
- **D3 卡片类型用大图**：`twitter:card` 取 `summary_large_image`；同时声明 `og:image:width` / `og:image:height` / `og:image:alt`，
  图片地址必须是绝对 URL，并随站点子路径正确解析。
- **D4 README 首屏允许降级**：GIF 需人工录制，未录好之前用**真实界面静态截图**占位；
  禁止留空、禁止坏链、禁止用设计稿/合成图冒充真实界面、禁止外链第三方图床。
- **D5 sitemap 由构建产出，不手工维护**：URL 必须是绝对地址、含站点子路径，只列公开页；
  不含 `404`、不含查询参数与锚点、不含本机地址（`localhost` / `127.0.0.1` / 内网 IP）。
- **D6 robots 只做一件事**：放开抓取并指向 sitemap；不得屏蔽 CSS/JS/图片等静态资源。
- **D7 禁 GA 是硬约束**：任何页面、任何构建产物不得引入第三方访客统计或行为分析脚本。
  理由：项目宪法与对外承诺是「100% local / 零数据上传」；统计脚本会把访客 IP、UA、访问路径发给第三方，
  与产品承诺直接冲突，且无法向用户交代。未来若确需流量口径，只允许「自托管 + 无 cookie + 聚合到自有域名」，
  并且必须先有独立 spec 与评审结论；评审通过前，P0 及后续任何变更都保持 0 统计脚本。
- **D8 不引入 SSR/预渲染**：两条流水线都保持静态构建；本期只保证「head 里的标签在构建产物中静态可见」，
  不承诺 SPA 正文被搜索引擎完整索引（这属于后续独立议题）。

## 影响面

| 层 | 变更 |
|----|------|
| 文档站 | `docs/.vitepress/config.mts` 的 `head` 与站点地图配置；新增 `docs/public/robots.txt` |
| 本机界面 | `web/index.html` 增标题、描述与卡片标签；`web/public/` 增静态图（不产出 robots / sitemap，见 D9） |
| README | `README.md`、`README.zh-CN.md` 首屏插入素材，两份保持一致 |
| 构建 | 两条流水线的产物根目录都必须能看到三件套；缺件视为构建失败 |
| 业务代码 | 零改动（不改 `src/`、不改路由、不改组件） |

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 卡片图 404（meta 写了但文件没进产物） | 构建后校验文件存在 + 尺寸；缺件即阻断发布 |
| 子路径写死导致迁移成本 | 图片与 sitemap 地址由构建配置派生，不散落在多处手写 |
| sitemap 列了不可访问页 | 逐条点开校验可访问；新增页自动纳入，不维护第二份清单 |
| robots 误屏蔽静态资源导致页面样式丢失 | 只写放开规则，不写资源级 `Disallow`；构建后抽查 |
| GIF 体积过大拖慢首屏 | 单文件体积上限 + 帧数与时长约束；未达标退回静态图 |
| 后续有人「顺手」接入统计 | 禁 GA 写进 spec 硬约束 + 发布前产物扫描；变更需独立评审 |
| 中英文 README 素材漂移 | 同一素材同一路径，两份一起改 |

## 回滚

- 三件套都是新增/独立的静态内容，`revert` 对应 commit 即回到现状；
- 站点地图与抓取指引删除后，爬虫回落到默认抓取，不会报错；
- 卡片标签删除后链接恢复裸链展示，不影响页面功能；
- README 素材删除后回到纯文字首屏，不影响安装与使用。

## Definition of Done

1. spec 中所有 Scenario 可手工复验，并留验收记录
2. 两条流水线各自生产构建后，产物根目录能看到 `sitemap.xml`、`robots.txt`，首页 HTML 里能看到卡片标签
3. 构建产物与仓库内 0 个第三方统计脚本
4. 中英文 README 首屏素材一致，且无坏链
5. `node scripts/privacy-check.mjs` 退出码 0
