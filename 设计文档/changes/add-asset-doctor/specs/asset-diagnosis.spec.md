# asset-diagnosis.spec.md：资产体检诊断（只读）

> capability: 单资产/批量诊断、确定性预检、报告渲染、缓存与失败隔离
> 变更: add-asset-doctor | 决策依据: proposal.md D1/D3/D5/D6

## 定义

- **体检报告**：对一个资产条目（skill/agent/rule/identity/command，库内资产）对照适用准则产出的结构化结论
- **确定性预检**：不调模型的机械检查（frontmatter 必填项缺失、description 为空、正文超长阈值、疑似全大写 shouting 规则等），先于模型执行且结果并入报告
- 诊断范围 = 资产侧：环境（未入库非自建）条目不提供诊断入口

## Scenario 1：单资产诊断出报告

- **Given** 某技能正文冗长、description 含糊，库内有 appliesTo 含 skill 的 enabled 准则
- **When** 用户在技能详情/卡片点「资产医生」
- **Then** 展示报告：结论徽标（健康/需关注/有风险）+ 问题列表，每条含严重度、引用准则名（可点回准则卡）、问题描述、修改建议；命中准则清单与"N 条准则未参与"披露同仲裁建议卡机制

## Scenario 2：健康资产给正反馈

- **Given** 某规则文件简洁、字段完备、符合准则
- **When** 诊断完成
- **Then** overall=healthy，问题列表为空并显示"未发现违反已启用准则的问题"，不编造低价值建议凑数（prompt 契约明确：无问题就返回空 issues）

## Scenario 3：确定性预检不消耗 token

- **Given** 某 agent 配置缺 name 字段（可机械判定）
- **When** 发起诊断
- **Then** 该问题由确定性检查直接入报告（标注"机械检查"），即使 AI 端点未配置也能看到此类问题；模型部分未配置时其余语义项显示降级提示（Scenario 7），机械项照常

## Scenario 4：内容未变时命中缓存

- **Given** 某资产已诊断过，之后正文与准则集都未变化
- **When** 再次点「资产医生」
- **Then** 直接返回缓存报告并标注"来自缓存"；编辑资产内容或增删改适用准则后缓存自然失效（key = sha256(内容 + 适用准则集哈希 + model)）

## Scenario 5：批量体检与预算护栏（proposal D5）

- **Given** 技能页有 60 个库内资产，其中 10 个已有缓存报告
- **When** 用户点「全部体检」
- **Then** 发起前显示"将调用 50 次模型（10 条来自缓存不消耗）"；超过 50 次实际调用时需二次确认；执行期并发≤4、逐条进度可见；单条失败进失败清单不中断批量；完成后报告清单按 有风险→需关注→健康→失败 排序，点条目看单份报告

## Scenario 6：准则为空时仍可诊断

- **Given** 库内没有任何 enabled 准则
- **When** 发起模型诊断
- **Then** system prompt 仅含内置基线骨架（机械检查照常），报告正常产出并提示"当前无自定义准则，结论基于内置基线——沉淀准则后诊断会更贴合你的标准"

## Scenario 7：未配置 AI 端点降级

- **Given** 用户未配置 baseUrl/apiKey/model
- **When** 点「资产医生」
- **Then** 不发起请求；报告面板展示机械检查结果 + "配置 AI 端点后可诊断语义质量问题"与跳转入口；批量体检同样降级（只跑机械项并明确标注）

## Scenario 8：非法输出失败隔离

- **Given** 模型返回无法解析 JSON / overall 不在三值闭集 / issue 缺必填字段
- **When** 解析
- **Then** 该资产标记"诊断失败：<原因>"，不产生半成品报告；资产本体与分发状态零变化

## Scenario 9：隐私边界

- **Given** 诊断发起
- **When** 请求发出
- **Then** 仅目标资产内容 + 适用准则正文发往**用户自配** OpenAI 兼容端点（与 AI 分类/仲裁同一 LlmClient 与配置），不经第三方；批量场景在确认框中重申此边界（与 PRIVACY.md 一致）
