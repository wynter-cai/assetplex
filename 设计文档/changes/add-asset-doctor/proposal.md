# proposal: add-asset-doctor（资产医生：最佳实践诊断 → 一键修复 → 分发）

> 级别：S（新能力模块 + 新 API + 跨资产类别的 UI 接入 + 写库与分发链路整合）
> 依赖：add-llm-conflict-arbitration 的 Phase A/B（准则元资产 + LLM 执行基建），两变更共用同一套组装/缓存/失败隔离机制
> 状态：待维护者审核

## 为什么做（背景）

1. **维护者拍板（2026-10-18）**："资产中心里的 skill、agent 等的设计要符合行业内最佳实践。派生一个任务，把业内相关的能用到的最佳实践用起来——不止仲裁冲突，还要通过业内最佳实践给诊断、给建议，甚至通过软件调用大模型，从资产中心直接修改资产并直接分发到各个 AI agent/coding 工具。"
2. 现状缺口：AssetPlex 管"资产在不在、到哪了"（盘点/收藏/分发/回滚），不管"资产写得好不好"。技能正文冗长、description 触发条件模糊、agent 配置失范——这些在行业里有成文最佳实践（Anthropic Agent Skills 指南、AGENTS.md 规范、token 效率实践），但用户要自己记得去对照。
3. 架构契合点：仲裁变更已把「裁决准则」立为元资产（criterion 类别，带 appliesTo 适用范围）。**诊断就是"单资产 × 准则集"的对照审视**——仲裁审两方冲突，医生审一方质量，prompt 组装、闭集输出、内容哈希缓存、失败隔离全部同构复用。准则包（A4 内容任务）第一次有了第二个消费方，"沉淀准则→资产变好"闭环成立。

## 目标

| # | 目标 | 用户可见结果 |
|---|------|-------------|
| G1 | 单资产诊断 | 资产卡（skill/agent/rule/identity/command）上「资产医生」按钮 → 体检报告：结论徽标 + 逐条问题（严重度/引用准则/怎么改） |
| G2 | 一键修复 | 可修复问题生成**改写草案**（可编辑）；确认预览中展示修改前后对照，确认后写入库（覆盖前保留旧版可回滚） |
| G3 | 修复后分发 | 写库成功的确认流里勾「同步分发」→ 复用 swap 单资产预览-确认-备份-执行链路，把新版投放到已安装该资产的每个工具 |
| G4 | 批量体检 | 类别页「全部体检」：并发逐条诊断、失败隔离、报告清单按严重度排序，点条目看单份报告 |
| G5 | 确定性零成本项 | frontmatter 缺字段等可机械判定的问题由确定性检查直接给出（不调模型），模型只审语义质量 |

## 非目标

- ❌ **无确认的自动修复/自动分发**：模型永不悄悄改资产；"一键"指把确认动作收敛为一次点击（草案预览+目标工具清单同屏），不是跳过确认（决策 D2）
- ❌ 定时/事件触发的自动体检（先手动；"资产变更后自动提示体检"留待评估）
- ❌ mcp 服务器配置的模型诊断（JSON 结构正确性已有确定性校验；语义调优需求弱，留后）
- ❌ 准则自学习（"诊断中发现的新问题模式自动固化为准则"——先由维护者手工沉淀）
- ❌ 诊断分数体系 / 历史趋势报表
- ❌ 环境（未入库）技能的诊断入口——医生只服务资产侧，与 asset-first-view 口径一致

## 关键决策

- **D1 同构复用仲裁基建**：诊断引擎 = `assembleCriteriaPromptBlock(enabled, targetCategory)` + LlmClient DI + sha256(内容+准则集哈希+model) 缓存 + 闭集 JSON 解析，全部来自 add-llm-conflict-arbitration Phase B，不另建一套。
- **D2 修复链路映射到既有写路径**：草案采纳 → 走 Hub 文件既有写入（identity/rule/mcp 走 hub-files 写、skill 走 skill-write、agent 走 agent-write），覆盖前把旧版存入备份区（复用 swap 备份语义）；分发一律经 swap 预览-确认-回滚骨架，**医生不自建第二条分发通道**。
- **D3 报告闭集结构**：`overall ∈ healthy / needs-attention / at-risk`；issue 四要素（severity ∈ high/medium/low、criterion 引用、finding、suggestion）+ `fixable` 布尔；非法输出失败隔离（与仲裁同规则），最坏体验 = 没有诊断。
- **D4 两段式确认收敛为一屏**：「应用修复」确认对话框同屏展示 ①修改前后 diff ②将分发的目标工具清单（默认全部已安装工具，可逐个取消勾选）③"分发仍会生成 swap 预览"说明；一次点击 = 写库 + 逐工具 swap 执行；任何一步失败如实报告并给出回滚入口。
- **D5 批量体检预算护栏**：批量 = 逐条独立 LLM 调用，发起前显示"将调用 N 次模型（已缓存 M 条不消耗）"，N>50 时需二次确认；并发池与缓存策略沿用分类管线（concurrency 4）。
- **D6 确定性优先**：先跑机械检查（frontmatter 必填、正文长度阈值、description 空缺等），命中即直接入报告并标 `fixable` 可生成的走草案；机械项不再进模型，省 token 且结果稳定。

## 影响面

- `src/core/`：新文件 `doctor.ts`（诊断纯逻辑 + 确定性检查 + 草案生成）；criteria/arbitration 基建小幅抽公共（prompt 组装调用、缓存读写模式）
- `src/server/`：路由 `routes/doctor.ts`（diagnose / fix-draft / apply + 批量）；分发执行复用 swap 路由能力（内部调用或前端二段请求）
- `web/`：资产详情/卡片接入「资产医生」；体检报告组件；修复确认对话框（diff + 分发勾选）；类别页「全部体检」
- 文档：taxonomy 元资产层补"准则的第二个消费方"；PRIVACY.md 诊断数据流出说明
- 不动：扫描器、同步引擎、swap 执行链路内部逻辑（仅被复用）

## 回滚

诊断/报告（只读）与修复分发（写）分 commit：revert 写链路 commit 后医生退化为"只读体检"；revert 整个变更退回手动管理，准则元资产不受影响（属前一变更）。
