# skill-catalog.spec.md：技能分类全貌、子集诊断与批量分发

> capability: 技能全貌看板、双维分类与分类依据、展开筛选、单个/子集诊断、结果聚合、批量分发、降级与空态
> 变更: refactor-skill-catalog（S 级）| 依赖契约: `../api-contract.ts`
> 沿用决策: 分类零模型优先（proposal D1）、三分组只作视图（D2）、看板与列表同源（D3）、
> 批量只诊断不修复（D4，承 `add-asset-doctor` fix-and-distribute Scenario 8）、
> 分发复用 swap 单资产范围（D5）、成本未知不发起（D6）、问题数只来自上次体检摘要（D7）

## 定义

- **技能资产**：已在我的库（`inLibrary === true`）或出处为自建（`provenance === 'self'`）的技能。
- **环境技能**：未入库且出处为市场安装 / 插件自带 / 官方内置 / GitHub 源的技能；不是资产，默认不公示。
- **全貌看板**：技能页顶部按两个维度汇总的分类总览——来源维度、用途维度。
- **来源分组（三分法视图）**：自建 = 自建出处；平台自带 = 官方内置 + 插件自带；导入 = 市场安装 + GitHub 源。
  这是看板上的聚合视图；条目自身的出处仍以五值为准，详情照旧显示细分出处。
- **用途分类**：编码开发 / 文档写作 / 浏览器自动化 / 数据处理 / DevOps 部署 / AI 集成 / 设计创意 / 工作流自动化 / 其他。
- **分类依据**：这个技能为什么被归到当前来源与用途，取值 目录判定 / 元数据 / 关键词 / AI / 手动。
- **上次体检摘要**：某技能最近一次诊断的结论与各级问题数、体检时间、当时正文指纹。
- **诊断预估**：发起前展示的「共多少项、多少条命中缓存、实际将调用多少次模型」。
- **影响清单**：批量分发前展示「哪些工具、各写多少个文件、其中新增/覆盖/冲突/跳过各多少」。
- **本次所选**：用户在技能页勾选的技能集合，或某个分类行下的全部技能。

## Requirement 1：全貌看板（R1）

### Scenario 1.1 打开技能页先看到全貌

- **Given** 我的库里有若干技能，来源覆盖自建、官方内置、插件自带、市场安装
- **When** 用户打开技能页
- **Then** 顶部展示全貌看板：资产技能总数；「按来源」三组（自建 / 平台自带 / 导入）各显示数量与最近更新时间；「按用途」九类各显示数量；看板合计与下方列表总数一致

### Scenario 1.2 问题数来自上次体检，未体检不显示 0

- **Given** 一部分技能体检过、一部分从未体检
- **When** 用户查看看板与技能卡
- **Then** 体检过的显示「有风险 / 需关注 / 健康」及问题数；从未体检的显示「未体检」，不得显示「0 个问题」

### Scenario 1.3 内容变化后摘要标为已过期

- **Given** 某技能上次体检为「需关注」，之后 SKILL.md 正文被编辑
- **When** 用户再次打开看板
- **Then** 该技能的摘要标「体检结果已过期」且不计入问题数合计；卡片仍可见上次结论与时间，但明确标注已过期

### Scenario 1.4 看板随筛选联动，失败不拖垮列表

- **Given** 用户选择了「我的库 × 某用途」
- **When** 看板与列表同时渲染
- **Then** 看板数字按当前筛选重算，且与列表条数一致；若统计接口失败，看板局部显示「统计暂不可用」，下方技能列表仍正常加载

### Scenario 1.5 最近更新可核对

- **Given** 三个来源分组都有技能
- **When** 用户查看分组行
- **Then** 每组显示该组最近一次更新时间（精确到日）；点「最近更新」可把组内技能按更新时间倒序展开

## Requirement 2：分类维度与分类依据（R2）

### Scenario 2.1 来源三分组不改变条目出处

- **Given** 某技能出自官方内置，另一条出自插件自带
- **When** 用户在看板「按来源」查看
- **Then** 二者都计入「平台自带」；分别展开后，卡片/详情仍显示「官方内置 · 工具名」与「插件自带」，不合并成同一个标签

### Scenario 2.2 目录判定优先于其他信号

- **Given** 某技能正文里写了「从市场安装」但文件位于自建技能目录
- **When** 系统判定来源
- **Then** 按目录判定为自建；正文措辞不改变来源

### Scenario 2.3 元数据与关键词只做兜底，且依据可查

- **Given** 某库内技能带有「来自市场安装」的收藏溯源信息；另有某技能无任何溯源信息
- **When** 用户查看这两条的分类依据
- **Then** 前者显示「元数据（收藏溯源）」；后者显示「关键词」或「手动」，不得显示为「目录」；详情中可看到当前用途分类的依据来源

### Scenario 2.4 AI 归类只显式触发且先标价

- **Given** 一部分技能已手动分类、一部分有 AI 缓存、一部分仍靠关键词
- **When** 用户查看「AI 归类」入口
- **Then** 入口显示「待分类 N（缓存命中 M，需调用 K）」；只有 N > 0 时按钮可用；未配置 AI 端点时显示配置引导且不发起任何调用；点击后逐条结果注明「手动已跳过 / 缓存命中 / 实际调用」

### Scenario 2.5 无法判定来源不冒充官方内置

- **Given** 某技能文件的目录不属于任何已知来源根，且无溯源元数据
- **When** 系统判定来源
- **Then** 该技能归入「平台自带」并标注「来源待确认」，不得显示为「官方内置」；看板上「来源待确认」有独立计数

## Requirement 3：展开与筛选（R3）

### Scenario 3.1 单分类展开与收起

- **Given** 看板「按来源」显示三组
- **When** 用户点击「平台自带」这一行
- **Then** 只展开该组技能（按当前排序），其余组保持收起；再次点击同一行收起；展开状态不影响看板数字

### Scenario 3.2 搜索自动展开命中的分组

- **Given** 用户搜索一个只存在于「导入」组的技能名
- **When** 搜索结果返回
- **Then** 命中的分组自动展开并显示「命中 X 个」，无命中的分组隐藏；清空搜索后回到之前的展开状态

### Scenario 3.3 三个筛选维度可叠加

- **Given** 用户在「按来源」维度下选择了「导入」，又把库状态切到「我的库」，并输入搜索词
- **When** 列表刷新
- **Then** 结果为三条件交集；各分类计数排除自身维度、随其余条件联动（与现有分面计数口径一致）；筛选变化后回到第 1 页

### Scenario 3.4 空分组与全空列表

- **Given** 某个来源分组下没有任何技能
- **When** 看板渲染
- **Then** 该分组显示数量 0 且不可展开，不占大块空白；若所有分组都为空，列表区显示空态与「扫描本机技能 / 收藏技能」下一步入口

## Requirement 4：单个与子集诊断（R4）

### Scenario 4.1 单技能诊断入口保持可用

- **Given** 某技能已在我的库
- **When** 用户打开该技能详情并点「资产医生」
- **Then** 正常产出报告（健康 / 需关注 / 有风险 + 逐条问题），行为与现状一致

### Scenario 4.2 勾选后批量诊断，先看预估

- **Given** 用户勾选了 12 个库内技能，其中 3 个已有未过期的体检摘要
- **When** 用户点「诊断选中 12 个」
- **Then** 发起前显示「共 12 项，3 条命中缓存不消耗，将调用 9 次模型」；用户确认后才开始；执行期显示进度与当前技能名

### Scenario 4.3 按分类发起诊断

- **Given** 某来源分组下有 40 个技能，其中 8 个未入库
- **When** 用户在该分组行点「诊断本类」
- **Then** 预估的缓存命中与实际调用数只按 32 个可诊断技能计算，并明确列出「8 个未入库，不可诊断」；不得静默丢弃或直接报错

### Scenario 4.4 成本未知或超限时禁止发起

- **Given** 预估接口失败、预估结果缺少调用次数、或用户选择超过单次上限
- **When** 用户尝试发起
- **Then** 发起按钮禁用并显示原因（「无法估算成本，暂不能发起」/「一次最多 100 个，请分批」）；不得在成本未知时调用任何模型

### Scenario 4.5 未配置 AI 端点与未入库技能

- **Given** 用户未配置 AI 端点，且所选技能中混有未入库自建技能
- **When** 打开诊断预估
- **Then** 显示「将只跑机械检查，零模型调用」，并逐条列出未入库技能与原因「收藏后可诊断」；发起按钮仍可用（机械检查照常），但界面明确标注「本次不含语义诊断」

### Scenario 4.6 诊断预算二次确认

- **Given** 预估实际调用 80 次
- **When** 用户点发起
- **Then** 弹出二次确认，说明调用规模与数据边界（仅技能正文与适用准则发往用户自配端点），用户确认后才执行

## Requirement 5：结果聚合（R5）

### Scenario 5.1 按技能分组、按严重度排序

- **Given** 一次批量诊断完成，其中 1 个技能有风险、2 个需关注、3 个健康、1 个失败
- **When** 结果展示
- **Then** 分组顺序为 有风险 → 需关注 → 健康 → 失败；每个技能行显示结论、高/中/低问题数、体检时间；同一技能内问题按严重度从高到低排列

### Scenario 5.2 从聚合结果进入单点修复

- **Given** 聚合结果中某技能有一条可修复的高严重度问题
- **When** 用户点「去修复」
- **Then** 打开该技能详情并定位到资产医生；修复仍走单点确认（生成草案 → 预览 diff → 备份 → 写库 → 可选分发）；聚合页不提供「全部修复」

### Scenario 5.3 部分失败可见、可只重试失败项

- **Given** 10 个技能中有 2 个因网络或输出非法失败
- **When** 结果展示
- **Then** 失败行显示原因原文；顶部汇总「成功 8 · 失败 2」；提供「重试失败项（2）」且只重跑这 2 个，不重复消耗已成功项

### Scenario 5.4 结果落为摘要并披露口径

- **Given** 批量诊断完成
- **When** 用户返回看板
- **Then** 被诊断技能的摘要已更新，问题数与时间可查；结果面板底部显示本次使用的规则集版本、模型名与生成时间；未参与语义诊断时明确标注「仅机械检查」

## Requirement 6：批量分发（R6）

### Scenario 6.1 分发前必须看影响清单

- **Given** 用户勾选 3 个库内技能，本机装有 4 个工具
- **When** 用户点「分发选中 3 个」
- **Then** 先展示影响清单：每个工具一行，显示是否安装、是否支持技能类别、将写入文件数（新增/覆盖）、冲突数、跳过原因；底部显示受影响文件总数，此时尚未写入任何文件

### Scenario 6.2 默认目标保守勾选 + 二次确认

- **Given** 3 个技能中，2 个已存在于工具 A，3 个都未投放工具 B
- **When** 影响清单打开
- **Then** 默认只勾选「已存在该技能」的工具（工具 A）；工具 B 需用户显式勾选；确认区说明「覆盖前会备份，可在结果页回滚本次分发」；不勾任何工具时确认按钮禁用

### Scenario 6.3 执行结果逐条如实报告

- **Given** 用户确认分发到工具 A 与 B
- **When** 执行完成
- **Then** 结果按「技能 × 工具」逐条显示 已写入 / 跳过（原因）/ 失败（原因）；某工具失败不影响其他工具；顶部汇总写入、跳过、失败数量；状态刷新为真实分发结果

### Scenario 6.4 回滚本次分发

- **Given** 本次分发至少有一个工具写入成功
- **When** 用户点「回滚本次分发」
- **Then** 按工具恢复分发前的备份文件；逐工具显示恢复结果；回滚失败的工具给出原因；库内技能内容全程未变

### Scenario 6.5 不可分发的选择要说明

- **Given** 所选技能中有未入库技能，或某工具不支持技能类别
- **When** 打开影响清单
- **Then** 未入库技能标注「未入库，不可分发」且不计入文件数；不支持的工具整行标灰并说明原因；不得静默排除

## Requirement 7：降级与空态（R7）

### Scenario 7.1 一个技能都没有

- **Given** 本机与我的库都没有任何技能
- **When** 打开技能页
- **Then** 看板显示「暂无技能」；列表区给出「扫描本机技能」「新建技能」两个下一步；不显示空的分组骨架

### Scenario 7.2 有技能但全部未入库

- **Given** 本机有 50 个环境技能，我的库为空
- **When** 打开技能页
- **Then** 看板显示资产口径为 0，底部折叠入口显示「本机技能环境 50」；「诊断选中」「分发选中」均禁用并说明「先收藏到我的库」

### Scenario 7.3 未配置 AI 端点

- **Given** 用户未配置 baseUrl / apiKey / model
- **When** 查看 AI 归类与诊断入口
- **Then** AI 归类显示配置引导、零调用；诊断预估显示「仅机械检查」；两者都提供跳转到 AI 配置的入口，不报错、不阻塞机械检查

### Scenario 7.4 批量超限

- **Given** 用户一次勾选 150 个技能
- **When** 点诊断或分发
- **Then** 提示「一次最多 100 个，请分批」并给出当前选择数；已选集合保留，用户可取消部分后继续；不得截断后静默执行

### Scenario 7.5 依赖接口失败

- **Given** 看板统计、诊断预估、分发影响清单任一接口失败
- **When** 页面渲染
- **Then** 仅对应区域显示失败原因与「重试」，其余区域正常；依赖该数据的按钮禁用；不得用 0 或旧数据冒充成功

### Scenario 7.6 部分工具状态未知

- **Given** 分发影响清单生成时，某工具检测失败
- **When** 展示清单
- **Then** 该工具标「状态暂不可用」且不可勾选；其余工具照常可选；确认区提示「部分工具状态未知」，不推断为未安装

## 非目标（Non-goals）

- 不提供批量修复、批量改写、批量删除
- 不改变五值出处的判定规则与库状态语义
- 不为环境技能提供诊断/分发入口
- 不做技能评分、使用频率、趋势图
- 不引入新的模型供应商或云端同步
