# proposal: refactor-skill-catalog（技能分类全貌 → 子集批量诊断 → 批量分发）

> 级别：S（技能页结构重构 + 新聚合 API + 批量分发写链路整合）
> 状态：已批准（2026-11-15），待开工
> 依赖：add-asset-doctor（诊断/预算估算/修复）、add-diagnosis-rules（规则集与证据）、
> add-skill-ai-classification（AI 归类的缓存与成本模型）、enable-tool-hot-swap（单资产范围分发）

---

## 为什么做（维护者原话）

> 「技能收纳了很多：自建 + 平台自带，平铺无法看全貌」
> 「要先分门别类看全貌，再按单个或类别展开诊断，再分发」
> 「这条流水线也要跑通」
> 「现状：技能不提供资产医生」

整理成一句话：**技能页缺一条「看全貌 → 选子集 → 诊断 → 分发」的完整流水线**；
现在能看单卡、能全量体检、能逐条改，但四步之间没有连贯的入口与结果回流。

## 现状核对（写 spec 前逐文件读码结论）

先纠正一条与记忆不符的前提：**单个技能已经有资产医生**。

| 诉求 | 现状 | 证据 |
|------|------|------|
| 技能单点诊断 | ✅ 已有：库内技能详情底部渲染医生面板 | `web/src/components/skills/SkillDetail.tsx`（`<DiagnosisPanel kind="skill" ... />`） |
| 技能全量体检 | ✅ 已有：页头「全部体检」，含预算预估、>50 次二次确认、并发 4、失败隔离、按结论排序 | `web/src/components/doctor/SkillsCheckupSection.tsx`、`BatchCheckup.tsx` |
| 预估算成本 | ⚠️ 仅按类别全量：`GET /api/doctor/estimate?category=skill` 统计 Hub 内全部技能，无法对「勾选子集 / 某一分类」估算 | `src/server/routes/doctor.ts` |
| 来源分类 | ✅ 已有五值 MECE：自建 / 市场安装 / 插件自带 / 官方内置 / GitHub 源；库状态独立轴 | `src/core/skill-provenance.ts`、`refactor-skill-origin-taxonomy` |
| 用途分类 | ✅ 已有九职能 + 三档分类来源（手动 > AI > 关键词） | `src/core/skills-inventory.ts`、`skill-ai-classification.ts` |
| 展开与筛选 | ✅ 已有维度切换、库状态三档、搜索、来源/职能 chips、分组展示 | `SkillsView.tsx`、`SkillsToolbar.tsx` |
| 按分类/勾选诊断 | ❌ 批量体检只有「全部库内技能」，不能按勾选或单个分类发起 | `BatchCheckup.tsx`（`getAssets` 返回全量） |
| 问题数进入全貌 | ❌ 列表/分组无「问题数、最近更新、上次体检时间」；报告缓存按内容哈希存，无法直接映射到技能 | `doctor-cache.ts`、`SkillInfo` 无 `lastModifiedAt` |
| 批量分发 | ❌ 批量条只有 AI 分类 / 收藏 / 改职能；分发只在单技能详情（且 `runSync` 是整库同步，不是所选子集） | `SkillsBatchBar.tsx`、`SyncDistribute.tsx`、`src/server/routes/sync.ts` |
| 结果回流 | ⚠️ 批量体检结果只在本次会话内存里，关闭即失；不能从聚合清单跳到单条修复 | `BatchCheckup.tsx` |
| 分发底层能力 | ✅ swap 已支持 `onlyHubRelativePaths` 单资产范围执行，可复用到子集批量分发 | `src/core/swap-types.ts`、`src/server/lib/doctor-dispatch.ts` |

结论：**不是从零做，而是把已有零件接成流水线**，并补三块真缺口——
① 全貌看板（问题数 / 最近更新 / 分类汇总）；② 针对子集的诊断预估与发起；③ 批量分发。

## 目标

| # | 目标 | 用户可见结果 |
|---|------|-------------|
| G1 | 全貌看板 | 打开技能页先看到「按来源 / 按用途」两组分类，每组显示数量、最近更新、问题数；点一行展开该组技能 |
| G2 | 分类零模型优先 | 来源按目录判定、用途按元数据/关键词判定；「分类依据」在卡片/详情可查；AI 归类只在显式点击时发生并标价 |
| G3 | 子集诊断 | 勾选若干技能或点某个分类行「诊断本类」→ 发起前显示「共 N 项，缓存命中 M，将调用 K 次模型」 |
| G4 | 结果聚合 | 诊断完成按技能分组、按严重度排序；每条问题可一键跳到该技能详情继续单点修复（批量不提供一键修复） |
| G5 | 批量分发 | 勾选技能 → 「分发选中」→ 影响清单（工具 × 文件）→ 二次确认 → 执行 → 逐条结果 + 回滚入口 |
| G6 | 诚实降级 | 无 AI Key、估算失败、超上限、部分失败、无技能、全部未入库，均有明确文案与下一步，不静默、不编造 |

## 非目标

- ❌ 批量修复：延续 `add-asset-doctor` fix-and-distribute Scenario 8，批量只到诊断；修复必须逐条单点确认
- ❌ 重做来源五值枚举：本次只在五值之上加「自建 / 平台自带 / 导入」**分组视图**，不改真值轴
- ❌ 新增模型供应商 / 云端服务：仍用用户自配 OpenAI 兼容端点，诊断与分发均本机
- ❌ 技能价值评分、使用频率统计（无数据源）
- ❌ 改动扫描来源根、去重规则、收藏/写库逻辑
- ❌ 自动/定时体检、诊断历史趋势报表
- ❌ 跨类别批量：本变更只做技能模块内的分类与批量（技能内多选、按分类批量）；跨资产类别的批量统一归质量中心（refactor-governance-center），两层数字必须同源

## 关键决策

- **D1 分类零模型优先**：来源 = 目录前缀判定（已有 `classifyOrigin`）；用途 = 手动覆盖 > AI 缓存 > 元数据/关键词（已有顺序）。
  AI 归类只作**显式兜底**：按钮上标「待分类 N（缓存命中 M，需调用 K）」，成本不为零就不自动跑。
- **D2 三分组是视图不是新轴**：「自建 = self」「平台自带 = builtin + plugin」「导入 = marketplace + github」，
  后端真值仍是五值 MECE；分组只在聚合层派生，避免重演「分类混维度」的老问题。
- **D3 看板数字必须与列表同源**：看板计数复用现有 `countByProvenance / countByFunction / countByStatus` 口径与筛选状态，
  不允许前端二次估算；两组数字对不上就是 bug。
- **D4 批量诊断只做诊断**：聚合清单提供「去修复」跳转，不提供「全部修复」；修复仍走 `doctor-fix` 单点确认。
- **D5 批量分发复用 swap 单资产范围**：逐工具预览后以 `onlyHubRelativePaths` 限定本次所选技能，
  不自建第二条分发通道；覆盖前由 swap 备份，回滚走 `POST /api/swap/rollback`。
- **D6 成本未知不得发起**：预估接口失败、预估字段缺失、选择超出上限时，发起按钮禁用并给出原因；
  禁止「先跑起来再说」。
- **D7 问题数只来自上次体检摘要**：新增本地摘要存储（技能相对路径 + 内容哈希 + 结论 + 各级问题数 + 时间）；
  内容哈希不一致即标「已过期」并不计入问题数，未体检显示「未体检」而不是 0。

## 影响面

| 层 | 变更 |
|----|------|
| `src/core/` | 新增技能目录聚合纯逻辑（分组/最近更新/摘要合并）；`SkillFs.dirMtime` 接出主文件修改时间；新增诊断摘要存储纯逻辑 |
| `src/server/` | `routes/skills.ts` 增 `GET /catalog`、`POST /diagnose/estimate`、`PUT /diagnosis-summary`；新增 `routes/skill-distribution.ts`（preview / execute），内部复用 `SwapEngine` 与 `onlyHubRelativePaths` |
| `web/` | 技能页拆为「看板 + 分组列表 + 详情」；`SkillCard` 增最近更新/问题数；批量条增「诊断选中 / 分发选中」；新增聚合结果面板与分发确认对话框 |
| 复用不动 | `doctor.ts` 单资产诊断、规则集、AI 分类缓存、swap 执行与备份、分发索引 |
| 文档 | 无新增隐私说明（诊断/分发数据边界不变）；`PRIVACY.md` 无需改 |

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 看板与列表两套数字漂移 | D3：同一接口口径 + 组件测试锁定「看板合计 = 列表 total」 |
| 批量分发一次写多个工具，误操作面大 | 影响清单 + 二次确认 + 默认只勾「已含该技能的工具」+ 逐工具 swapId 可回滚 |
| 摘要存储成为第二真相 | 摘要只做展示，不参与诊断结论；哈希不符即过期；清空摘要不影响任何写链路 |
| 技能卡片信息过载 | 卡面最多 2 个常驻徽章（现有规范），问题数用单点标记，详情才展开 |
| 选择中混入环境技能导致 403 | 发起前客户端过滤并在预估响应回传 `unDiagnosable` 明细，禁止静默丢弃 |

## 回滚

- 看板、目录聚合、摘要：纯读 + 独立存储，revert 即回到现有平铺列表。
- 子集诊断：只新增预估接口，执行仍走既有单资产诊断；revert 后「全部体检」不受影响。
- 批量分发：独立路由与对话框，revert 后单技能 `SyncDistribute` 与 doctor apply 分发不受影响。

## Definition of Done

1. spec 全部 Scenario 可手工复验；前端核心分支有组件测试
2. `npm test` 全绿、`npm run typecheck` 无错、后端 `npm run build` 与前端 `vite build` 成功
3. 批量分发在临时 Hub + Fake 适配器下测过：部分失败、冲突不静默覆盖、回滚可用
4. 无新增 `any` / `@ts-ignore`；`node scripts/privacy-check.mjs` 退出码 0

## 已拍板（2026-11-15，均按推荐批准）

1. **未入库的自建技能**：本期维持「先收藏后诊断」，预估里明确列出未入库项与原因；若要放开，需单独评估写链路影响。
2. **批量诊断上限**：单次最多选 100 个技能；预计实际调用 > 50 次需二次确认；单次实际调用硬上限 200 次，超出要求分批。
3. **批量分发默认勾选**：默认只勾「目标工具里已存在该技能」的工具（等价覆盖升级）；新工具首次投放需用户显式勾选。
