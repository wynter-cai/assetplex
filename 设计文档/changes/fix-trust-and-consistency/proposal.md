# proposal: fix-trust-and-consistency（阶段 0：止血与可信）

> 级别：M（跨 core / server / web 的一致性修复，无新能力模块）
> 输入依据：`设计文档/assetplex-project-diagnosis.md` 第六节 P0 + 第七节 T1 + 第八节 D4/D5/D7
> 状态：待维护者审核
> 前置：无。本变更不依赖阶段 1（记忆/命令入库）与阶段 3（README/docs 重写）

## 为什么做（背景）

新定位把产品从「同步工具」抬升为「AI 资产中心」，两个承诺随之变成契约：

1. 「跨工具无缝迁移」→ 资产**是否真的分发出去了**必须可查、可解释；
2. 「统一管理全部资产」→ 全站对「有多少资产、叫什么、属于哪类」只能有一套口径与一套词。

诊断实测发现这两条都未成立：资产库 187 项全部显示「未分发」，连接页同时显示「已同步资产 · 技能 182」；同一技能在五个位置有五个数字；同一概念有库/我的库/入库/Hub 四种叫法。**在修好这些之前，任何新功能都会被人一眼看穿。** 本变更是新定位的地基工程，不新增任何资产类别。

## 目标

| # | 目标 | 用户可见结果 |
|---|---|---|
| G1 | 分发状态真实化 | 资产卡展示每个已启用工具的真实状态（已同步 / 待同步 / 冲突 / 未启用 / 未安装），拒绝占位值 |
| G2 | 计数口径唯一 | 首页、资产库、连接、技能、切换五处数字来自同一聚合源，且每处标注口径名 |
| G3 | 资产类别单一真相 | 后端一份声明式清单，前端导航与资产库由它派生；新增类别只改配置 |
| G4 | 「全部资产」可用 | 类别/分发状态筛选 + 分页；技能资产按技能名展示，内部元数据文件不再冒充资产 |
| G5 | 词表收敛 | 「我的库 / 收藏 / 同步 / 切换」四词定死，四套同义词从用户可见文案中消失 |
| G6 | 危险动作有护栏 | 执行同步前显式显示影响范围；未选目标不可执行；预览开关语义明确 |
| G7 | 展示卫生 | 版本号单一来源、旧品牌名收敛、死链与死命令清理 |

## 非目标

- ❌ 新增资产类别（记忆 / 命令 / 偏好进资产中心）——属阶段 1，本变更只消除「能搬不能看」的**误导性表述**，不假装已管理
- ❌ 智能体可写、legacy 路由下线——属阶段 1
- ❌ 最佳实践层（模板/校验/准则包/健康报告）——属阶段 2
- ❌ README 与 docs 内容重写、SEO 技术项、Gitee 镜像——属阶段 3
- ❌ 分发状态的历史趋势、漂移检测、自动修复
- ❌ 新增写通道：本变更的所有状态计算均为**只读**

## 关键决策

- **D1 状态闭集不扩张**：沿用既有 `synced / pending / conflict / not_enabled / not_installed`（`src/core/assets.ts`）。「目标不存在」归 `pending`（待同步），「内容不一致」归 `conflict`。理由：前端圆点语义与文案已按此设计，扩张枚举会让旧页面出现空状态。
- **D2 状态实时计算 + 短缓存**：新增只读索引服务，遍历「已启用且已安装」的工具，按适配器策略判定每个库内资产的状态；结果缓存 30 秒，`?refresh=1` 强刷，sync / swap / doctor apply 成功后主动失效。理由：资产量级（~200）× 工具数（5）的 stat 成本可接受，但列表页会并发请求，必须缓存。
- **D3 项目级工具不进单资产索引，改在项目维度表达**：Qoder 的用户级目录（`~/.qoder-cn` / `~/.qoder`）**仅用于安装检测**，真实分发目标是 `hub.toml` 的 `projectTargets`——N 个项目 × 规则 / 技能 / AGENTS.md，状态天然是「资产 × 项目」二维。一维圆点装不下：全绿会掩盖未同步项目，全灰会否认已同步项目，新增 `not_supported` 既扩张闭集又误导（Qoder 是支持的，只是配置形态不同）。故索引不产生 Qoder 条目、`toolSynced` 不含它，界面固定一句「按项目分发，请在项目页查看（已接入 N 个项目）」。二维矩阵视图留到阶段 2，不用单资产状态凑。 
- **D4 计数四口径**：`library`（我的库：Hub 内资产入口文件数）、`environment`（本机环境：工具目录中存在但未入库）、`pendingImport`（可收藏：扫描到且不在库）、`toolSynced`（已同步到某工具：由 D2 索引聚合）。四者在 API 中显式命名，界面必须带口径名，禁止裸数字。
- **D5 类别清单后置为 API**：后端新增 `src/core/asset-categories.ts` 作为唯一声明源（code / label / description / hubDir / external / syncable / doctorSupported），`GET /api/asset-categories` 暴露；前端保留内置 fallback 常量用于首屏渲染，接口返回后以接口为准。理由：纯动态会让首屏侧栏闪烁；纯静态又会继续漂移。
- **D6 分页在客户端**：`/api/assets` 契约不动，前端 50/页。理由：库内资产上限在千级，服务端分页收益低但会牵动 6 处调用点。
- **D7 同步页改为「必须显式选目标」**：未选目标时执行按钮禁用，并在按钮旁写明「请先选择目标工具」；原「不选=全部已启用」的隐式行为下线。理由：隐式全量写入与「零惊讶」原则冲突。
- **D8 版本号构建期注入**：vite define 注入 `__APP_VERSION__`，侧栏与设置页共用；`assetplex --version` 读同一来源。禁止在 UI 里写字面量。

## 影响面

- `src/core/`：新增 `asset-categories.ts`（声明源）、`distribution-index.ts`（只读状态计算 + 缓存）；`assets.ts` 增加入口文件归一与内部文件过滤
- `src/server/`：新增 `GET /api/asset-categories`、`GET /api/distributions`；`/api/hub/overview` 增加 `counts` 四口径，`assetStats` 保留兼容
- `web/`：`config/asset-categories.ts` 改为「fallback + 接口覆盖」；`Sidebar`、`AssetSnapshot`、`Vault`、`AssetCard`、`Connections`、`Sync`、`Settings` 接入新数据源；新增筛选与分页控件
- `docs/` / 根文档：版本号与旧品牌名清理、死链修复、`profile learn` 提示改为「即将支持」
- 不动：适配器接口、同步引擎执行路径、swap 执行链路、导入向导

## 回滚

三个 commit 边界可独立 revert：① core + server（状态与类别）②web（消费新数据源）③docs 卫生。revert ② 后旧界面仍可运行（旧字段保留兼容）；revert ① 只影响新接口，既有页面回到占位状态但功能不坏。
