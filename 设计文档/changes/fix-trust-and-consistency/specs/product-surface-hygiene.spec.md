# spec: product-surface-hygiene（词表 · 版本 · 危险动作 · 展示卫生）

> capability：用户可见文案与危险动作的确定性
> 关联：proposal D7 / D8、诊断 P0-4 / P0-5 / D4-D7
> 消费者：全站文案、侧栏与设置页、同步页、切换页、CLI 帮助与模板、公开文档

## 为什么需要这份 spec

同一条动作有四套叫法、同一个版本号有三处不同取值、最危险的写入动作在 0 选中时仍可点击、模板里写给用户的命令在 CLI 里不存在。这些不是审美问题，它们是**用户判断"我按了什么、发生了什么"的依据**。

## 词表（本 spec 强制，其他表述一律禁止）

| 词 | 唯一含义 | 允许出现的位置 |
|---|---|---|
| **我的库** | 已收藏进 Hub 的资产集合 | 导航、页头、空态、计数口径名 |
| **收藏** | 把工具目录里的资产收进我的库 | 按钮、成功提示、向导步骤名 |
| **同步** | 把库内资产写到各工具目录 | 导航、按钮、结果文案 |
| **切换** | 以某目标工具为边界，整体预览-执行-校验-可回滚 | 导航、按钮、结果文案 |

禁用词（用户可见文案中不得出现）：`保险箱`、`沉淀`、`分发`、`分发同步`、`投放`、`入库`（作为动作）、`Hub`（作为"库"的同义表达）、`未分发`。

> 例外：后端字段值、API 路径、代码标识不受本表约束；界面展示层负责映射。

## Scenario 1 — 禁用词守卫

- **Given** 全站页面已渲染
- **When** 运行界面术语走查测试（覆盖导航、页头、空态、按钮、toast、确认框）
- **Then** 禁用词命中数为 0
- **And** 任一页面出现禁用词时该测试失败并打印命中页面与文案

## Scenario 2 — 版本号单一来源

- **Given** `package.json` 的 version 为 `0.1.0`
- **When** 查看侧栏底部、设置页版本字段、并执行 `assetplex --version`
- **Then** 三处完全一致，均显示 `0.1.0`
- **And** 界面中不存在任何硬编码的版本字符串

## Scenario 3 — 未选目标不可执行

- **Given** 同步页初始状态，未选择任何目标工具
- **When** 查看「执行同步」按钮
- **Then** 按钮为禁用态，紧邻文案为「请先选择目标工具」
- **And** 不存在"未选择即同步到全部已启用工具"的隐式行为
- **And** 页面不再同时出现"从左侧选择目标"与"未选择将同步全部"两句互斥文案

## Scenario 4 — 执行前必须显示影响范围

- **Given** 已选择 2 个已启用工具，预览结果为 12 项变更、3 项冲突
- **When** 查看主操作按钮与其邻接区域
- **Then** 显示「将影响 2 个工具 · 12 项变更 · 3 项冲突」
- **And** 变更与冲突为 0 时，主操作按钮禁用并提示「没有需要同步的内容」

## Scenario 5 — 预览开关可感知、可解释

- **Given** 同步页存在「预览模式」开关
- **When** 用户以键盘或读屏聚焦该开关
- **Then** 开关具备可访问名称（「预览模式」）与角色说明
- **And** 开关状态变化时，页面出现明确差异文案：「预览模式：只计算不写入」/「执行模式：将写入文件」
- **And** 预览模式下主操作按钮文案为「生成预览」而非「执行同步」

## Scenario 6 — 未安装目标可识别且给出口

- **Given** 同步页列出未安装的工具
- **When** 查看该目标卡
- **Then** 卡片呈现禁用态（不可勾选、`aria-disabled="true"`），并给出「未安装」标签
- **And** 卡片内含一句引导：「安装后重新扫描即可启用」

## Scenario 7 — 项目级工具必须自解释

- **Given** 切换页与连接页列出项目级策略工具
- **When** 查看该工具的卡片
- **Then** 卡片展示其能力说明（至少一句「项目级：在项目内分发」）
- **And** 不存在"只有名字、没有任何能力标签"的工具卡
- **And** 未配置任何项目时，卡片显示「尚未选择项目」+「去配置」入口，**而不是把六类能力全标成「不支持」**
- **And** 支持矩阵必须来自工具能力本身，不得由「当前配置下 `resolveHubItems()` 返回空」反推（现存缺陷：`buildSupportMatrix()` 正是这么算的）

## Scenario 8 — 不得提示不存在的命令

- **Given** CLI 当前只提供 `init` / `doctor` / `sync` / `ui`
- **When** 用户阅读 `init` 生成的模板文件或适配器的提示信息
- **Then** 不出现任何未实现的命令名
- **And** 计划中的能力必须以「即将支持」显式标注，且不写成可直接执行的命令样式

## Scenario 9 — 公开文档卫生

- **Given** 仓库面向开源
- **When** 全量检查 `设计文档/`、`docs/`、`README*.md`、`PRIVACY.md`
- **Then** 不存在本机绝对路径链接（`file:///...`）、不存在旧品牌名、不存在指向不存在文件的相对链接
- **And** 隐私终检脚本退出码为 0

## 验收口径

- 术语走查测试纳入前端测试集且为阻断项；
- 版本号仅有一处来源，构建产物可验证；
- 危险动作的三条（未选禁用、影响范围、预览模式）在浏览器实测中逐条核对；
- 公开文档链接检查可重复执行（脚本或测试）。
