# spec: asset-distribution-truth（分发状态真实化）

> capability：资产分发状态可查、可解释
> 关联：proposal D1 / D2 / D3、诊断 G2/G3
> 消费者：资产库卡片与详情、连接页、首页连接状态、同步页

## 为什么需要这份 spec

现状：`Asset.distributions` 恒为空数组，界面据此对每一项资产显示「未分发」；连接页则把「Hub 内该类资产数量」标成「已同步资产」。两处同时撒谎，且方向相反。本 spec 把「已同步」重新定义为**可验证的文件事实**。

## 术语

| 词 | 定义 |
|---|---|
| 库内资产 | Hub 内存在入口文件的资产（技能 = `skills/<name>/SKILL.md`） |
| 已启用工具 | `hub.toml` 中 `enabled = true` 且 `detect()` 判定已安装的工具 |
| 目标位置 | 某工具中该资产应出现的位置（由适配器映射决定） |
| 索引 | 一次计算得到的「库内资产 × 已启用工具」状态快照 |

## 状态判定规则（实现方不得自行改判）

优先级从上到下，命中即止：

1. 工具未安装 → `not_installed`
2. 工具已安装但未启用 → `not_enabled`
3. 工具为项目级策略（Qoder）→ **不产生条目**（见 Scenario 6）
4. 目标目录为符号链接，且解析后等于 Hub 对应目录 → 目录内全部资产 `synced`
5. 目标为单个符号链接，且解析后等于 Hub 文件 → `synced`
6. 目标为聚合文件策略（如 CLAUDE.md `@import`）→ 聚合文件内容中出现该资产的 Hub 相对路径 → `synced`，否则 `pending`
7. 目标存在且非符号链接：内容与 Hub 文件一致（按字节比较）→ `synced`；不一致 → `conflict`
8. 目标不存在 → `pending`

> 不使用「未接入」「未知」等第五种状态：所有条目必须落在上述五值内。

## Scenario 1 — 目录级符号链接视为已同步

- **Given** TRAE 已安装并启用，`~/.trae-cn/skills` 是指向 `<Hub>/skills` 的符号链接（Windows 下可为 junction）
- **When** 打开资产库并查看任一技能卡片
- **Then** 该卡片 TRAE 圆点为绿色，悬浮显示「TRAE 中国版：已同步」
- **And** 不出现「未分发」字样

## Scenario 2 — 聚合文件策略按 import 行判定

- **Given** Claude Code 已安装并启用，`CLAUDE.md` 中存在指向 `identity/profile.md` 的聚合引用，且不存在指向 `rules/safety.md` 的引用
- **When** 查看这两个资产
- **Then** `identity/profile.md` 对 Claude Code 显示「已同步」
- **And** `rules/safety.md` 对 Claude Code 显示「待同步」

## Scenario 3 — 目标缺失为待同步

- **Given** Codex 已安装并启用，采用复制策略，`~/.codex/skills/<name>/SKILL.md` 不存在
- **When** 查看该技能
- **Then** Codex 圆点为黄色，文案为「待同步」
- **And** 资产卡展示的汇总文案不得写成「冲突」或「未分发」

## Scenario 4 — 内容不一致为冲突

- **Given** Codex 复制目录中存在同名技能文件，但其内容与 Hub 中版本不同
- **When** 查看该技能
- **Then** Codex 圆点为红色，文案为「冲突（内容不一致）」
- **And** 用户可从详情进入同步页预览该条变更

## Scenario 5 — 未启用与未安装可区分

- **Given** 一个已安装但 `enabled = false` 的工具，以及一个未安装的工具
- **When** 查看任一资产
- **Then** 前者显示「未启用」，后者显示「未安装」，两者视觉上可区分
- **And** 二者都不计入「已同步工具数」

## Scenario 6 — 项目级工具不出现在单资产状态里

- **Given** Qoder 为项目级策略工具
- **When** 查看任一资产的工具状态列表，或查看连接页说明
- **Then** 列表中不出现 Qoder 条目
- **And** 界面（连接页 Qoder 详情或资产库页脚）存在一句说明：「Qoder 为项目级工具，分发在项目页管理（已接入 N 个项目）」
- **And** 不得把 Qoder 呈现为「未分发」，且「已同步工具数」/`toolSynced` 不包含 Qoder
- **And** 索引层不得去猜 Qoder 的“最乐观”或“最悲观”单值——它是二维的，一维表达一律不许

## Scenario 7 — 快照与刷新

- **Given** 索引在 30 秒内已计算过一次
- **When** 用户手动点击「刷新状态」
- **Then** 强制重新计算结果，并在界面显示最近一次计算时间
- **And** 执行同步、切换、资产医生应用修复成功后，下一次读取不得命中旧缓存

## Scenario 8 — 计算失败必须诚实降级

- **Given** 某适配器在判定过程中抛错（权限、路径不可读）
- **When** 渲染资产状态
- **Then** 该工具的条目缺失，且页面出现一行提示：「部分工具状态暂不可用」
- **And** 绝不把失败的工具渲染成「未分发」

## Scenario 9 — 未入库资产没有分发状态

- **Given** 某技能仅存在于工具目录、未收藏进我的库
- **When** 浏览资产库
- **Then** 该技能不出现（环境侧入口另行展示）
- **And** 界面不为其渲染任何分发圆点

## 验收口径

- 状态五值闭集有单测覆盖，边界（symlink/junction、聚合文件命中与未命中、内容一致与不一致）逐条有测试；
- 维护者本机实测：任一资产的状态可在终端用 `lstat` / 内容比较复核一致；
- 全站不再出现「未分发」作为兜底文案。
