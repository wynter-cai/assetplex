# spec: asset-center-consistency（资产类别单一真相 · 计数唯一 · 列表可用）

> capability：资产中心的口径、命名与列表行为一致
> 关联：proposal D4 / D5 / D6、诊断 G2/G3/G4
> 消费者：侧栏、首页快照、资产库列表与详情、连接页、技能页

## 为什么需要这份 spec

同一个「技能」在五个位置有五个数字；同一个「资产类别」有六份互不一致的清单；「全部资产」把技能目录里的 `SKILL.md` 平铺成同名条目、把 `_` 前缀内部元数据当成资产。用户无法建立任何心智模型，也难以判断「我的资产到底有多少」。本 spec 只做一件事：**让口径与命名唯一、可追溯**。

## 术语（本 spec 强制定义）

| 口径 | 含义 | 出现位置 |
|---|---|---|
| 我的库 `library` | Hub 内资产入口文件数（技能按 `skills/<name>/SKILL.md` 计 1 项） | 首页快照、资产库计数、连接页 |
| 本机环境 `environment` | 工具目录中存在、但未收藏进我的库的条目数 | 技能页环境入口 |
| 可收藏 `pendingImport` | 扫描到且不在我的库的条目数 | 首页导入入口、连接页 |
| 已同步 `toolSynced` | 某工具中状态为 `synced` 的库内资产数（见 asset-distribution-truth） | 连接页工具详情 |

> 任何界面数字必须能对应到上述四者之一，并在就近位置给出中文口径名。禁止裸数字。

## 资产类别声明源

唯一声明源为后端 `src/core/asset-categories.ts`，字段固定为：

```
code            类别代码（URL / API 使用）
label           中文显示名
description     一句话描述（类别页副标题）
hubDir          Hub 内目录名
external        是否由专用接口供数（true 时不走 /api/assets）
syncable        是否支持跨工具分发
doctorSupported 是否纳入资产医生
order           排序权重
```

前端 `web/src/config/asset-categories.ts` 仅保留**同名字段的 fallback 常量**（首屏渲染用，图标由 code 映射），接口返回后覆盖。禁止在前端再维护第二份独立清单。

## Scenario 1 — 新增类别只改一处

- **Given** 维护者在后端声明源中新增一个类别（含 label、hubDir、order）
- **When** 重启服务并刷新界面
- **Then** 侧栏资产库子项、首页资产快照、资产库类别筛选**同时出现**该类别
- **And** 未修改任何前端清单文件
- **And** 若接口不可用，界面回退到 fallback 清单且不报错、不白屏

## Scenario 2 — 五处数字一致

- **Given** 我的库中有 100 个技能入口文件、工具目录中共有 343 个技能条目、其中 68 个不在我的库
- **When** 依次打开首页、资产库全部、技能页、连接页
- **Then** 首页技能数字 = 资产库技能数字 = 100，且紧邻文字为「我的库」
- **And** 技能页环境入口显示 343，且说明文字为「本机技能环境」
- **And** 连接页「可收藏」显示 68
- **And** 不存在任何一处显示 182 或 185 作为技能数

## Scenario 3 — 已同步数来自真实状态

- **Given** TRAE 已安装并启用，我的库有 100 个技能，其中 96 个在 TRAE 中状态为 `synced`
- **When** 打开连接页 TRAE 详情
- **Then** 技能一行显示「已同步 96 / 我的库 100」
- **And** 不再出现把库内总数标成「已同步资产」的写法
- **And** 未安装工具不显示任何「已同步」数字

## Scenario 4 — 技能资产按技能名展示

- **Given** 我的库中有 `skills/<name>/SKILL.md` 形式的多项技能
- **When** 打开资产库「全部资产」
- **Then** 每项以 `<name>` 作为标题展示
- **And** 不存在多张标题完全相同的 `SKILL` 卡片

## Scenario 5 — 内部文件不冒充资产

- **Given** 技能目录内存在 `_meta.json`、`_icon`、`.` 开头的隐藏文件、以及 `references/*.md` 之类子文件
- **When** 打开资产库「全部资产」
- **Then** 这些文件都不作为独立资产出现
- **And** 只有当它们是某类资产的合法入口文件（如 `SKILL.md`、`rules/**/*.md`）时才出现

## Scenario 6 — 全部资产可筛选、可分页

- **Given** 我的库有 100+ 项资产
- **When** 打开「全部资产」
- **Then** 页面提供类别筛选与分发状态筛选，且筛选后的数量实时可见
- **And** 列表按 50 项/页分页，页内提供上一页/下一页与总数
- **And** 切换筛选后回到第 1 页

## Scenario 7 — 首页快照可下钻且口径一致

- **Given** 首页资产快照展示各类型号
- **When** 点击某一类别的数字
- **Then** 进入该类别页，页内数字与首页一致
- **And** 类别页标题与副标题使用声明源中的 `label` 与 `description`，不得漏列导航中存在的类别

## Scenario 8 — 空态与失败态不说假话

- **Given** 我的库为空
- **When** 打开资产库
- **Then** 空态文案说明「还没有资产」并给出唯一主动作「从工具收藏到我的库」
- **And** 请求失败时显示错误与重试，不显示「共 0 项」

## 验收口径

- 声明源字段有类型定义与单测（新增类别不触碰前端清单的测试）；
- 四口径在 API 响应中有显式命名，前端无 `filter(...).length` 形式的就地计数；
- 「全部资产」在维护者真实数据下：卡片数等于我的库入口文件数、无同名重复标题、无 `_` 前缀条目。
