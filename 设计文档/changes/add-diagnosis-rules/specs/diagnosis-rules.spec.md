# diagnosis-rules.spec.md：规则优先的资产深度诊断

> capability: 规则注册表、静态判定、AI 增量、证据链、误报控制、隐私、评测、降级
> 变更: add-diagnosis-rules | 决策依据: proposal.md D1-D8
> 规则清单: 同目录 `diagnosis-rules.yaml`（v1.0.0，71 条）

## 定义与数据口径

| 名词 | 含义 |
|---|---|
| **规则** | 一条可稳定引用的检查项，字段固定为 `id / category / severity / mode / signal / recommendation / source`；跨资产规则额外带 `appliesTo` |
| **规则集** | 随产品版本发布的全部规则，带 `version`（如 `1.0.0`）。规则集是产品承诺，不是用户配置 |
| **findings** | 一次诊断产出的问题列表，每条必须绑定一个 `ruleId` |
| **静态规则** | `mode: static`，纯本地判定，零模型调用 |
| **AI 增量** | `mode: llm`，在静态结果之上做语义判断，必须带证据，且只能从候选规则中选 |
| **证据** | `{ 库内相对路径, 行号, 原文片段 }`，片段长度 ≤ 200 字，必须能在原文中定位 |
| **置信度** | `high / medium / low`。静态命中默认 high（阈值类可为 medium）；AI 判定最高只能到 high，且必须证据完整 |
| **忽略** | 用户主动屏蔽某条命中，按 `ruleId + 路径 + 内容哈希` 记录；内容变更后自动失效 |
| **覆盖度** | `{ evaluatedRules, skippedRules, skippedReasons }`，用于回答「这轮到底查了什么、没查什么」 |

严重度与调研分级映射：`P0 → high`、`P1 → medium`、`P2 → low`。

统计口径：跨资产通用规则（`category: cross`）在任一适用类别的 tab 下展示，但全库计数与评分只计一次；`category: cross` 不计入七类各自的规则条数。

## Requirement 1：规则来源与结构

**用户可见行为**：任何一条问题都能追溯到一条有编号、有依据、有改法的规则；不同页面看到的是同一套规则。

### Scenario 1.1 问题可回溯到规则

- **Given** 某技能的 description 过泛，命中 `SK-04`
- **When** 用户展开这条问题
- **Then** 问题卡显示规则编号、规则名（一句话）、严重度、来源依据（指向最佳实践条目）、判定信号原文与建议改法；编号可复制

### Scenario 1.2 通用规则不重复计数

- **Given** 某规则文件含明文密钥，命中通用规则 `SEC-01`
- **When** 用户依次查看「规则」tab 与「全部问题」视图
- **Then** 该问题在「规则」tab 下可见（因为 `appliesTo` 含 rule），但在全库统计、健康分与向导计数中只出现一次

### Scenario 1.3 规则集版本可见

- **Given** 一次诊断完成
- **When** 用户查看报告头部
- **Then** 显示「规则集 v1.0.0 · 覆盖 71 条（本轮评估 N 条，跳过 M 条及原因）」；同一份资产在规则集升级后再次诊断，报告可对比两次的版本与结论差异

### Scenario 1.4 规则结构不完整即不生效

- **Given** 规则集中某条规则缺 `signal` 或 `severity` 非法，或出现重复 `id`
- **When** 诊断引擎加载规则集
- **Then** 该条不参与诊断并计入启动告警日志；其余规则照常工作，不因单条坏规则导致整份诊断失败

## Requirement 2：机器判与 AI 判分层

**用户可见行为**：能机器判的问题不需要模型；模型只做语义补充，不负责定罪。

### Scenario 2.1 无模型时静态规则完整

- **Given** 用户未配置任何 AI 端点
- **When** 对一批资产发起诊断
- **Then** 45 条静态规则全部执行并产出带证据的 findings；26 条 AI 规则显示「未评估（需配置模型）」，不显示为通过、不显示为 0 分

### Scenario 2.2 AI 只能从候选规则中选择

- **Given** 静态阶段已产出 2 条命中，候选 AI 规则集中在 `CON-01`、`RU-03`、`SK-11`
- **When** 模型返回一条不在候选清单内的规则编号，或自造编号
- **Then** 该条被丢弃并计入「解析拒绝」；报告只用合法条目，其余照常展示

### Scenario 2.3 静态高危不被 AI 覆盖

- **Given** 静态阶段判定 `SEC-01`（明文密钥，high）
- **When** 模型返回整体结论「健康、无问题」
- **Then** 最终结论仍取较重者，`SEC-01` 保留且不可被 AI 删除；AI 只能补充影响与改法

### Scenario 2.4 AI 接收范围受限

- **Given** 某技能正文 8000 字，静态阶段命中 3 条
- **When** 发起 AI 增量判断
- **Then** 发送内容仅包含：该资产的库内相对路径、3 条命中的位置与片段、候选规则清单与判定信号、资产类型；不含其他资产、不含全文、不含用户绝对路径

## Requirement 3：证据链

**用户可见行为**：每条结论都能自己复核；查不到证据时明说「无法确定」。

### Scenario 3.1 结论必须带证据

- **Given** 任一 finding 被展示
- **When** 用户展开证据区
- **Then** 至少一条证据包含文件（库内相对路径）、行号（无法定位到行时为片段序号并标注）、原文片段（≤200 字）；片段与结论分区展示，不混成一段建议

### Scenario 3.2 证据不足不下结论

- **Given** 模型认为某条规则可能成立，但无法指出具体原文位置
- **When** 报告渲染
- **Then** 该条标「证据不足，无法确定」，不参与计分、不进入整改建议、不提供一键修复；用户仍可查看它，但视觉上弱于有证据的结论

### Scenario 3.3 片段必须可在原文定位

- **Given** 模型返回的片段在资产原文中找不到（被改写或编造）
- **When** 引擎校验证据
- **Then** 该条被丢弃并计入「解析拒绝」，报告披露拒绝条数；不出现「看起来引用了原文、实际不存在」的伪证据

### Scenario 3.4 证据与结论分离

- **Given** 一条 high 严重度结论
- **When** 用户在治理中心下钻
- **Then** 面板分为「原文 / 规则说明 / 解释与建议」三块，原文块可跳转到对应行；不得只给一段自由文本

## Requirement 4：误报控制

**用户可见行为**：默认只打扰值得打扰的问题；不认同可以忽略，忽略后不再重复提示，且不制造「虚假健康」。

### Scenario 4.1 默认只看高置信

- **Given** 一次诊断产出 12 条 findings，其中 4 条 high 置信、8 条 medium 或 low 置信
- **When** 用户打开某一类资产的问题列表
- **Then** 默认视图只展示 4 条高置信项，并显示「另有 8 条低置信项已折叠」；展开后按严重度排序展示

### Scenario 4.2 忽略生效并在内容变更后失效

- **Given** 用户忽略「`SK-04` 命中：description 过泛」
- **When** 用户不修改该文件直接再次诊断
- **Then** 该条不再出现在默认视图与计分中；用户修改该文件内容后再次诊断，若仍命中，则恢复提示（忽略随内容哈希变更失效）

### Scenario 4.3 忽略必须透明

- **Given** 某资产有 2 条 finding 被忽略
- **When** 用户查看该资产报告与健康分构成
- **Then** 报告显示「已忽略 2 条」并可一键恢复；健康分说明中注明忽略条数，不得静默按健康计

### Scenario 4.4 向导克制且有正反馈

- **Given** 首次体检完成
- **When** 向导展示结果
- **Then** 最多展示 3 条高置信问题 + 总数 + 一个进入治理中心的入口；若没有任何命中，显示「未发现违反规则集的问题」并给出规则覆盖率，不编造建议凑数

## Requirement 5：隐私边界

**用户可见行为**：默认完全本地；用 AI 也必须知道发了什么，且随时可关。

### Scenario 5.1 默认零上传

- **Given** 用户未配置 AI 端点
- **When** 运行诊断
- **Then** 全部静态规则在本机执行，不发起任何网络请求；忽略清单、反馈、评测基线均只写本地

### Scenario 5.2 只发必要证据片段

- **Given** 用户已配置 AI 端点并发起 AI 增量
- **When** 请求发出
- **Then** 单条资产只发送：类型、库内相对路径、命中位置的片段（累计不超过设定字符预算）、候选规则与信号；不发整份资产、不发其他资产、不发绝对路径与用户名

### Scenario 5.3 模型端点由用户自备

- **Given** 用户配置了自己的 OpenAI 兼容端点
- **When** 发起 AI 增量
- **Then** 请求只发往该端点，不经过任何产品方中转；设置页明确标注「AI 为可选增量，关闭后静态规则仍完整可用」

### Scenario 5.4 忽略与反馈不外传

- **Given** 用户忽略若干问题并标记「有用 / 没用」
- **When** 任何网络请求发生
- **Then** 这些数据不出现在请求体中；它们只用于本机回归与后续权重调整的输入

---

## Requirement 6：评测与回归

**用户可见行为**：规则或提示词改动后，诊断结果的变化是可比较、可解释的。

### Scenario 6.1 标注集固定

- **Given** 仓库内维护一批中性示例资产（覆盖七类资产 × 应报 / 不应报）
- **When** 跑诊断回归
- **Then** 对每条样本输出「期望命中规则集合」与「实际命中集合」的差异清单，逐条可比

### Scenario 6.2 规则版本变更可比较

- **Given** 规则集从 v1.0.0 升到 v1.1.0
- **When** 对同一批资产重跑
- **Then** 报告携带各自 `rulesVersion`；对比工具输出新增、消失、严重度变化的条目，且能定位到是哪条规则变了

### Scenario 6.3 指标与门禁

- **Given** 标注集跑完
- **When** 查看结果
- **Then** 输出精确率、召回率与人工同意率；指标低于约定初值时在 CI 只报警告并给出差异，不阻断构建（规则与样本仍在演进期）

### Scenario 6.4 语义变更必须升版本

- **Given** 某条规则的判定信号或严重度被修改
- **When** 提交变更
- **Then** `version` 必须递增；仅改文案（`recommendation` 措辞）可不升版本，但需在变更说明中标注

---

## Requirement 7：降级

**用户可见行为**：没有模型、模型失败、超预算，都不会得到一份「看起来健康」的假报告。

### Scenario 7.1 无模型时静态完整可用

- **Given** 用户未配置 AI
- **When** 打开治理中心与单资产报告
- **Then** 静态 findings 完整展示；规范性维度标注「语义质量未评估」，不按满分或零分计入；建议区解释「配置模型可解锁 N 条语义规则」

### Scenario 7.2 超时或超预算降级

- **Given** AI 增量执行中触发超时或字符预算上限
- **When** 结束本轮
- **Then** 保留已完成的静态结论与已成功的 AI 结论，标注「本轮语义评估未完成（原因）」；不返回空报告，也不把未评估项当作通过

### Scenario 7.3 单条失败隔离

- **Given** 模型对某条规则返回非法结构（缺字段、证据不可定位、编号非法）
- **When** 解析
- **Then** 只丢弃该条并计入拒绝数；同批其他资产与其他规则结果不受影响，资产本体与分发状态零变化

---

## 非功能约束

- **零模型调用承诺**：静态规则在大批量资产上不得发起任何网络请求；单资产静态诊断在普通笔记本上应达到「点开即出」的体感。
- **可解释性**：任何展示给用户的分数与结论，都必须能回答「哪条规则、哪段原文、怎么改」。
- **口径单一**：治理中心分类页、资产详情、资产编写指南必须读取同一份规则集与同一份规则说明；不得出现页面各写一套的情况。
- **隐私**：规则集、spec、夹具、示例一律使用中性名称（如 `demo-skill`、`example-rule`、`testuser`），禁止出现真实用户数据、真实绝对路径、真实技能名。
