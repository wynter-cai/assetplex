> 日期：2026-11-15

> 用途：B16-02 正式 spec 的输入（跑基线再写 spec），不用于发布

## 1. 方法与口径

- **不改数据**：只读遍历 Hub 的七个类别目录，未写入、未移动、未删除任何资产。
- **静态规则**：用仓库内的规则注册表 + 静态执行器，按**生产调用方式**（`kind + hubRelativePath + content`，不注入 peers / siblings / exists）逐资产实跑，结果即线上会看到的结论。另跑一遍「注入上下文」的对照，用于判断哪些规则是结构性不生效。
- **语义规则（mode=llm）**：静态执行器不跑语义规则，本基线用人工方式，以「规则原文判定信号」逐条比对样本正文，记录命中 / 零命中与理由；证据不足的记「无法确定」，不硬给结论。
- **不跨类别硬套**：每条资产只套「自身类别规则 + 适用于该类的 cross 规则」，cross 规则严格按 `appliesTo` 过滤。
- **命中判定**：命中 = 规则判定信号在本样本上成立；误报 = 信号成立但按规则意图属于不该报的情形。

## 3. 结论摘要

- **静态规则共产生 68 条 finding，人工判定真阳性 18 条、误报 50 条（误报率 74%）**。误报高度集中：SK-03（16）、SK-09（12）、SK-12（6）、VAG-01（5）、SK-08（3）、RU-04（3）六条规则贡献了 45 条（90%）。
- **45 条静态规则中 28 条至少命中 1 次，17 条零命中**；其中 **4 条是结构性不执行**（SK-05 / STL-01 / DUP-01 / AGT-06：执行器缺 peers / siblings / exists 上下文，线上永远不会报），并非样本干净。
- **26 条语义规则中 8 条在人工复核中命中、2 条证据不足、16 条零命中**（多为样本里确实没有该场景）。
- **规则总数 71，本基线中有实际结论覆盖 46 条（65%）**；未覆盖的 25 条里，7 条因命令类别零样本、4 条因执行器未接线、14 条为语义规则零命中。
- 最严重的一条**漏报**：引用类正则把 `https://` 误当成盘符绝对路径，导致 `SK-09 / ID-09 / RU-06` 的路径信号整体失真（详见 §6.2）。

## 6. 误报逐条（人工判定理由 + 改法）

### 6.1 SK-03｜22 命中，16 误报（最大误报源）
- 形态：19 条报「缺少 Use when / 当用户 / 适用于 触发子句」，3 条报「description 含尖括号」。
- 误报 1（13 条）：描述里写的是**等价触发句式**——「用户提到 X 时使用」「用户说 X 时优先走这里」「任何包含 X 都应使用」「命中关键词」「Invoke when」「Triggers:」「Use for」。正则只认四个字面词，把中文最常用的「用户提到…时使用」全部判死。
- 误报 2（3 条）：尖括号出现在**反引号内的命令占位符**（`<domain> <verb>`、`@<exact-version>`），不是会被清洗的 HTML 标签。
- 真阳性 6 条：确有 6 份描述只写「做什么」不写「何时用」（例如「XX 管理：列出、查看、删除…」），这类应保留命中。
- 改法建议：触发子句判定改为「动作 / 时点 / 条件」三类语义信号之一即可（`用户提到|用户说|当用户|适用于|Invoke when|Use when|Use for|Triggers|命中关键词|用户要求`），并把尖括号检查限定为「不在反引号 / 代码块内」。

### 6.2 SK-09｜13 命中，12 误报（并波及 ID-09 / RU-06）
- 形态：报「引用使用绝对路径：换机器即失效」。
- 理由：12 条命中行的内容是 `https://...`。绝对路径正则 `[A-Za-z]:[\\/]` 把 URL 里的 `s:/` 当成了「盘符 + 分隔符」。同一正则还被 ID-09（人设）与 RU-06（常驻规则）复用，属**跨规则共用的系统性缺陷**。
- 唯一真阳性：S35 正文含一处真实本机盘符路径 + 反斜杠引用。
- 改法建议：盘符判定加左边界（前面不能是字母，例如 `(?<![A-Za-z])[A-Za-z]:[\\/]`）并排除 `://`；URL 先行剔除；同时补一条「URL 不是路径」的回归用例。

### 6.3 SK-08｜5 命中，3 误报
- 形态：报「正文仅 N 行，且无流程、无引用、无示例」。
- 理由：S10（37 行）、S30（27 行）、S34（45 行）都有 `##` 二级标题，但检测用的 `/^\d+\.\s|^##\s|示例|example/i` **缺少 `m` 标志**，`^` 只匹配整个正文字符串开头，所以标题一律看不见。这是实现 bug，不是阈值问题。
- 真阳性 2 条：S28（0 行）、S29（9 行 7 步通用流程）。
- 改法建议：正则补 `m` 标志；「过短」分支还应把「有二级标题或有序步骤」视为有结构。

### 6.4 SK-12｜7 命中，6 误报
- 形态：报「枚举多个选项却没有给出默认使用 X」。
- 理由：判定正则是 `或\s*[A-Za-z\u4e00-\u9fa5]`，等价于「出现『或』且后面跟任意字」，于是「或显式告诉用户」「或把 X 接入」「或直接点名」「不用于一句话问答或立即完成的小事」全中。这不是「枚举选项」。
- 真阳性 1 条：S35 的反斜杠路径（该子信号成立）。
- 改法建议：删掉这条弱信号，或改成结构化判定（同一行 ≥2 个并列项 + 无「默认 / 首选」）；反斜杠子信号独立成条，已有 SK-09 覆盖时避免重复扣分。

### 6.5 SK-04｜1 命中，误报
- 理由：命中词 `helper` 来自**子命令名**（`helper mcp`），不是「泛化助手」自述；描述里还有明确的命令族与边界，模型完全能判断何时用。
- 改法建议：泛化词扫描前先剔除反引号 / 代码片段；`helper` 与 `tools` 这类同时是常见命令名的词应降权或从词表移除。

### 6.6 RU-04｜3 命中，全部误报
- 理由：三条都是**单动作 + 并列宾语**：一条禁止 bash 语法（列了 9 个禁用命令）、一条列出要看的错误关键字、一条列出单元测试覆盖的对象。顿号计数把「枚举宾语」当成了「多个动作」。
- 改法建议：连接词计数只在「动词短语」之间成立，至少要求每个分句带动作动词；纯名词 / 代码标识符列表不计。

### 6.7 RU-02｜1 命中，误报
- 理由：报「单段超过 15 行」，命中的那段是 19 行的围栏代码块 + 紧随清单，视觉上并非「一整面文字墙」。
- 改法建议：切段前先剔除围栏代码块；或对含代码块的行单独计权。

### 6.8 RU-06｜1 命中，误报
- 理由：R1 是常驻规则，命中项是「PowerShell 里含空格的路径要加双引号」这条**通用**规则中的示例字符串，不是「只对某个项目成立」的路径。且同一条缺陷与 §6.2 同源（盘符正则过宽）。
- 改法建议：先用 §6.2 的修正版正则；并区分「示例中的路径」与「规则作用域声明」。

### 6.9 MC-09｜1 命中，真阳性但口径过宽
- 理由：M1 是 9 行服务器来源清单，确实没有哈希基线；但把「基线缺失」压在**单个配置文件**上不合理——基线应属「MCP 资产集合 / 扫描任务」。
- 改法建议：规则改为集合级判定（存在 MCP 资产但库内无基线文件），或在单文件诊断时标「证据不足」而非命中。

### 6.10 SK-01｜1 命中，形态真阳性、样本选取有问题
- 理由：S28 是一个空目录，没有 SKILL.md。按规则字面成立，但它根本不该进入资产样本——扫描器把「空目录」当成了技能。
- 改法建议：扫描阶段过滤空目录 / 无 SKILL.md 且无任何文件的目录；确需保留则单独归为「无效资产」而不是技能缺陷。

### 6.11 MEM-06｜1 命中，误报
- 理由：MM1 是自动生成的 17 行记忆文件（内容区块为空），要求它「库内有审计记录」属层级错位——审计是库级能力，不可能落在单个记忆文件里。
- 改法建议：MEM-06 改为「记忆库」级检查，仅在集合视图执行；单文件诊断不参与。

### 6.12 STL-02｜1 命中，误报
- 理由：命中的是 `2048`（图片分辨率），被 `\b20\d{2}\b` 当年份，同行又有「当前」，于是拼成「时限性表述」。
- 改法建议：年份需与「年 / 版 / 发布」等上下文共现，或限定 1990–2099 且排除纯分辨率（2048/4096/1080 等白名单）。

### 6.13 VAG-01｜7 命中，5 误报
- 理由：5 条命中的「必要时」后面紧跟**具体动作**（重跑第 1 阶段、转某技能、补 `--modality`），已经满足规则原文「同句给出判定条件或默认动作」；实现只查「条件 / 默认 / 当…时 / 如果 / 除非」这些字面词，认不出「必要时 + 命令」这种写法。
- 真阳性 2 条：「输出尽量稳定」「尽量用起来」确实是不可验收的空洞要求。
- 改法建议：裸条件词后若同句出现反引号命令、明确动词或指向具体章节，视为已限定；`尽量` 单列，不与 `必要时` 共用一套豁免。

## 7. 规则实现缺陷清单（按影响排序）

1. **绝对路径正则误伤 URL**（§6.2）：影响 SK-09 / ID-09 / RU-06，一次改动可消掉 13 条误报中的 12 条。
2. **触发子句只认四个字面词**（§6.1）：一条规则制造 22 条命中、16 条误报，是当前误报率的主因。
3. **SK-08 缺 `m` 标志**（§6.3）：短技能几乎必报，属确定性 bug。
4. **上下文类规则未接线**（SK-05 / STL-01 / DUP-01 / AGT-06）：规则清单宣称可用，线上永不执行；DUP-01 已证实能抓到真实重复。
5. **引用存在性缺相对基准**：一旦接线，按 Hub 根解析会制造 80+ 条误报。
6. **「或 + 任意字」弱信号**（§6.4）：6 条误报，建议直接删除。
7. **同模式只报首次命中**：ID-09 在 P1 上 8 处问题只报 2 条，用户会低估问题量。
8. **缺少「占位未填写」规则**：A1–A8 全是「待补充」空壳，71 条规则无一条能判它不合格（AGT-01 只能给证据不足），这是最值得新增的一条跨资产规则。

## 8. 对正式 spec 的输入建议

1. 先修 4 个确定性实现 bug（URL 误判盘符、触发子句字面匹配、SK-08 缺 `m`、弱信号「或」），再谈阈值调优，否则基线不可比。
2. 明确「上下文类规则」的启用边界：peers / siblings / exists 由谁注入、相对基准是什么，写进 Given-When-Then。
3. 把「占位未填写 / 空壳资产」新增为跨资产规则，A1–A8 是现成回归样本。
4. 阈值类规则（SK-08 / RU-01 / RU-02 / ID-08）全部标 medium 且默认折叠，误报代价高于漏报。
5. 命令类别零样本，spec 前必须补 ≥5 条命令资产，否则 CMD-01~07 的验收无法成立。
6. 单文件放不下的规则（MC-09 基线、MEM-06 审计）改为集合级判定，并定义集合视图的输入。
7. 每条规则补「已知误报形态」清单与对应回归夹具，误报率作为准入门槛而非事后指标。
