# 提案：斜杠命令是否纳入资产中心（command）

> 状态：**已拍板（2026-11-19）——维持不做（选项 A）**，与 2026-10-29 的 D3 一致；无需实现规格，第二梯队记为收口。
> 日期：2026-11-18

## 为什么要重提

资产分类法里第二梯队写了三项：`command`（斜杠命令）、`agent`（子代理）、`memory`（记忆）。现状：

- `memory`：✅ 已落地（`add-memory-category`，含旧 `preferences/` 兼容并入）
- `agent`：✅ 只读盘点已接入，可收藏、可同步
- `command`：❌ 未做，且 2026-10-29 已拍板「不做」——理由：仅 Claude Code 有等价机制，单工具专属目录不构成「换工具能带走」的资产

也就是说，第二梯队只剩 `command` 一项悬而未决。本次不预设答案，只把决策所需的事实与代价列清，供你一次拍板。

## 现状事实

- 扫描器已移除 `commands/` 规则，资产中心任何位置（侧栏、快照、筛选、收藏向导、切换页）都不出现「命令」类别。
- Hub 磁盘上已有的 `commands/` 历史文件仍在原处，只是不再作为资产呈现，也不参与同步、诊断或健康分。
- 声明源 `src/core/asset-categories.ts` 中确实没有 `command`；`AssetCategory` 类型里保留了这个代码，属于内部类型的历史遗留，不影响界面。

## 三个选项

### 选项 A：维持不做（推荐）

- 范围：零改动，只把「第二梯队已收口」写进分类法与 HANDOFF。
- 好处：口径最干净——资产的定义是「换工具能带走」，单工具专属目录进来会破坏这个定义；也避免为一条没有跨工具等价物的内容再开一套扫描/收藏/分发链路。
- 代价：Claude Code 用户的自定义命令仍然游离在管理之外，想备份只能自己拷文件。

### 选项 B：只读盘点，不参与分发

- 范围：扫描 `commands/*.md` 并只读展示（沿用 `agent` 的「只读盘点」形态）；不支持收藏、不支持同步、不计入健康分。
- 好处：至少能看见「我有哪些命令」，方便备份。
- 代价：界面上多一个「只能看、不能用」的类别，与「盘点即可带走的资产」叙事冲突；后续一定会有人问「为什么这个不能同步」。

### 选项 C：完整管理 + 跨工具分发

- 范围：新增类别、扫描、收藏、详情、诊断、分发适配器，并逐工具实现命令格式转换。
- 前提：必须先实测各工具是否真有等价机制（Claude Code 之外，TRAE / WorkBuddy / Codex / Qoder 是否有同类能力、格式是否一致）。没有等价机制的工具只能「显式不支持」，分发价值随之缩水。
- 代价：一个完整 S 级变更（声明源 + 扫描 + 适配器 + 界面 + 分发 + 测试），且要长期维护各工具的命令格式差异。

## 风险与边界

- 若选 B 或 C，等于推翻 2026-10-29 的 D3 决议，需要同步改分类法里「命令不是资产」的口径，避免文档与实现打架。
- 命令正文常含团队内部流程与仓库路径，纳入管理后若再叠加诊断/分发，会扩大隐私面；这是选 C 时最需要先想清楚的一条。
- 无论选哪个，都不建议把历史 `commands/` 文件搬走或删除——磁盘上可能已被工具的软链占用。

## 开放问题（拍板前需要你回答）

1. 你自己现在还用斜杠命令吗？主要用哪个工具的？
2. 除了 Claude Code，你希望哪些工具能收到命令？（决定 C 是否有意义）
3. 如果只能「看见但不能同步」，你会用吗？（决定 B 是否有价值）

## 建议

按 A 维持现状：把第二梯队记为「memory ✅ / agent ✅ / command 明确不做」，不再留悬空项。理由是资产的定义比覆盖面更重要，且 C 的维护成本长期落在你一个人身上。
