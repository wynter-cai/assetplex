# AssetPlex 主页与治理中心方案（讨论稿）

> 日期：2026-11-14 · 状态：待维护者拍板 · 关联：P2-3 首页大改、P1-4 AI 深度诊断、P1-5 资产编写最佳实践
> 本文回答三个问题：①引导页与主页是什么关系；②「体检 → 治理 → 分发」怎么串；③老用户每天打开产品应该看到什么。

---

## 1. 核心判断

**1）引导页不做主页。**
引导是一条**一次性、线性、教学式**的路径；主页是**反复使用、并行多任务**的工作台。把引导当主页，老用户每次都要穿过一层「欢迎/下一步」，效率最低。
但两者共用同一套壳与设计语言；引导完成后侧栏保留「新手引导」入口，供重看或换机后重跑。

**2）主页不是「信息展示页」，是「行动面板」。**
老用户打开产品的真实问题不是「我有什么」，而是：
- 哪里不一致 / 有风险？
- 我今天该改哪一条？
- 改完有没有同步到各工具？
所以主页的主区应该是**待办队列**，不是营销 Hero、不是卡片墙。

**3）治理是产品的主循环，不是向导的一步。**
「体检 → 治理 → 分发 → 漂移检测 → 再治理」才是长期价值。首跑只露出体检摘要和治理入口，完整治理放在正式导航里，按资产类型深做。

**4）导航从「按功能平铺」改为「按任务分组」。**
现有 10 项平铺（首页/资产库/连接/同步/切换/体检/导入/智能体/技能/活动/设置）让新用户看不出边界。建议收敛为 4 组 + 设置。

## 2. 用户与任务

| 用户状态 | 目标 | 产品应答 |
|---|---|---|
| 首次使用 | 60 秒内看到自己的资产、完成第一次收纳与分发 | 线性向导（已实现），结束即退出 |
| 换机 / 换工具 | 把资产带过去 | 引导重跑 + 备份恢复 |
| 日常使用（高频） | 发现并修好问题、保持各工具一致 | 主页行动面板 + 治理中心 |
| 深度整理（低频） | 按最佳实践逐类优化人设/规则/技能 | 治理中心分类视图 |
| 排障（偶发） | 某工具不生效、内容被覆盖 | 同步/漂移视图 + 活动日志 |

## 3. 信息架构

```
总览（主页）
资产库
  ├─ 全部资产
  ├─ 身份 / 规则 / 技能 / MCP / 命令 / 子代理 / 记忆
治理
  ├─ 待处理（按严重度）
  ├─ 按资产类型（人设 / 规则 / 技能 / MCP / 命令 / 子代理 / 记忆）
  └─ 历史与已忽略
连接与同步
  ├─ 工具连接
  ├─ 分发与漂移
  └─ 备份与恢复
活动
设置
```

原则：
- **一个任务只出现在一个主入口**；跨入口用深链，不复制功能。
- 「体检」不再作为独立一级入口，成为「治理」的一个视图（健康分 + 全量问题）。
- 「导入/切换」并入「资产库」与「连接与同步」的次级动作，避免一级导航膨胀。

## 4. 主页（总览）布局

```
┌──────────────────────────────────────────────────────────────┐
│ AssetPlex   本地运行 · 不上传              ⌘K 搜索     设置  │
├──────────┬───────────────────────────────────────────────────┤
│ 总览     │  健康分 78   待治理 12   未同步 3   上次备份 2h   │
│ 资产库   │  ┌───────────────────────────┬─────────────────┐  │
│ 治理 ●12 │  │ 今日待办                  │ 工具与同步      │  │
│ 连接同步 │  │ □ 人设缺边界        高    │ TRAE CN   ✓     │  │
│ 活动     │  │ □ 规则 always 冲突   高    │ Claude    ● 漂移│  │
│          │  │ □ 技能描述过泛       中    │ Codex     ✓     │  │
│          │  │ □ MCP 未固定版本     中    │ Cursor    未连接│  │
│          │  │ □ 记忆引用失效路径   低    │ [+ 添加工具]    │  │
│          │  │ [查看全部 12 项 →]         │                 │  │
│          │  └───────────────────────────┴─────────────────┘  │
│          │  最近变化（活动流，默认 5 条，可展开）             │
└──────────┴───────────────────────────────────────────────────┘
```

要点：
- **顶部四个数字是状态条，不是卡片**：健康分、待治理、未同步、最近备份；点击进入对应视图。
- **今日待办**按严重度排序，每条一行：资产名 + 问题类型 + 严重度 + 「查看/修复」；支持键盘上下与 Enter。
- **工具与同步**是矩阵：工具名 + 状态点 + 最近同步时间；漂移工具一键进入差异视图。
- **最近变化**只保留 5 条，避免活动流吞掉主区。
- 不放大段营销文案、不做「快捷操作九宫格」；新增资产用一个全局「+」按钮（命令面板同源）。

### 4.1 空态（老用户但库为空 / 全部健康）

- 库为空：主区显示「从已安装工具收藏第一批资产」+「运行首次引导」两个出口。
- 全部健康：顶部状态条变绿，主区显示「最近一次体检时间 + 下次建议检查项」，不制造虚假待办。

## 5. 治理中心（核心模块）

### 5.1 三种视图

1. **待处理队列**：全部 finding 按严重度/资产类型筛选，适合「今天修几条」。
2. **按资产类型**：人设、规则、技能、MCP、命令、子代理、记忆七个 tab，每个 tab 是该类资产的专属检查清单与逐条结果。
3. **单资产详情**：左树（文件/资产）、中间问题列表、右侧证据与建议 diff。

### 5.2 每条问题的固定结构（与 P1-4 调研一致）

```
[严重度] 问题标题                          [来源：规则 / AI]
证据：文件 + 行号 + 片段
影响：不修会发生什么
建议：具体改法（可展开 diff）
依据：引用哪条最佳实践（技能/人设/规则…）
操作：应用修复 · 忽略 · 稍后 · 查看原文
```

- 机器判的问题（格式、长度、引用断链、密钥）默认零 Key 展示。
- 语义类（冲突、描述过泛、身份不可验证）标记「AI 判断」，必须附证据，证据不足显示「无法确定」。
- 应用修复前自动备份；支持单条撤销与按批次撤销。

### 5.3 分类深度（这是「做细」的地方）

| 资产类型 | 专属检查重点 | 依据 |
|---|---|---|
| 人设 | 是否含角色/受众/目标/边界/不确定时策略；是否可验证；是否混入项目细节 | P1-5 人设 12 条 |
| 规则 | 分层是否正确、是否冲突/重复、是否超长、是否可执行、是否含密钥 | P1-5 规则 12 条 |
| 技能 | description 路由、正文 <500 行、引用一层可达、反模式 | P1-5 技能 15 条 |
| MCP | 明文密钥、未固定版本、工具描述指令化、lethal trifecta | P1-5 MCP 10 条 |
| 命令 / 子代理 | 单职责、输入契约、验收、权限最小、描述总量 | P1-5 commands 8 / agents 9 |
| 记忆 | 是否过期、是否与规则矛盾、是否把门禁写进记忆 | P1-5 memory 9 |

每条检查项都必须带 `ruleId + 判定信号 + 建议 + 来源`，同一份规则同时驱动「诊断」和「资产编写指南」，避免两套口径。

### 5.4 评分口径

- 总分仍由规则计算，AI 不参与打分（可解释、可回归）。
- 每个资产类型单独给分与「已覆盖检查项/总数」，避免技能数量多掩盖人设问题。
- 评分只用于排序与趋势，不用来做「及格/不及格」的羞辱式表达。

## 6. 流程：引导、治理、分发怎么串

### 6.1 新用户（首跑）

```
欢迎 → 盘点 → 结果 → 收纳 → 体检（Top 3 + 健康分） → 分发 → 完成
                                                   ↘ 完成页次按钮：去治理第一条
```

- 首跑**不做完整治理**：60 秒承诺优先，只展示 Top 3 与一个入口。
- 完成页提供「去治理」与「进入资产库」两个出口；选治理则带着第一条问题进入治理详情。
- 分发与治理顺序：先分发让用户马上在各工具生效，再治理；治理后的修改通过同步回到工具。

### 6.2 老用户（日常）

```
打开 → 总览待办 → 治理详情（证据 → 应用） → 自动/手动分发 → 状态条更新
```

- 治理页修完一条，右侧直接出现「同步到 N 个工具」；不强制跳页。
- 漂移由同步模块检测，进入总览「未同步」计数与工具矩阵。

### 6.3 引导页的定位

- 独立路由（`/onboarding`），不进入主布局；完成后写标记。
- 侧栏常驻入口用于重看；换机后可通过备份恢复 + 重跑引导。
- 主页不承担教学；引导不承担日常任务。

## 7. 交互细节

- **命令面板 ⌘K / Ctrl+K**：搜索资产、跳转治理项、执行「体检/分发/备份」。
- **键盘**：列表 J/K 或上下移动，Enter 打开，A 应用，I 忽略，Esc 返回；所有操作有 toast 与撤销。
- **diff 优先**：建议改动先展示 before/after，不直接覆盖。
- **批量**：同类问题支持「全部应用」，但必须先展示影响文件清单。
- **诚实空态**：数据缺失显示「暂不可用」，不伪造 0 分或「全部健康」。
- **响应式**：桌面优先；<1024px 导航折叠为抽屉，治理三栏变单栏分步；移动端只保留「看待办/看资产/同步」三件事（低优先级，见 backlog P2-4）。

## 8. 分期落地

| 阶段 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| Phase 0 | 主页骨架 + 状态条 + 待办队列（只读现有 health/issues） | 无 | 老用户打开 3 秒内看到「今天要处理什么」 |
| Phase 1 | 治理中心：按类型 tab + 单条证据/建议 + 应用/撤销 | P1-4 诊断模型、P1-5 规则清单 | 每类资产至少 5 条可判定规则；修复可撤销 |
| Phase 2 | 治理 ↔ 分发联动：修完即同步、漂移回流到待办 | P1-1 漂移检测 | 改一条资产 ≤2 步同步到目标工具 |
| Phase 3 | 首页个性化、响应式、快捷键完善 | Phase 0–2 | 窄屏可用；常用操作全键盘可达 |

## 9. 风险与取舍

- **风险：治理做太重，首跑又变长。** 对策：首跑严格只做 Top 3 + 入口，完整治理永远在正式页面。
- **风险：AI 误报伤害信任。** 对策：AI 结论必须带证据；证据不足不下结论；默认只展示高置信项。
- **风险：导航改动让老用户迷路。** 对策：保留 URL 与深链；旧入口重定向；一期内不删功能只重组入口。
- **取舍：首页不放「资产总数」大数字。** 数字放资产库；首页只放「需要行动的数字」。

## 10. 需要维护者拍板

1. 导航是否按「总览 / 资产库 / 治理 / 连接与同步 / 活动」五组收敛？
2. 首跑完成页是否默认引导「去治理第一条」，还是默认进资产库？
3. 治理中心的「应用修复」一期是否允许直接改文件（带备份/撤销），还是只给建议、由用户手动改？
4. 主页「今日待办」是否允许用户手动忽略/稍后（需要持久化状态）。
