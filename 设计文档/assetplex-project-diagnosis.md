# AssetPlex 项目全面诊断

> 版本：1.0 | 日期：2026-10-25 | 状态：待维护者审核
>
> 触发背景：产品定位升级为「开源 · 做大影响力」，并明确两个用户痛点——① 盘点 AI 资产、跨 AI Agent/Coding 工具无缝迁移；② 在资产中心统一管理全部资产（人设、规则、技能、用户记忆、智能体……），并在管理过程中引入业内最佳实践。
>
> 本文档是该定位下的**项目级诊断基线**，结论与证据分离；后续产品设计与用户旅程以此为对照物。变更实施见 `changes/fix-trust-and-consistency/`。

---

## 一、结论摘要

| 维度 | 评级 | 一句话判断 |
|---|---|---|
| 工程质量 | A | 引擎、适配器、测试、隐私治理均为上游水平 |
| 产品能力（痛点 1：盘点+迁移） | B+ | 骨架成立，缺 CLI 入口与「状态可信」 |
| 产品能力（痛点 2：统一管理+最佳实践） | C | 只完成一半，记忆/命令为「能搬不能看」的幽灵资产 |
| 产品叙事（README/docs/npm） | C | 仍在讲「同步工具」，把一年长出的增量全部藏起来 |
| 界面与信息架构 | C | 13 项平铺导航、4 套同义词、5 个互不相同的技能计数 |
| 开源物料与 SEO | C- | 5 篇英文文档、无 demo、无 sitemap、品牌名未收敛 |

**核心判断：风险不在「做得不够多」，而在「做了用户看不见」以及「关键状态不真实」。**

新增能力（准则包、资产医生、冲突仲裁、切换回滚、技能发现、工作区）已经沉淀在代码里，但没有任何一个在公开叙事和首屏交互上被表达出来；同时资产卡片的「分发状态」在实现上是恒空占位，与「同步到所有工具」的核心承诺直接冲突。**先修可信度与信息架构，投入产出比远高于再写一个新功能。**

## 三、定位诊断

### 3.1 对外叙事仍是「同步工具」

README / npm description / docs 三处一致地在讲：

> One hub, every AI agent — Sync your identity, skills, rules & MCP servers…

问题有三层：

1. **品类红海**：这句话把产品放进 agentsync / agentsmesh / sync-rules 的正面竞争区，差异化只剩「中国工具栈 + Windows」。
2. **能力漏报**：资产医生、裁决准则、冲突仲裁、切换与回滚、技能发现、工作区、智能体盘点，**README 一个都没提**。
3. **概念过时**：Web UI 预览仍是旧版 9 tab 的 ASCII 图；Roadmap 把已上线功能写成「开发中」。

### 3.2 新定位的能力结构

两个痛点不是并列关系，而是**「保险 + 增值」双层**：

```
第 1 层（保险）：盘点 → 收藏入库 → 跨工具迁移        已有，且是护城河
第 2 层（增值）：统一管理 → 按业内最佳实践兜底        半成品，是拉开差距的真正理由
```

只有第 1 层，产品永远是「又一个 sync 工具」；第 2 层成立，才是「AI 资产中心」。而第 2 层的**弹药已经在代码里**（准则元资产、准则包、资产医生、仲裁），只是没有产品化。

### 3.3 叙事建议（待拍板）

- 三支柱表达：**盘点（Discover）→ 迁移（Move）→ 规范（Standardize）**；导航、README、docs 首页全部按此组织。
- 待决策：主叙事是「AI 资产中心（保险 + 增值）」还是「AI 资产标准中心（以最佳实践为主打）」。
- 概念冲突需先解决：早期隐喻「保险箱」已被界面词汇表禁用（taxonomy §八），但新定位的天然表达正是「保险箱 / 我的库」。需要定一个词，否则文案会继续分裂。

## 四、痛点 1（盘点 + 跨工具迁移）覆盖度

### 4.1 已成立的部分（不应被低估）

- 5 适配器 × 多策略（symlink / copy / native-import / per-project），含 Windows junction 降级；
- 反向导入 + 冲突仲裁（LLM 建议 + 机械合并 + 用户确认落盘）；
- 「切换」是全站最完整链路：预览冲突 → 备份 → 写入 → 校验 → 撤销 → 历史；
- 技能发现锁 commit、只读预览、显式确认入库；
- 隐私模型（方法公开、隐私值不入库）在开源项目中属上游水平。

### 4.2 缺口

| # | 缺口 | 影响 |
|---|---|---|
| G1 | CLI 只有 4 个命令，盘点/收藏/切换/体检/发现全在 Web UI | 开源开发者第一触点（终端）拿不到核心能力，README 演示不出 wow 时刻 |
| G2 | 分发状态恒为「未分发」（`distributions: []` 占位） | 与核心承诺冲突，信任归零 |
| G3 | 连接页把「Hub 内资产数」标成「已同步资产」 | 同一事实两处矛盾，用户无法判断是否真的同步成功 |
| G4 | 记忆 / 命令 / 偏好「能搬不能看」 | 与新痛点 ② 直接冲突 |
| G5 | 迁移的验证边界（只证明写入，不代表工具已加载）只写在代码注释里 | 诚实边界本是最强差异化，却被藏起来 |

## 五、痛点 2（统一管理 + 最佳实践）覆盖度：最大缺口

### 5.1 资产类别能力矩阵

| 类别 | 盘点 | 收藏入库 | 编辑 | 分发 | 体检 | 回滚 |
|---|---|---|---|---|---|---|
| 身份 identity | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 规则 rule | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 技能 skill | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| MCP mcp | ✅ | ✅ | ✅ | ✅ | ❌ 一期不做 | ✅ |
| 智能体 agent | ✅ 只读 | ❌ | ❌ | △ 仅经「切换」 | △ 有类别无入口 | △ |
| 用户记忆 memory | △ | ❌ | ❌ | ✅ 切换含六类 | ❌ | ✅ |
| 斜杠命令 command | △ 仅 Claude | ❌ | ❌ | ❌ | △ 有类别 | ❌ |
| 偏好 preference | ✅ 落到 `preferences/` | ❌ | ❌ | ✅ 聚合进 CLAUDE.md | ❌ | — |
| 裁决准则 criteria | ✅ | ✅ | ✅ | —（元资产） | — | — |

### 5.2 三个结构性判断

1. **记忆是当前最刺眼的断点**：协议层（切换六类、仲裁五类）都承认它，资产中心却不承认它（前端类别只声明 4 类）。根因是「资产类别」有六份互不一致的清单（见第七节）。
2. **「最佳实践」只发生在事后，没发生在事中**：现有落地只有导入冲突仲裁 + 单资产体检（准则包 7 条）。新建/编辑时没有模板、没有实时校验，没有批量整改、没有健康报告、准则包不可导出/分享。
3. **新定位在首屏不可见**：首页唯一质量信号是裸的「健康度 100」，不可点、无构成、无来源。准则命中、待整改、冲突、漂移这些真正代表「管得好不好」的信息没有汇聚。

### 5.3 建议的产品化路径（护城河）

```
资产规范层（Standards Layer）
├─ 类别模板       每个类别 2-3 个「行规合规」起步模板
├─ 编辑时校验     保存前跑确定性机械检查（已有 4 项能力）
├─ 一键整改       医生 fix 草案提升到「我的库」批量层
├─ 准则包         导入 / 导出离线文件（无后端，符合 local-first）→ 社区可发「前端资产规范包」
└─ 健康报告       可贴进 README 的徽章 + 一份 MD 报告 ← 最强传播物
```

## 六、界面与交互诊断（9 页实测）

> 前提：0 console error、接口 0 失败。问题不在「跑不跑得起来」，在信息架构与状态建模。

### 6.1 P0（摧毁信任 / 造成误操作）

1. **状态自相矛盾**：资产库 187 项全部「未分发」，连接页同时显示「已同步资产 · 技能 182」。
2. **同一技能 5 个数字**：首页 182 / 技能页 100 / 连接页可导入 185 / 本机环境 343 / 切换历史 183。口径未定义，用户无法建立心智模型。
3. **「全部资产」页不可用**：187 张卡 + 563 个按钮 + 0 个筛选器；技能目录里的 `SKILL.md` 被平铺成同名资产；`_` 前缀内部元数据文件被当成资产展示。
4. **危险动作无护栏**：同步页 0 选中时「执行同步」仍可点、不显示影响范围；「预览模式」开关无标签、与执行关系不明；右侧两个空态文案互相打架。
5. **导航 13 项平铺 + 4 套同义词**：库（资产库 / 我的库 / 入库 / Hub）、动作（同步 / 分发 / 投放 / 切换）、状态（已同步 / 未分发）。侧栏「资产库」的折叠按钮嵌在链接内部。

### 6.2 P1（影响上手）

6. 首屏无「下一步」：健康度裸数字、快速动作缺「切换」、全站无「上次同步时间」。
7. 技能页 13 个平铺筛选控件；环境说明文案被排在长列表之后，首屏永远读不到；卡片描述长度从数百字到空值并存，无法扫读。
8. 连接页「重新扫描」与「重新检测」无区分；「导入到 Hub」是第四种「库」的叫法，且导入页不在侧栏、进去无返回路径；未安装工具零引导。
9. 切换页：Qoder 卡片无任何能力标签；历史存在重复记录；页面内找不到「撤销」入口。
10. 项目页：23 张卡 / 70 个按钮，绝大多数指标全 0；只有「打开文件管理器/终端/IDE」，没有任何站内操作；无加载态，先白屏。
11. 设置页直接暴露内部枚举（`hybrid`、工具 id、`~/.assetplex/.backups`）；市场源第三个域名疑似拼写错误；无「未保存」提示。
12. 窄屏：侧栏固定宽度且无折叠、无响应式断点，800px 宽时吃掉约 30% 视口；首页连接状态写死两列。

### 6.3 P2

项目卡路径格式不一致、`IDE` 按钮语义不明、英文标识直出（`SKILL`、`evals`）、卡片可点 + 卡内「查看」双入口。

## 九、优先级路线图

### 阶段 0 · 止血与可信（1 周）

分发状态真实化（或明确标注未接入）、计数口径归一、资产类别单一真相、词表收敛、`/vault` 可用性、版本号单一来源、死链与死命令清理、危险动作护栏。
→ 变更规格：`changes/fix-trust-and-consistency/`
→ **状态：已完成。** Phase H / I / J / K 全部勾选，逐条实测记录与 commit 哈希见该目录 `tasks.md`；验收方式：双端全量测试 + 隔离环境 API 回环 + 9 页浏览器走查（含 800px 窄屏）。遗留：`buildSupportMatrix()` 仍由「当前配置下 `resolveHubItems()` 返回空」反推能力矩阵，待适配器能力声明落地后修（`specs/product-surface-hygiene` Scenario 7 已明写为现存缺陷）。

### 阶段 1 · 补齐资产中心（2–3 周）

记忆 / 命令 / 偏好进资产中心（盘点 → 收藏 → 编辑 → 分发 → 体检）；智能体从只读升级为可写；下线 legacy 路由。

### 阶段 3 · 开源影响力（可与 1/2 并行）

README 重写（新叙事 + demo + 对比表升级）、docs 双语与功能页、SEO 技术项一次补齐、Gitee 镜像与渠道物料。

### 阶段 4 · 工程债
